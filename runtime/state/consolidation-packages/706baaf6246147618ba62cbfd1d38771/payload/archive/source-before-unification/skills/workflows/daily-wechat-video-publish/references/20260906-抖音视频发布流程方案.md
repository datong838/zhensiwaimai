# 微信群视频 → 抖音发布：开发前方案

## 目标

从指定普通微信群中，按群名、发送人和起始时间筛选原视频，按本轮独立批次保存到本地，依据店铺映射表生成抖音作品描述和位置，逐条发布并回读抖音作品状态。当前首轮只接入抖音，不执行其他平台发布和抖音评论回复。

## 输入合同

- 群名：必须逐字匹配；当前试运行 `红太阳鱼杂王蜀川湘菜店抖音发视频`。
- 发送人：当前试运行 `略略略`。
- 起始时间：`昨天 19:00`，按 Asia/Shanghai 解释为 `2026-09-05 19:00:00`。
- 店铺映射：`/Users/ddt/work/臻肆/视频/微信群-店铺名-店铺地址.xlsx`。
- 本轮目录：`/Users/ddt/work/臻肆/视频/runs/<run_id>/`，不得把新文件直接混入历史根目录。
- 抖音账号：复用用户已登录的普通 Chrome；不新开登录 Profile、不复制 Cookie、不安装扩展。

## 固定状态机

`candidate → download_pending → downloaded → prepared → publish_pending → submitted → verified`。

异常状态：`blocked_login`、`download_unknown`、`publish_unknown`、`failed`。未知状态不得自动重试或补发。

## 执行阶段

1. 只读预检：核对实体手机、普通微信、完整群名、发送人和时间范围；核对抖音域名与可见账号。
2. 候选扫描：只读取目标群指定时间之后的消息，记录消息时间、发送人、视频时长、封面 OCR 和消息位置证据。
3. 下载：优先使用微信“保存视频/下载”能力；若只能播放或分享而没有本地保存入口，写 `download_pending`，不得用转发到第三方替代。每个文件保存 SHA-256、原始文件名、批次文件名和完成时间。
4. 文案准备：`封面文案 + 约10字广告词 + 店铺名 + 地址：完整地址`。文案只在本地生成，发布前逐视频展示。
5. 抖音准备：进入 `/creator-micro/content/upload`，只填视频、作品描述和位置，其他字段保持默认；选择文件或填写字段视为写入准备。
6. 发布闸门：发布前确认具体视频文件、完整描述、位置、可见范围和账号。单条发布后回读内容管理页，确认作品存在且状态明确。
7. 评论回复：另行按“作品—具体评论—回复文本”建立单条授权，不与视频发布授权混用。

## 去重与历史

- 以 `source_message_id`（可获得时）、`source_timestamp + sender + duration + cover_hash` 和文件 SHA-256 组成复合键。
- 每轮写 `run.json`、`candidates.jsonl`、`timeline.jsonl`、`publish-receipts.jsonl`。
- 历史只用于去重参考；本轮候选必须以当前群最新读取结果为准。
- 同一视频已进入 `submitted` 或 `verified` 后禁止再次发布；`publish_unknown` 禁止自动重发。

## 失败与停止规则

- 登录失效、安全提示、验证码、账号风险提示：停止并等待人工处理。
- 群名/发送人/时间无法同时确认：停止，不猜测。
- 下载只有播放/分享没有保存证据：记录 `download_pending`，不把缓存文件冒充原视频。
- 发布结果未知：停止，不重发。
- 同一阶段最多一次受控恢复；第二次失败进入 `failed` 并保留证据。

## 验收指标

- 候选筛选准确率：群名、发送人、起始时间三项均有证据。
- 批次隔离：本轮文件不与历史文件混放，文件哈希可回读。
- 文案字段完整：封面文案、广告词、店铺名、地址均存在；位置字段为店铺地址。
- 发布证据完整：提交前快照、平台返回、管理页回读和最终状态齐全。
- 运行时记录每个节点耗时，并标记是否发生模型介入；固定执行器阶段目标为 `runtimeModelDecisions=0`。
