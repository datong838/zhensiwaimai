# 桌面文字只读对账证据修复方案

## 问题

桌面文字首次发送已经完成一次物理发送，并取得目标群、空输入框、两帧稳定气泡、唯一复制菜单和原生复制全文 SHA-256 一致的证据。首次发送仍需用发送前后帧证明新气泡；但后续 `reconcile` 是只读操作，无法重新生成发送前帧，继续要求 `newOutgoingEvidence` 会让合法的 unknown 永久无法提交。

## 修改范围

- 只修改 `skills/wechat-messaging/scripts/desktop_adapter.py` 的文字 `reconcile` 判定。
- 保留发送路径的 `newOutgoingEvidence` 门禁不变。
- 保留群名、载荷 SHA-256、一次物理发送、发送后输入框双帧为空、两帧稳定气泡、唯一复制菜单和原生复制全文精确哈希门禁。
- 图片和文件路径不变。

## 验证

1. 新增单元测试：满足完整原生复制证据时，只读 reconcile 返回 verified，且不调用 `text_newness`。
2. 新增反例：复制哈希错误时仍返回 unknown。
3. 运行微信技能全部测试和商家工作流全部测试。
4. 对当前 unknown 事件执行真实只读 reconcile，确认 `sendAttempts=0`、业务物理发送总次数仍为 1。
5. 完成共享技能当前版本验收、更新依赖摘要并重新封板后，继续生产工作流；第二家只允许一次发送。

## 风险控制

只读 reconcile 不能调用发送函数。修改不放宽首次发送的新气泡证明，也不影响图片和文件核验。任何正文、群名或原发送收据不一致仍失败关闭。
