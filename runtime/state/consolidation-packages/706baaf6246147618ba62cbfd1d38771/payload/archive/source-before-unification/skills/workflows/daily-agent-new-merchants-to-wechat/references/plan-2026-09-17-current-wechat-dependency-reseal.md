# 统一微信当前验收版本接入与商户工作流重新封板方案

## 背景与问题

商户工作流于 2026-09-16 完成生产文字真实非空验收并封板。随后统一 `wechat-messaging` 为图片和文件发送完成了桌面重启后修复与真实复验，当前 `dependencies.json` 已绑定该最终接受版本。商户锁仍保存变更前摘要，因此普通心跳在任何微信、浏览器和状态动作前以 `executor-lock-digest-mismatch:messaging_dependencies` 失败关闭。

当前统一技能的 `accepted-version.json` 与实际 `dependencies.json` 逐项一致，图片和文件真实发送及防重重放均通过。由于公共桌面适配器属于文字、图片、文件共享运行路径，不能只把新摘要写入商户锁；必须重新执行商户文字真实非空生产验收后才能恢复 SEALED。

## 不变边界

- 生产群固定为「电销+直播攻坚组」，通道固定 desktop，授权固定 `user-20260915-production-hourly`。
- 生产游标、发送历史和 attempted 标记不手工修改；只由业务执行器在逐字复制回读通过后提交。
- 不改统一微信文字、图片、文件发送算法；先验证当前已经被媒体真实验收的统一版本。
- unknown/attempted 不重发；发现公共缺陷时停止本轮，由 `wechat-messaging` 整体修复并回归三类能力。
- 测试游标与生产游标继续隔离，不改群名或回退手机。

## 实施步骤

1. 运行统一微信全量离线测试、依赖摘要校验及商户执行器合同测试，确认文字、图片、文件共享逻辑自洽。
2. 将 `executor-lock.json` 受控切换为 `UNSEALED_ACCEPTANCE`，仅更新 `messaging_dependencies` 为当前真实媒体验收版本摘要，并记录本次用户生产实操授权、时限和范围。
3. 使用唯一业务总入口和 `--unsealed-acceptance-authorization` 执行一轮生产采集、审计、发送、双帧与原生复制全文复核、历史及游标提交。
4. 只有本轮存在真实待发商户且至少一条新发送满足 `physicalSendAttempts=1`、`runtimeModelDecisions=0`、输入框双帧清空、复制全文哈希一致，才以本轮收据恢复 SEALED。
5. 用普通封板入口重放一轮，核对防重、最终游标和代码生成的逐项复盘。

### 当生产采集为零待发时的验收组合

若生产采集完整通过但 `targetCount=0`，不得制造或重复发送生产商户。此时把验收拆成两个可独立核对的部分：

1. 保留原生产商户真实非空整链收据，用于证明业务适配器、生产群、历史和游标提交合同；要求商户工作流自身运行文件摘要与该收据封板后保持不变。
2. 对当前统一微信版本在已授权「臻肆测试群」执行一条独立文字真实发送，要求单次发送、双帧新气泡、空输入框和原生复制全文哈希一致；该收据用于证明发生漂移的共享文字路径。
3. `executor_integrity.py` 同时校验以上两份收据及当前依赖摘要，缺少任一部分均拒绝 SEALED。图片和文件继续由统一技能当前 `accepted-version.json` 及全量回归证明，不写入商户业务成功历史。

这种组合只用于“业务代码未变、共享微信代码变更、当前无合法生产待发”的情况；不能在业务适配器或生产提交逻辑发生变化时替代新的生产非空整链验收。

## 完成标准

- 统一微信离线回归全部通过，当前依赖与媒体真实验收版本一致。
- 商户生产真实非空发送完成；若当前无合法待发，则原生产整链收据与当前共享文字真实收据同时通过代码校验。
- 新锁绑定当前全部运行文件及新的商户真实非空收据。
- 普通封板入口通过；重放不重复发送，最终游标与最后一条已验证商户一致。

若本轮采集为零待发，只能证明当前版本可空跑，不能重新封板；保持受控验收状态，等待下一条真实业务数据，不以历史或媒体收据替代文字生产验收。

## 2026-09-18 当前共享微信版本再次验收

09:40 左右，统一微信包的 `workflow_bridge.py`、`dependencies.json` 及其绑定的公共桌面预检、群定位代码发生变更，原 SEALED 锁按代码门禁在任何浏览器和微信动作前拒绝运行。用户已明确授权：“允许解封当前版本并用这家新商家完成生产验收，成功后自动重新封板。”

本次维护继续采用既有方案，不修改业务执行器或统一微信文字、图片、文件算法：先运行统一微信与商户工作流离线回归；然后原子切换为 `UNSEALED_ACCEPTANCE`，绑定全部当前运行文件摘要和原授权 `user-20260916-production-hardening`；最后只调用一次业务总入口。只有真实新增商户完成单次生产发送、双帧与原生复制全文复核、成功历史及游标提交后，才允许代码自动恢复 SEALED。任何 unknown、摘要再次漂移或证据不完整均保持未封板并禁止重发。
