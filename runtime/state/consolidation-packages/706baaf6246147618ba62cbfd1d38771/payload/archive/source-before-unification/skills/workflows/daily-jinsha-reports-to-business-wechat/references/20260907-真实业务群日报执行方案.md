# 真实业务群日报执行方案

> 2026-09-10 更新：下载阶段缺省且优先使用 `jinshaChannel=browser` 和 `jinsha-business:9232`；只有显式配置 `desktop` 才使用桌面金鲨。发送阶段缺省且优先使用 `wechatChannel=desktop`；只有显式配置 `mobile` 才使用手机。下载和发送的不同通道均不得作为 unknown 结果的自动补发路径。

## 目标

在不修改隐藏内部底座 `.daily-jinsha-reports-core` 第14轮封板文件的前提下，复用其金鲨下载、报表生成、手机选文件、单次发送、气泡复核和失败关闭能力，将昨日美团外卖与淘宝闪购日报发送到唯一真实业务群「FEIBING NEO AI数字员工」。

## 不变基线

- 原封板 Skill、合同、下载执行器、制表器、发送器及测试保持只读，哈希不得变化。
- 业务日期为 Asia/Shanghai 昨日；美团、淘宝各下载一次。浏览器与桌面金鲨采用完全相同的日期、方案和36项指标合同。
- 美团使用「最终美团最新日报」36项；淘宝使用既定日报方案并确保「单均实付」「单均到手」后为36项。
- 下载后释放所选金鲨资源；制表及微信阶段不再占用后台浏览器任务标签或桌面金鲨。
- 客户表关联、列序、营收降序、条件格式、公式与保存后验证完全复用封板实现。
- 手机绑定已核验物理设备与普通微信；每份文件只允许一次发送点击，结果未知只读复核。

## 独立业务配置

- 唯一目标群：`FEIBING NEO AI数字员工`。
- 独立授权：`zhensi-business-main-wechat-feibing-neo-ai-daily-v1`。
- 独立账本：`zhensi_waimai/.local/state/jinsha-report-send-feibing-neo-ai.json`。
- 成品名称：`美团外卖日报_YYYY-MM-DD.xlsx`、`淘宝闪购日报_YYYY-MM-DD.xlsx`。
- 成品文件名、工作表标题和运行目录不得包含「测试」或「考核」。
- 下载原始文件与运行回执使用独立 `runId`，不与历史测试轮次混用。

## 实现方式

0. 下载通道由 `jinshaChannel` 决定，缺省为 `browser`。浏览器执行器只连接 `jinsha-business:9232`，使用任务自有标签、DOM语义定位和 Playwright 下载事件；显式 `desktop` 时保留原 CUA 执行器。两条通道共享金鲨租约、文件路径、`runId` 与下载收据合同，禁止自动互相回退。

1. 新发送入口动态加载冻结 `wechat_file_sender.py`，只替换运行时的目标群、授权常量及三个冻结函数在导入时绑定的账本默认参数；不复制或修改发送业务逻辑。
2. 新整链入口复用冻结 `build_reports.mjs` 与 `download_receipt_contract.mjs`，并沿用封板的 `downloadStartedAt - 2秒容差` 新文件校验；在调用手机发送器时显式传入配置中的群名和授权。
3. 整链入口对群名、授权、文件名和文件数量执行白名单校验；任何偏差均在发送前停止。
4. 发送前输出两份成品绝对路径、大小和 SHA-256。2026-09-07 用户已授予本固定流程持续执行权：普通微信、精确群名「FEIBING NEO AI数字员工」、当日业务日期两份日报且文件校验全部通过时，后续无需逐轮人工批准。该权限不扩展到其他群、其他文件或其他微信身份。
5. 桌面微信适配器不使用近期会话坐标：只控制唯一精确名为 `微信` 的聊天主窗，允许 `微信 (窗口)` 网页伴随窗存在但绝不操作；完整群名搜索后，在左侧结果面板选择唯一完整群名，与任何可变分区标题解耦，打开后再通过顶部群标题复核。手机模式继续使用原两帧稳定定位。
6. 目标群含空格时，标题与气泡复核对「期望群名」和「OCR 文本」同时去空格后精确匹配；不允许模糊群名、部分群名或跨群复用。
7. `DocumentsUI` 偶发将文件列表标记为不可滚动，但精确目标行仍可见且被底部导航裁剪。业务适配器允许有界的固定方向滑动，仅在精确文件名节点唯一、连续两帧边界稳定且完全可见时点击。多个不同边界的同名节点视为真重复并失败关闭。
8. 微信标题字体中英文 `AI` 可被 OCR 稳定识别为 `Al`。仅在精确片段 `Al数字员工` 中将小写 `l` 校正为大写 `I`；群名其余文字和成员数格式仍必须完整匹配。
9. 文件气泡换行时，OCR 可遗漏业务前缀与日期之间的单个下划线。只对固定文件名结构「平台日报前缀 + 可选单下划线 + 精确业务日期 + `.xlsx`」放宽，同时必须匹配精确群标题和文件字节数换算的 KB 大小。

## 执行前门禁

1. 金鲨下载只有一个受控通道；共享协作租约可获取。浏览器默认固定 Profile/端口为 `jinsha-business:9232`，桌面仅允许显式选择。
2. 浏览器任务必须从 `https://data.guoshuyufen.com/#/businessData/realTimeData` 同源进入 `#/reportDownload`，且美团/淘宝平台控件与下载主体同时存在；桌面当前页面仍必须精确为 `#/reportDownload`。
3. 浏览器只按DOM标签定位淘宝指标；桌面通道强制刷新后仍由业务执行器读取实时截图尺寸并动态换算，配置中禁止传入绝对像素。
4. 昨日日期、两平台方案和指标数量逐节点验证。
5. 默认桌面模式要求 Mac 普通微信已登录、聊天主窗与目标群唯一；只有显式手机模式才检查手机物理身份、普通微信和设备连接。

## 恢复与停止

- 页面空白：只执行金鲨 `Force Reload`，主体稳定后重新开始尚未产生下载的轮次。
- 页面重渲染：重新读取当前 UI 树，不复用旧元素编号。
- 已确认下载：同一 `runId` 只恢复未完成平台，不重复下载。
- 已确认发送：账本按目标群与文件哈希跳过；未知结果只读复核，禁止自动重发。
- 错群、错文件、登录失效、物理设备不符、同名群歧义立即失败关闭。

## 验收

- 原封板文件哈希与第14轮清单一致。
- 两个昨日原始文件结构有效且为本轮新下载。
- 两份成品通过冻结制表器的保存后检查，名称无测试标记。
- 发送收据的目标群严格等于「FEIBING NEO AI数字员工」。
- 两份文件各出现一个完整文件名新气泡，群标题、大小和哈希验证通过。
- 最终只读复核新增发送为0。
- 最终成功总回执必须清除上一轮失败留下的 `reason` 和 `phoneOutput`，避免 `ok=true` 与历史错误字段同时存在。
- 分别报告业务完成、180秒效率状态及每节点模型介入情况。
