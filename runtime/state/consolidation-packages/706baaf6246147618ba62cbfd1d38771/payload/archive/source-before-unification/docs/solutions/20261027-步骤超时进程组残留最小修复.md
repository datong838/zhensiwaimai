# 步骤超时进程组残留最小修复

## 产品目标与范围

工作流异常不得留下后台写者或岗位占用，阻塞后续流程。只清理由本runner以start_new_session=True创建的本步骤原进程组，实时核验成员身份后操作；不杀无关进程，不改业务intent/unknown、防重、原发送守卫或班表时长。超时意味着业务结果可能未知，不能同轮重试该步骤。

修改范围：runtime/skill_runner.py、新增runtime/test_step_process_cleanup.py与本方案。仅源码开发和隔离fixture，不修改生产、账本或今日结果，不提交。

## 真实复现（修复前）

2026-10-27以临时目录的独立Python父/孙fixture调用原run_step(timeout=1)：孙进程忽略TERM并每50ms写本fixture心跳，主进程默认TERM退出。返回timed_out=true、duration=1.0秒，但返回后心跳继续变化、live登记已删除。复现结束立即只清理该fixture自建进程组。

原因：超时先killpg TERM，再仅proc.wait等待主进程，主退出后不再执行KILL；强杀函数又依赖os.getpgid(proc.pid)，主已reap后无法定位仍活的孙。正常主提前退出也无组存活核查。run_skill还会将timeout归RECOVERABLE并按max_retries同轮重试，可能重复提交。

## 最小技术方案

1. 本步创建后立即保存原 `pgid=pid`、`sid=pid`、leader PID 和 birth token。Darwin 依据本机 SDK 的 `struct proc_bsdinfo`/`PROC_PIDTBSDINFO` 通过 `libproc.proc_pidinfo` 取得启动时间秒+微秒；非 Darwin 或 native 不可用时才回退为 `ps lstart`。通过系统 `ps` 获取该进程组成员 PID/PGID/出生时间/状态，并对每个候选成员用 `getsid` 实时核验会话。leader 仍在时 birth token 必须一致；leader 已退出时，只接受仍处于原 SID 的后代。birth token 为空、会话或出生标识不匹配时一律不发信号、保留 live 登记。
2. TERM后按原10秒宽限有界等待整个组，而非主进程；仍存在的原组再KILL，随后有限等待清空。不可用PID重查已退出的主进程来推算pgid。僵尸成员不再持锁/写入，不作为活写者，但必须经ps状态核实。
3. 正常主退出却有存活组成员，也做本步有界清理并将步骤标为异常，不能假报全部完成。普通无孙步骤保持原成功语义。
4. 清理失败/身份不明保留登记以便诊断，禁止同轮重试；已超时亦无论recoverable分类一律不在同轮重跑。业务层原技术结果不更改、不重发。

### 返回语义与兼容边界

- `StepResult` 增加有默认值的 `process_group_leak`、`cleanup_uncertain` 和 `cleanup_detail`，保留旧调用方的构造兼容性。
- 超时仍保留 `timed_out=true` 与原分类，但 runner 在该轮直接结束重试循环。非超时的后代泄漏追加结构化诊断文本并按 `UNKNOWN` 失败，不把主进程 `exit=0` 写成成功。
- 只有进程组已确认无活跃成员（僵尸不持锁也不写入）才删除 live 登记；`ps/getsid` 失败、身份不匹配或 KILL 后仍有活跃成员均保留登记。
- `kill_live_steps` 对新登记使用同一身份核验；无身份锚点的历史登记不再盲目向可能复用的 PGID 发信号，原文件保留给人工诊断。

### 回滚

回滚仅需恢复 `runtime/skill_runner.py` 与删除专用测试；不涉及 manifest、业务状态、账本或生产进程。部署前必须由主监理单独复核，不随本开发任务自动上线。
