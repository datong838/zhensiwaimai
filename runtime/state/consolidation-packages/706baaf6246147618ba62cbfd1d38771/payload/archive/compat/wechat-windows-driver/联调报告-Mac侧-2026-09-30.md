## 二、最严重问题：发文件导致服务端整个挂掉

**复现**（100%，2 次）：
```
POST /  {"action":"auto_send","params":{"who":"臻肆测试群",
        "content":"C:\\work\\projects\\ai_agents\\wechat-windows-driver\\inbox\\wechat_link_test_1.txt"}}
→ 连接被服务端直接关闭，无响应（客户端 RemoteDisconnected）
```
**后果**：崩溃后 8731 端口彻底失联（ping 通、端口拒绝），**守护进程未能在 5 秒内拉起**——持续观测 60 秒+仍未恢复，需人工重启服务。
**对比**：同参数发文字 `send_message` 一直正常；`upload` 正常。问题精确定位在 **文件发送的 UI 自动化路径**（怀疑：文件对话框操作抛异常且未捕获，甚至带崩进程）。
**附带猜测**：文件发送中途崩溃可能给微信留了脏 UI 状态（残留对话框），这与随后「切换会话失败」可能相关，重启服务后请复测切换。

## 四、Mac 侧已完成 / 约定

- 官方 `client.py` 已部署到调用目录；**加了 3 行本地补丁**（`self._opener = build_opener(ProxyHandler({}))`，get/post 走 opener）——因为 Mac 的翻墙代理会给 shell 注入 `http_proxy=127.0.0.1:55511`，不绕过的话所有请求被截胡成 `502 upstream connect failed`。**你们后续升级 client.py 时请保留这个补丁**（或服务端实现同等能力）。
- 联调用环境变量（token 不落代码）：`WIN_IP` + `WECHAT_AGENT_TOKEN`（值见连接信息.txt，不外传）
- `example.py` 的 TOKEN 行改为优先读环境变量

## 五·五、复测中新发现：服务端仍会偶发崩溃（01:31）

- 01:29 发文件成功后约 2 分钟，服务端再次失联（先 Connection reset、后端口 refused；ICMP 一直通）
- 守护进程这次 **约 40 秒**自动拉起（上一次崩溃则是几分钟都没恢复、需人工重启）——**恢复机制不稳定**
- 崩溃时间点与文件发送/回读操作时间上接近，怀疑 UI 自动化路径仍有偶发致命异常
- **建议**：服务端给所有 action 的 dispatch 外层加兜底 try/except + 崩溃钩子日志；守护进程检测间隔缩短并加"拉起后健康确认"
