# 移动端 UI 自动化技术方案

> **目标设备**：荣耀 9X / HONOR 9X / HLK-AL00 / HarmonyOS 3.0.0 / 麒麟 810
> **技术路线**：电脑端 Python + **uiautomator2** + ADB，驱动真机运行安卓 App
> **适用范围**：本文档覆盖**三个应用层**——**美团外卖**、**淘宝闪购**、**微信**

---

## 1. 目标与边界

### 1.1 目标

通过脚本精确控制手机上的美团外卖、淘宝闪购、微信，实现：

- **美团外卖 / 淘宝闪购**：按「地址 + 店铺关键词」搜索 → 进入店铺 → **截图 + OCR 抓取店铺/商品信息**（评分、月售、配送费、起送价、配送时效、距离、价格、活动标签等）
- **微信**：有权账号下的「打开对话 → 准备草稿 → 经明确授权后发送」等基础操作；默认只读导航，不自动发送

### 1.2 边界声明（务必阅读）

> ⚠️ **技术可行 ≠ 可以无限制使用**

1. **仅限有权操作的账号和设备**；控制频率、保留审计证据，并优先在测试对象验证
2. **禁止**：批量爬取、竞品监控、营销群发、自动抢红包、抓取聊天记录——这些违反平台规则且已有行政处罚判例
3. **账号风控**：高频自动化可能触发封禁，微信处置为「警告 → 限功能 → 封号 → 关联设备封禁」阶梯式
4. **维护成本**：美团 / 淘宝 / 微信每次大版本更新，`resourceId` 与页面结构可能变化，需用 weditor 重新校准
5. **OCR 算力**：麒麟 810 为中端芯片，**OCR 务必在电脑/云端运行**，手机端跑 PaddleOCR 会卡死

## 2. 技术选型

### 2.1 路线对比

| 路线 | 是否需要自研 App | 是否需要电脑 | 开发量 | 适用场景 |
|---|---|---|---|---|
| **① 华为智慧助手「模拟点击」录制** | 否（系统自带） | 否 | 零 | 个人低频固定动作（定时发消息） |
| **② uiautomator2 电脑端驱动（本文采用）** | 否（部署 u2.jar/辅助组件） | 是 | 中 | 精确控制 + OCR/AI 配合 |
| **③ AccessibilityService 纯手机后台** | 是 / 或用第三方 | 否 | 高 | 无电脑、需后台常驻 |

**本文采用路线 ②**：手机上**无需自行开发 App**。当前固定验证版本 uiautomator2 3.7.0 的 `init` 主要部署 `u2.jar` 与输入法辅助组件，并按需启动服务；旧版资料中的 ATX/minicap/minitouch/两个桌面图标不能作为当前必然安装清单。成功必须以 ADB、设备信息、当前应用、截图和控件树的现场证据共同判断。

### 2.2 为什么不用 UiAutomator2 直连 + 手写？为什么要封装？

uiautomator2 是通用安卓 UI 自动化框架，**美团外卖、淘宝闪购、微信都是安卓 APK，在同一套技术路径上**——差别只在「应用层」（`*_client.py`），**驱动层（driver / human / locator / vision）三个应用共用**。这正是本方案的架构核心。

### 2.3 为什么「控件树 + 截图 OCR」双轨？

| 页面区域 | 定位方式 | 原因 |
|---|---|---|
| 搜索框、按钮、列表卡片 | **控件树**（text / resourceId / XPath） | 定位快、稳定、可交互 |
| 店铺详情（评分/销量等） | **截图 + OCR** | 多为 WebView / 自定义控件，无障碍拿不到文本 |

**双轨制 = 长期生命力（控件定位） + 兜底韧性（视觉识别）**。

### 2.4 稳健交互与平台规则

所有操作统一走 `human.py`，目的仅是等待界面稳定、降低误触并限制无效重试，不用于绕过平台检测：

- 点击坐标只允许在已确认安全区域内做小范围容错
- 操作间等待页面稳定（点击前后、输入间隔、翻页等待）
- 失败 **指数退避**重试

## 3. 系统环境（针对荣耀 9X / 鸿蒙 3）

目标设备为 **HarmonyOS 3.0.0（安卓兼容层）**。当前代码支持 ADB/uiautomator2 通路，但必须以现场设备探针为准；本次无 ADB 与 uiautomator2 运行环境，未宣称真机通路已验证。

### 3.1 手机端准备

1. **开启开发者模式**：设置 → 关于手机 → 连点「HarmonyOS 版本」7 次
2. **开启 USB 调试 + USB调试(安全设置)**：设置 → 系统和更新 → 开发人员选项
   > ⚠️ **鸿蒙必须额外开启「USB调试(安全设置)」**，否则 shell input 类命令被拦截
3. USB 用途选 **传输文件（MTP）**
4. **关闭纯净模式增强防护**：设置 → 系统和更新 → 纯净模式（否则可能拦截 atx-agent 安装）
5. 若手机实际安装了输入法辅助 APK，只按初始化提示确认；不要为不存在的旧版 ATX App 预设后台保活步骤

### 3.2 电脑端准备

```bash
# 1. 安装 ADB 驱动（华为可装 HiSuite 自动装驱动），确认授权
adb devices          # 勾选"始终允许"

# 2. 安装 Python 依赖
pip install -r requirements.txt

# 3. 首次初始化（固定基线 3.7.0 不支持 --mirror）
python -m uiautomator2 init
```

**成功条件**（须同时满足）：
- ✅ `adb devices -l` 显示目标设备为 `device`
- ✅ `python -c "import uiautomator2 as u2; print(u2.connect().info)"` 返回设备信息
- ✅ 可以获取当前包名、截图和非空控件树

> ⚠️ **鸿蒙特例**：重启后若无法连接，先检查 USB 调试和 USB 调试（安全设置）。3.7.0 的 `init` 不接受 `--mirror`，不要照搬旧命令。

## 4. 架构设计

### 4.1 分层结构

```
┌──────────────────────────────────────────────┐
│ 编排层  main.py（按 config.TARGET_PLATFORM 选应用）│
├──────────────────────────────────────────────┤
│ 应用层（每个 App 一个 Client）                  │
│  ├── meituan_client.py      【美团外卖】       │
│  ├── taobao_flash_client.py 【淘宝闪购】       │
│  └── wechat_client.py       【微信】          │
├──────────────────────────────────────────────┤
│ 能力层（三应用共用）                            │
│  ├── driver.py       连接 / 健康检查 / 亮屏    │
│  ├── human.py        稳健交互（等待/容错/退避） │
│  ├── anti_popup.py   通用弹窗/权限处理         │
│  ├── locator.py      混合定位（降级策略）      │
│  ├── vision.py       截图 + OCR + 模板匹配    │
│  └── extractors.py   结构化字段抽取            │
├──────────────────────────────────────────────┤
│ 配置层  config.py（包名/选择器/交互参数）       │
└──────────────────────────────────────────────┘
        ↓ ADB over USB
   [荣耀 9X / 鸿蒙3 + ATX 守护 App]
```

### 4.2 核心设计决策

1. **应用层与能力层分离**：换 App 只加一个 `*_client.py`，底层不动
2. **SELECTORS 指纹池**：所有 resourceId 集中在 `config.py`，版本升级只改一处
3. **混合定位降级**：`text → resourceId → XPath → 视觉兜底`，任一层命中即可
4. **稳健交互强制收敛**：所有点击/输入经 `human.py`，统一页面等待、误触防护和失败退避

## 5. 应用层说明（三个应用）

### 5.1 美团外卖（`meituan_client.py`）

**流程**：`launch → 确保地址(_ensure_address) → 搜索店铺(search_shop) → 进店(enter_first_shop) → 抓信息(scrape_current)`

**采集字段**：`shop_name / rating / monthly_sales / delivery_fee / min_order / delivery_time_min / distance_km / promotions`

**关键方法**：
- `collect(address, keyword, top_n)`：批量采集前 N 个店铺
- `dump(results, path)`：落盘 JSON

> `_ensure_address` 因各用户地址管理不同，**预留 `NotImplementedError`，需在 weditor 实测后填充**。

### 5.2 淘宝闪购（`taobao_flash_client.py`）

**流程**：`launch → 进闪购频道(enter_flash) → 搜索(search) → 抓信息(scrape_current)`

**采集字段**：`shop_name / price / sales / eta(时效) / promotions`

**容错**：闪购入口未找到时**退化为直接搜索**；搜索框/入口优先指纹池，失败 OCR 兜底。

> 淘宝关键入口 resourceId 命名较规范（如搜索框 `searchEdit`），相对稳定。

### 5.3 微信（`wechat_client.py`）

**流程**：`launch → 打开对话(open_chat) → 发送文本(send_text) → 截图(screenshot_current)`

**⚠️ 特殊说明**：
- 微信反自动化**远强于**美团/淘宝（动态 ID、混淆 content-desc、行为检测、AccessibilityService 探测）
- 本模块**仅作个人自用技术验证**（定时发消息/查看），严禁群发/抢红包/抓聊天记录
- 华为小艺 GUI Agent **微信暂未接入**，故走 uiautomator2 路线

## 6. 字段抽取规范（`extractors.py`）

统一用正则从 OCR 全文本中提取，规则如下：

| 字段 | 正则 | 示例 |
|---|---|---|
| rating | `(\d\.\d)\s*分` | 4.8分 |
| monthly_sales | `(?:月售\|已售)\s*(\d+[\+万]*)` | 月售9999+ |
| delivery_fee | `配送费?\s*[¥￥]\s*(\d+)` | 配送¥5 |
| min_order | `起送\s*[¥￥]\s*(\d+)` | 起送¥20 |
| delivery_time_min | `(\d+)\s*分钟` | 30分钟 |
| distance_km | `(\d+\.?\d*)\s*[kK][mM]` | 1.2km |
| price | `[¥￥]\s*(\d+\.?\d*)` | ¥29.9 |
| eta | `\d+\s*(?:分钟\|小时)达` | 30分钟达 |

`build_shop_info(blocks, platform, rank)` 按 `platform` 分发，输出统一字典。

## 7. 开发与验证流程

### 7.1 分阶段行动清单

| 阶段 | 动作 | 验证点 |
|---|---|---|
| **0 环境** | 开 USB调试 + USB调试(安全设置) + 关纯净模式 | — |
| **1 连接** | `adb devices` → 勾选始终允许 | 显示 `device` |
| **2 依赖** | `pip install -r requirements.txt` | — |
| **3 初始化** | `python -m uiautomator2 init` | 当前包名、截图与控件树可读；桌面图标不是硬门 |
| **4 自检** | `SKIP_DEVICE=1 python -m tests.test_env` / `python -m tests.test_locator` | 纯逻辑测试全绿 |
| **5 真机** | `python -m tests.test_env`（连手机） | 打印 `model=HLK-AL10`、ATX 运行中 |
| **6 校准** | 跑 `weditor` / `python -m uiautodev`，实测填充 `config.SELECTORS` | 指纹池可用 |
| **7 运行** | 改 `config.TARGET_PLATFORM` → `python main.py` | 生成 `result.json` |

### 7.2 校准 SELECTORS（关键一步）

代码里的 `SELECTORS` 是占位/常见值。**首次运行前必须用 weditor 实测填充**，否则定位会失败：

```bash
python -m uiautomator2 init   # 顺带装 weditor 所需
# 浏览器打开 weditor，点选控件，把 resourceId/text 填进 config.SELECTORS
```

`locator.py` 的混合降级保证：**即使指纹池未填满，只要文本可 OCR 识别，仍能兜底点击**。

### 7.3 运行

```bash
# 在 config.py 里设置：
# TARGET_PLATFORM = Platform.MEITUAN   # 或 TAOBAO_FLASH / WECHAT
python main.py
cat result.json
```

**输出示例**：
```json
[
  {
    "platform": "meituan", "rank": 1,
    "shop_name": "麦当劳（北京朝阳店）", "rating": 4.8,
    "monthly_sales": "9999+", "delivery_fee": 5,
    "min_order": 20, "delivery_time_min": 30,
    "distance_km": 1.2, "promotions": ["满减", "折扣"]
  }
]
```

## 8. 风险与应对

| 风险 | 应对 |
|---|---|
| **账号与平台风险** | 使用有权账号、控制频率、先测试对象验证、禁止批量与越权操作 |
| **页面结构升级** | SELECTORS 集中管理，weditor 重新校准一处即可 |
| **WebView 抓不到文本** | 强制走截图 OCR 兜底（`vision.py`） |
| **鸿蒙重启后 USB 调试关闭** | 连不上先去重开开发者选项 |
| **Kirin 810 跑 OCR 卡顿** | OCR 放在电脑/云端，手机只负责截图 |
| **ATX 被系统杀后台** | 应用启动管理 → 允许自启动/后台 → 最近任务锁定 |

## 9. 后续扩展建议

1. **校准 SELECTORS**：针对你美团/淘宝的具体版本，用 weditor 实测填充指纹池（这是 Demo → 生产可用的关键）
2. **持久化**：加 SQLite/CSV，把抓取结果入库方便对比
3. **定时任务**：cron / 计划任务，每天固定时间跑一次
4. **视觉兜底增强**：对固定版式区域用「裁剪 + 模板匹配」提高 OCR 精度
5. **多设备**：如需同时控多台手机，可在 `driver.connect(serial)` 层做并发编排

## 10. 通用手机控制与业务自动化分治（v2，已批准）

### 10.1 分治目标

本工程不再同时充当“手机控制框架”和“具体平台业务脚本”。目标结构固定为：

1. `skills/skills/app-controler/harmonyos3-phone-control`：面向 Agent 的鸿蒙 3 手机通用控制 Skill；
2. `zhensi_waimai`：美团外卖、淘宝闪购、微信的业务适配与任务编排；
3. 两层通过稳定的动作参数、页面快照和 `ActionResult` 收据协作，禁止业务层绕过安全门直接触发外部副作用。

HarmonyOS 3 在本方案中指具有 Android 兼容层、可由 ADB 与 uiautomator2 控制的华为/荣耀设备；不把该能力推断为 HarmonyOS NEXT 原生自动化能力。

### 10.2 通用 Skill 职责

通用 Skill 只负责：

- 设备发现、连接、健康检查、亮屏和当前应用识别；
- 页面截图、控件树导出、页面指纹与变化检测；
- text/resourceId/XPath/视觉定位的逐级降级；
- 点击、输入、滚动、返回、启动/停止 App 等原子动作；
- 系统权限、系统键盘、遮挡和 ATX/ADB 异常处理；
- 动作风险分类、执行前检查、执行后验证和审计收据。

通用 Skill 不得包含美团店铺、淘宝闪购频道、微信联系人等业务语义，也不得保存账号、口令、聊天内容、订单信息或设备私密数据。

### 10.3 业务工程职责

`zhensi_waimai` 负责：

- 三个平台的包名、页面语义、选择器指纹和版本差异；
- 美团店铺搜索与经营字段采集；
- 淘宝闪购频道进入、搜索与即时零售字段采集；
- 微信会话定位、草稿准备和经批准后的发送流程；
- 平台专属弹窗、字段抽取、流程检查点和业务结果模型；
- 任务编排、运行参数、输出制品和业务收据。

### 10.4 动作风险分级

| 等级 | 示例 | 默认策略 |
|---|---|---|
| `READ_ONLY` | 设备探测、截图、控件树、查看、滚动 | 可直接执行，仍生成收据 |
| `LOCAL_EDIT` | 在本地组织参数、生成文本草稿 | 可执行，但不得自动提交到第三方 |
| `EXTERNAL_EFFECT` | 发送消息、提交订单、支付、发布、删除、确认收货 | fail-closed；最终动作前必须获得明确授权 |

“输入到第三方表单”不是纯本地编辑。凡是会把内容传给第三方、改变线上数据或影响交易状态的动作，都必须按 `EXTERNAL_EFFECT` 管理。

### 10.5 通用动作结果

每个动作统一生成 `ActionResult`：

```text
actionId / deviceId / appPackage / actionType / riskLevel
beforeState / afterState / selectorUsed
screenshotBefore / screenshotAfter
success / failureReason / startedAt / finishedAt
```

页面跳转成功必须由包名、Activity、关键控件或页面指纹中的至少一种新鲜证据验证，不能把“点击没有报错”当作成功。

### 10.6 迁移原则

1. 先新增通用接口和平台包，再把旧文件收缩为兼容入口；
2. 未完成真机回归前不删除旧入口；
3. 系统权限弹窗归通用层，营销券、业务提示等归平台适配器；
4. 原“拟人化对抗风控”统一改述为操作速率、页面稳定等待、失败退避与平台规则遵守；
5. 微信等高风险业务默认只能导航到目标页面或准备草稿，发送动作必须单独授权；
6. 所有测试必须区分纯逻辑测试、合同测试和真机测试，不以缺少设备为由伪造通过。

### 10.7 实施波次

| 波次 | 内容 | 退出条件 |
|---|---|---|
| W0 | 冻结本文分治与安全契约 | 方案、目录、风险等级一致 |
| W1 | 创建通用鸿蒙手机控制 Skill | Skill 校验通过，通用脚本无业务词汇 |
| W2 | 新增业务工程通用运行接口 | 旧入口仍可导入，新接口有单测 |
| W3 | 重组平台配置、抽取器与工作流 | 三个平台合同测试通过 |
| W4 | 动作审批、页面验证和收据 | 外部副作用默认关闭，收据可验证 |
| W5 | 无副作用真机探测 | 只读设备/页面证据通过；无设备则明确阻断 |

## 10. 结论

- **鸿蒙 3 安卓兼容层**是本方案的目标运行环境；代码路径已建立，但必须通过现场 ADB/uiautomator2 探针后才能确认具体设备可用，**无需为本路径自研手机 App**
- **美团外卖 / 淘宝闪购 / 微信共用一套驱动层**，差异仅在应用层 Client——**换 App = 加一个 Client 文件**
