6. **交付**：申诉明细写当日 md 笔记 → 全申诉完成后汇总 Excel（按 `全部/未申诉/申诉中/申诉成功/申诉失败` 状态维度）→ 发群。

## 三、方案

### 3.1 命名与目录

```
skills/workflows/negative-feedback-list-appeals/
├── SKILL.md
├── references/20261006-负反馈列表申诉流程方案.md
└── scripts/
    ├── cdp.mjs                    # 金鲨 CDP 连接 + assertJinshaEntry（复用岗位 auth.mjs）
    ├── navigate.mjs               # 进入负反馈页、切平台/时间/状态，全链路回读
    ├── candidate_collector.mjs    # 未申诉候选采集 + 稳定判定
    ├── appeal_executor.mjs        # 逐条：prepared→ready→submitted_once→确认→权威回读
    ├── all_feedback_collector.mjs # 「全部」页分页全量（Excel 明细事实源）
    ├── report_builder.mjs         # Excel 生成（状态维度头部 + 明细）
    └── deliver_batch.mjs          # 固定投递器 → FEIBING NEO AI数字员工
```

记录目录：`records/negative-feedback-list-appeals/YYYY-MM-DD/<key>.md`
输出目录：`outputs/negative-feedback-list-appeals-YYYYMMDD/负反馈申诉汇总-YYYY-MM-DD.xlsx`

### 3.2 执行流程（四段闭环）

**① 导航门禁**（任一不符即 fail-closed，零副作用）
首页 → 锁定左侧渠道 `.cutli` = 美团/淘宝 → 点 `.el-menu-item`「负反馈列表」
→ 回读路由必须是 `#/evaluationManagement/feedback` → 选 `.optionli` 平台 → 点 `.reviewLi`「近7日」→ 回读两个 `input.el-range-input` 与「近7日」跨度一致 → 点 `.status-btn`「未申诉」→ 回读 `.status-btn.active` 与 5 个计数。

**② 候选采集**
`.feedback_list` 下可见卡片，含唯一可见 `.appeal_btn` 者为候选。
连读两次相同候选键集合才开跑（防空态/异步渲染误判）。
记录键 = sha256(平台 | 门店 | 评价日期 | 订单编号 | 问题分类)。

**③ 逐条申诉**（沿用同族防重四态）
- 点击前写 `prepared`
- 打开弹窗 → 等 `.appeal-dialog-body textarea` **连续两次读数一致**（避免刚打开的空白）
- 把实际文本 + 通过率写入 `ready_for_confirmation`
- 写 `submitted_once` 后**才**点「确定」
- 确认后权威回读：**同条目从未申诉列表移除 且 该状态页计数减少** ⇒ `verified_submitted`
- 回读失败 ⇒ `unknown` + **停止批次，绝不重发**（防双发）

**④ Excel 汇总 + 投递**
- 明细以「全部」页**分页回读**为事实源（行数必须 = 「全部」计数，不一致即停止生成）
- 头部状态维度：全部 / 未申诉 / 申诉中 / 申诉成功 / 申诉失败（读 `.status-btn` 计数）
- 本地 md 只补「申诉类型/核验」等页面没有的字段
- **0 条硬闸**：明细 0 行 ⇒ 不生成、不发送（铁律）
- 投递走固定投递器，复用 `workflow_bridge_windows.py`，群名/路径/事件键三重固定
