# 发送按键前上下文绑定

问题：当前正文全文与群标题在Python里分两次读取，然后另起原生调用按Return，用户在其间打字或切群时，按键动作仅校验AX角色/焦点，未再绑定正文值。原生UI树能定位控件，但系统键盘仍可能受并发输入影响。

最小修复：仍用原System Events脚本，把发送前已有的正文/群核对移动到同次Return调用中。动作expected增加精确正文（文字全文或已选附件占位U+FFFC），guards只允许精确路径只读属性核对、绑定完整目标群；执行脚本先核对这些属性，随后按原Return，不增加重试或新控制法。文字粘贴后原分离读取取消，避免多轮预检。JXA若在任何动作前明确拒绝guards，可返回结构化actionRejected且results为空；Python仅对此抛专用NativeUIActionRejected，发送器记录blocked0。普通异常或已有动作结果仍保留unknown，不能据错误文本推定零发送。

文件/图片只有已证明留在正文的附件草稿才使用同一Return绑定；实际文件预览确认分支不改。既有意图、SHA、队列、账本及所有未知记录保留。此修复缩短校验到按键的间隔，不能承诺操作系统层不可中断或完全消除用户输入干扰。

文件：skills/wechat-messaging/scripts/native_ui_tree.py、native_ui_tree.jxa、native_ui_post.py及对应tests。验证结构化拒绝、错误群/正文绑定、既有焦点失败零发送、未知不重发、全部回归。诊断不输入、不激活，不以生产外发验证；合成测试仍限原测试群、原适配器和独立事件。

验收：403项Python回归、4个实际JXA源码模拟场景通过（均不操作真UI）；测试群A05经原队列真实一次发送、完整正文双帧verified，整次11.812秒；重入1毫秒无preflight/send，不重复发送。普通未知与原账本保持，未做全后台或完全零干扰声明。
