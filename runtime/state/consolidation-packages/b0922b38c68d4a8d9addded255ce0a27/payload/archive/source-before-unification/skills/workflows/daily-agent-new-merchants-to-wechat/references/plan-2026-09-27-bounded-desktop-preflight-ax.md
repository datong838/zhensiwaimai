# 桌面微信预检 AX 子进程有界恢复方案（2026-09-27）

## 现场证据与根因判断

本轮唯一生产入口完整采集并审计出 1 条今日待发商家。桌面微信预检运行 60.011 秒后被统一截止器以 `deadline-expired` 终止；机器收据明确 `sendAttempts=0`、无发送复核、无 attempted/unknown，历史和游标未写入。共享交互锁在调用期间成功创建并已释放，复核时没有锁持有进程，因此锁竞争不是根因。预检输出目录没有生成定位截图；其首条定位路径是原子激活微信后读取 AX 树。由此可将故障定位到激活/AX 控制子进程未返回，但旧接口的 60 秒外部信号只留下通用截止码，无法区分二者。

根因是共享桌面控制器对预检启动路径中的 AppleScript 激活和 AX 树读取使用无超时的 `subprocess.run`；此外，激活前的 `ensure_window_size()` 在父进程同步调用 macOS AX API，也没有为 AX 消息设置期限。外围 60 秒信号只能留下通用 `deadline-expired`，不能收口或定位卡住的控制调用。

## 最小修复

1. 在共享 `wechat_desktop.py` 为预检快速路径中的微信激活 AppleScript 与 AX 树读取设置独立、有限的 20 秒子进程超时；将超时转为稳定、可审计的 `wechat-window-activation-timeout` 或 `wechat-ax-read-timeout`。同时给 `ensure_window_size()` 的唯一微信 app/window AX 元素设置 5 秒消息超时，防止父进程被系统 AX 调用无限阻塞。
2. 在 AX 树读取脚本中对每个访问元素设置 5 秒 AX 消息超时，并保留 20 秒总子进程上限；超时故障不得回退到猜测群身份或发送。
3. 在共享 `desktop_preflight.py` 将上述两个明确错误保留为机器原因，不折叠为笼统预检错误。
4. 补共享桌面回归测试：激活和 AX 读取子进程分别模拟超时，证明明确错误和超时参数；AX 消息超时设置覆盖唯一 app/window；错误归一化保留明确阶段。测试不触碰真实微信、不发送消息。
5. 先跑共享桌面专项测试，再走 `wechat-messaging` 代码维护入口刷新其依赖摘要及全量回归；之后由商家 `maintenance_executor.py` 原子刷新未封验收态和当前摘要。仅当代码机器收据证明零发送且无 attempted/unknown 时，才用新的唯一私有输出目录再次调用生产 `workflow_executor.py`。

## 风险、边界与完成标准

- 更快失败只缩短卡住的预检，不增加重试次数，不改变已发送/未知防重规则，也不扩大群、通道或授权范围。
- 子进程超时、登录/风控信号、群身份歧义或其他硬门禁仍停止当前外部动作；任何发送之后的不确定结果只能只读对账，禁止重发。
- 完成要求：新代码及共享与商家测试通过；共享依赖和商家维护收据回读通过；唯一生产复跑的机器收据显示准确发送次数、全文复核、历史及游标最终状态，并生成 review.json/review.md。若新复跑仍未能确认群或需要登录，则不继续尝试发送，按机器收据报告所需用户操作。
