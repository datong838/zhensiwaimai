# 微信扫描非法时间容错方案

## 现场问题

微信窗口 OCR 可能把聊天时间识别成 `18:84` 一类非法时分。当前 `parse_message_time` 直接调用 `datetime.replace`，因此整轮扫描会以 `ValueError` 中断。

## 最小修复

- 仅在聊天消息时间解析入口校验小时为 `0..23`、分钟为 `0..59`。
- 非法 OCR 时间返回 `None`，由现有扫描逻辑忽略，不把它作为下载边界或候选来源。
- 保持合法的今天、昨天、星期及完整日期格式行为不变。
- 不修改微信点击、视频下载、平台上传、发布、checkpoint 或去重逻辑。

## 验证

- 增加今天、昨天、星期三种非法时分测试。
- 运行全部现有 Python 测试与编译检查。
- 清空本轮尚为空的候选记录后，从同一批次重新扫描；只有目标群、目标发送人、合法消息时间三者同时成立才允许下载。
