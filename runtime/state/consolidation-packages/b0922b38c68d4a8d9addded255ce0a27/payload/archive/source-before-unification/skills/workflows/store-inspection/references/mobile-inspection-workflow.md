# 手机巡店固定执行方案

## 目标

把已经验证的动作固化为“当前页面取证 → 语义定位 → 下一页面复验”的固定链路。业务执行阶段不保存裸坐标，不在两套手机控制方式之间切换；大模型只负责根据已保存证据形成诊断和建议。

## 执行前准备

1. 只选一个非 `emulator-*` 的物理设备；存在多个物理设备或没有物理设备时停止。
2. 确认 `adb`、`uiautomator2`、中文输入通道和 `ocr_vision` 可用。
3. 从本周台账锁定 `平台 + 城市 + 台账店名`；先建立该店唯一证据目录。
4. 明确安全动作白名单：启动 App、返回、搜索、选择地址、进入目标店、切换“点餐/评价/商家”、安全滚动、截图。
5. 领券、收藏、加购、下单、拼单、电话、导航、买单和提交类按钮始终禁止。
6. 美团外卖固定通过 `mobile_inspection_executor.py start-platform-app --platform 美团外卖` 启动原生美团 App（包名 `com.sankuai.meituan`）；不得改走微信美团小程序，也不得由运行时临时选择入口。

## 无裸坐标定位

- 每次点击前重新截图并执行 OCR；坐标只来自本次 OCR 框中心，动作后立即失效。
- UI 树存在目标文字或描述时优先使用 UI 树；WebView 不暴露语义时才使用 OCR。
- OCR 使用归一化比较：忽略全半角括号、空格、`·/•/.` 等标点差异，但核心汉字顺序不能改变。
- 同一归一化文字出现多次时，结合页面标题、商圈/地址和相邻字段消歧；仍不唯一则停止该店。
- 动作后必须在下一帧看到预期页面标题、目标店名或目标 POI，不能把“点击成功”当作“业务成功”。

## 地址与店铺身份门禁

1. 消费者端搜索受配送范围约束时，先切换到门店所在商圈的精确 POI。
2. 淘宝闪购：从搜索页地址入口进入“选择收货地址”，中文搜索 POI，选择后回到搜索页，并确认顶部地址已变化。
3. 美团外卖：优先从全局搜索页的“切换地址”进入“选择收货地址”；该路径在 2026-09-09 真机回归中稳定。首页定位入口若触发滑块验证，停止自动处理，重启美团后走全局搜索页路径，不自动绕过验证。
4. 搜索完整店名，保存搜索结果证据。台账名与消费者端名称轻微改名时，只有核心品牌、商圈/城市和商家页地址同时一致才可继续，并在结果里记录“名称口径漂移”。
5. 仅出现近似店、同品牌其他分店或到店团购页时立即作废，不作为外卖巡店结果。
6. 执行前运行 `mobile_inspection_executor.py validate-route`；仅允许 `references/verified-store-routes.json` 中的城市、POI、台账名、消费者端名称及地址锚点组合。美团陶姥姥的已登记名称漂移是唯一白名单，其他漂移失败关闭。

## 每店固定证据序列

报表混合模式不得默认执行完整序列。先读取 `hybrid_inspection_executor.mjs plan` 生成的 `mobileChecklist`，按 `search → products → reviews → merchant` 只进入包含模板行的模块；每个模块进入前必须通过 `mobile_inspection_executor.py validate-mobile-module`。计划没有 `reviews` 时不打开评价页；某模块 `skipped / failed` 后仍继续后续独立模块，并在 `finalize` 输入中留下对应收据。

1. 搜索结果：完整店名、商圈/城市、评分、月售、起送、配送费、距离/时效。
2. 商品首页及安全下翻：店内顶部、评分/月售、分类、代表商品、价格、月售和促销。
3. 评价及差评：评价总量、好差评、商家回复、评分维度、原文主题、日期和星级。
4. 商家资料：消费者端店名、地址、营业/配送时间、证照和服务标签。
5. 截图与 OCR 只用于当前过程复核和定位，不作为结果 Excel 的交付附件；未交付图片时，结果表不得出现图片文件名或“证据：”文字。

六张截图不是巡店项目，只是取证节点。巡店项目必须来自模板。某条模板检查点无法由六张消费者端截图判断时，对应发现、证据和方案均留空，不能从截图之外推断。

## 结构化与制表

1. 每店过程目录必须包含 `inspection.json`，其中 `templateChecks` 必须正好覆盖模板第 2–45 行，共 44 条；每条包含 `row`、`finding`、`recommendation`。
2. 消费者端、报表或后台均不可见，或因平台错误无法读取的检查点，`finding` 与 `recommendation` 同时留空，禁止补猜数字或写入“未核验”。
3. 使用 `scripts/build_inspection_result.mjs` 导入 Skill 内固定模板，在 B 列写“检查点 + 巡店发现”，在 C 列写本店具体方案；不得创建自定义四表，也不得写入未交付的证据文件名。
4. 使用 `scripts/test_inspection_result.mjs` 检查模板项目/检查点顺序、44 行覆盖、发现与方案非空；渲染整张表查看，确认没有截断、空项和跨店证据。
5. 本地试巡只写 `runtime/results/年-月-第x周/`，不回写周台账完成状态，不上传企业微信。

## 停止与恢复

- 同一节点最多一次受控恢复；恢复动作必须回到上一个已验证页面。
- 目标身份、城市/商圈或地址无法确认时停止该店，不换成近似店。
- 出现验证码、安全校验或登录失效时停止自动处理，不绕过安全措施。
- 用户手动关闭验证码后，重新保存当前帧，再继续尚未受影响的独立分区；不对验证码区域执行输入、识别或重试。
- 输入命令前必须确认焦点已在可编辑控件；输入法返回空指针、OCR 合框或重复命中时失败关闭，回到已验证页面重新取帧，不使用历史坐标。
- 发生误入到店团购、买单、领券等非目标页时立即返回并作废该页证据。
