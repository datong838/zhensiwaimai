# 企业微信群视频下载技术方案

## 1. 目标

从指定企业微信租户的指定群中，按明确条件下载文件附件或原生视频卡片，并把可发布文件交给后续三平台流程。企业名称、登录账号、群名、群类型、发送人、时间边界、文件数量和输出目录都是运行参数，执行器不得写死任何企业或本机 Profile。

本次验收样例：

- `enterprise_name=上海臻肆文化传播有限公司`
- `enterprise_marker=上海臻肆文化传播有限公司`
- `group_name=临时测试群`
- `expected_count=2`
- `file_types=[mp4]`

样例只用于验收，不作为默认业务配置。

## 2. 能力选型结论

### 2.1 默认路线：企业微信 Mac 客户端可见自动化

适用于已经人工登录、没有会话内容存档权限、需要处理既有人工内部群附件的场景。

控制器连接当前可见的企业微信客户端，通过辅助功能树识别当前企业、群标题、消息行、文件名和文件大小。下载动作发生在客户端中；落盘后再按界面已确认的精确文件名查找客户端本轮产生的文件，复制到本轮隔离目录。

这条路线不使用 CorpID、Secret、Cookie、Hook、协议注入或客户端逆向。

### 2.2 规模化路线：企业微信会话内容存档

适用于企业已经开通会话内容存档、需持续自动处理多个群或多个企业的场景。

前置条件：

1. 企业开通相应版本的会话内容存档。
2. 应用具有数据与智能专区/会话内容权限。
3. 涉及成员在生效授权列表；外部客户场景还要满足客户同意要求。
4. 使用会话存档专用 Secret、私钥和官方 SDK，凭据由外部密钥系统注入。
5. 每个企业独立 token、游标、密钥、队列和文件命名空间。

数据流：

```text
msgaudit_notify 新消息提示
  → 按企业游标拉取存档消息
  → 官方 SDK 解密消息
  → roomid 映射并核对群名
  → 过滤 video/file 消息、发送人和时间
  → 根据消息中的媒体标识用官方 SDK 分片拉取媒体
  → SHA-256、格式、大小与消息身份校验
  → 写入本轮目录并提交新游标
```

新消息事件约按十五秒窗口聚合，只表示可能有新数据，不能代替按游标拉取。媒体拉取接口、SDK 版本和分片规则在编码前必须重新核对当时官方文档；无法确认时状态为 `NEEDS_VERIFICATION`，不得猜接口。

### 2.3 不适用的官方接口

- `appchat/get`、`appchat/update`：只适用于企业自建应用自己创建的应用群聊；只能管理群资料和成员，不能读取既有人工群的消息历史或下载附件。
- 应用消息 `message/send`：用于应用向成员/部门发送消息，不是读取人工内部群历史的接口。
- 智能机器人：群聊回调依赖用户与机器人发生明确交互；当前官方说明中的本地文件和视频回调仅支持单聊，不能作为任意内部群视频采集器。
- 客户群接口：面向外部联系人客户群，不能替代内部群消息读取。
- 群机器人 Webhook：主要用于发送，不提供任意群历史读取能力。

## 3. 运行参数

```yaml
connection_mode: desktop        # desktop | message_archive
enterprise:
  expected_name: "${ENTERPRISE_NAME}"
  app_name: "企业微信"
  bundle_id: "com.tencent.WeWorkMac"
target:
  group_name: "${GROUP_NAME}"
  sender: "${SENDER_OR_EMPTY}"
  after: "${ISO_TIME_OR_CURSOR}"
  expected_count: 2
  extensions: [".mp4"]
output:
  root: "${OUTPUT_ROOT}"
  run_id: "${YYYYMMDD_NN}"
policy:
  exact_group: true
  exact_filename: true
  allow_global_latest_cache: false
  unknown_retry_limit: 0
```

密钥类配置只允许使用密钥管理系统或进程环境注入，不写入 YAML、代码、日志和 Skill。

## 4. 桌面模式工作流

### 4.1 连接与身份预检

1. 附着已经运行的 `企业微信` 应用，不主动切换登录企业。
2. 读取当前窗口和企业上下文；无法确认 `enterprise.expected_name` 时停止。
3. 搜索或选择 `target.group_name`，进入后再次从聊天标题精确回读群名。
4. 群名只接受完整匹配；会话列表摘要不能代替聊天标题。
5. 每次点击前刷新辅助功能树，禁止复用旧元素序号。

### 4.2 候选识别

从目标群聊天区读取消息行，候选必须同时满足：

- 当前聊天标题等于目标群名；
- 文件扩展名在允许列表；
- 文件名、界面大小、发送人和时间条件符合配置；
- 不是群看板、引用预览、其他会话摘要或已处理文件；
- 同一文件名在本轮只产生一个候选。

候选身份键：

```text
enterprise_name | group_name | sender | message_time | filename | ui_size
```

落盘后以 SHA-256 作为内容身份键。

原生视频卡片不显示源文件名时，候选身份改为：

```text
enterprise_name | group_name | group_type | sender | message_time | duration | row_sequence
```

执行器先冻结当前群消息行：只接受目标发送人、带原生播放控件和时长的消息；带 `[视频号]`、`sph` 标识或没有原生播放控件的卡片必须排除。同一时间批次内缺省的逐条时间继承上一条明确的企业微信消息时间。

### 4.3 下载与落盘

1. 对候选文件执行客户端的下载/打开动作。
2. 等待附件状态由未下载转为可打开，或精确同名文件在客户端本轮目录中稳定出现。
3. 文件大小连续两次不变后才认为下载完成。
4. 只查找目标群界面已经确认的精确文件名；禁止选择缓存目录中“最新的视频”。
5. 将文件复制到 `${OUTPUT_ROOT}/${enterprise}/${group}/${run_id}/videos/`。
6. 记录源文件名、目标路径、字节数、SHA-256、下载时间和状态。
7. 验证 MP4 容器可读；可用时读取时长、宽高并生成首帧供人工检查。

客户端缓存位置只能运行时发现，不得写死企业 Profile 哈希。若存在多个同名缓存文件，必须结合本轮时间、界面大小及哈希消歧；仍不能唯一确认则进入 `download_unknown`。

对于无文件名原生视频，执行器在目标群预检后按本轮冻结候选进行整批绑定：活动企业 Profile、缓存生成时间窗口、候选数量和四舍五入后的完整媒体时长多重集合必须全部一致。只要存在额外文件、缺少文件或时长集合不一致，整批进入 `ambiguous_source`。同一时长的多个视频只作为已验证批次成员处理，不伪造逐条文件名映射。

### 4.4 完成判据

只有以下条件全部成立才返回 `downloaded`：

- 企业、群标题和文件名全部匹配；
- 目标文件存在且非空；
- 文件大小稳定；
- SHA-256 已生成；
- MP4 可读取；
- 实际成功数量等于 `expected_count`。
- 无文件名视频的缓存文件数量和媒体时长多重集合与冻结候选完全一致。

本轮完成后暂停，由人工检查视频内容。未经检查通过，不进入文案准备和平台发布。

## 5. 状态机与重试

```text
discovered
  → download_pending
  → downloading
  → downloaded
  → human_review_pending
  → accepted | rejected_wrong_content
```

异常状态：

- `blocked_login`：未登录或企业不匹配。
- `blocked_group`：目标群不存在或标题无法精确确认。
- `download_unknown`：点击后无法确认是否落盘；先查结果，禁止重复点击。
- `ambiguous_source`：出现多个无法唯一绑定的同名文件。
- `invalid_media`：文件为空、损坏或容器不可读。

允许对“读取状态失败”做一次有界恢复；不得对结果未知的下载动作盲目重做。

## 6. 多企业隔离

执行器代码共用，运行状态必须按企业隔离：

```text
state/<enterprise_key>/<group_key>/checkpoint.json
runs/<enterprise_key>/<group_key>/<run_id>/
```

`enterprise_key` 使用配置生成的稳定别名，不能使用或记录 Secret。切换企业时重新执行登录态、企业名和群标题预检；不得沿用另一企业的窗口元素、缓存路径、游标或去重索引。

## 7. 拟开发文件

实施前复核本方案与 `qiyeweixin` Skill，最小新增范围：

- `scripts/wecom_download.py`：命令入口和状态机。
- `scripts/lib/wecom_desktop.py`：企业微信窗口、企业、群和附件语义操作。
- `scripts/lib/wecom_config.py`：参数校验与企业隔离路径。
- `scripts/lib/wecom_media.py`：精确文件发现、稳定性、哈希和媒体校验。
- `scripts/test_wecom_config.py`：企业切换、群名和路径隔离测试。
- `scripts/test_wecom_media.py`：同名文件、半下载、错误扩展名和错误缓存测试。
- `scripts/test_wecom_state.py`：未知结果不重试、数量不足不完成测试。

会话内容存档适配器作为后续独立模块，避免把管理员权限和 SDK 依赖带进默认桌面路径。

### 7.1 本次落地决策

- 主执行器默认且唯一的下载来源改为 `wecom_desktop`；旧普通微信模块暂时保留为未接线的历史实现，避免破坏已有证据，但 `SKILL.md` 和 `workflow_executor.py` 不再调用它。
- `--enterprise`、`--group` 是初始化必填参数。`--enterprise-marker` 用于核对当前企业微信窗口内可见的企业标识；省略时使用 `--enterprise` 本身。当前实操使用完整标识“上海臻肆文化传播有限公司”；未来切换企业时必须重新传参并重新预检。
- 批次写入 `runs/<enterprise_key>/<group_key>/<run_id>/`；处理索引写入 `state/<enterprise_key>/<group_key>/processed_index.json`。同名群和同名文件不能跨企业复用状态。
- 附件发现只接受当前聊天辅助功能树中完整回读出的 `.mp4` 文件名和显示大小。缓存搜索以这些精确文件名为输入，禁止按修改时间选择全局最新视频。
- 当前桌面模式不能稳定回读附件发送人和逐条消息时间，因此这两个筛选条件只在界面确实提供证据时启用；传入后无法核实时失败关闭，不做推测。
- 下载完成后统一进入 `human_review_pending`。`prepare` 只有在封面主题门通过时才生成发布计划；无法判定时保留原视频并标记 `review_required`，不再删除文件。
- 发布桥接器及三平台状态机保持不变。本轮回归止于下载，不触发任何平台上传或发布动作。
- 每个视频只生成并人工校对一次 `caption`。`publish-plan.json` 保存视频内容哈希、`captionVersion` 和唯一文案；抖音、快手、视频号三个发布器只读取同一条文案，禁止在平台循环中再次 OCR、再次生成或各自改写。
- 下载命令必须可幂等回放：已经完成的文件不重复复制，返回本批累计成功数；只有整批文件仍然存在且状态完整时才维持成功和游标。

## 8. 验收用例

1. 正向：指定企业、指定群中两个 MP4 均下载并生成不同哈希。
2. 企业隔离：切换到另一企业时必须重新确认企业名，不能沿用上次路径。
3. 群隔离：同名文件出现在其他群时不得拾取。
4. 半下载：文件大小仍变化时不得标记完成。
5. 重名：多个同名文件不能唯一绑定时失败关闭。
6. 焦点变化：用户切换窗口后重新读取状态，不按旧坐标点击。
7. 登录失效：停止并返回 `blocked_login`。
8. 数量不符：实际文件数不是 `expected_count` 时整体不完成。
9. 内容验收：下载后暂停，人工拒绝的视频不得进入发布计划。

## 10. Skill 证据

- `qiyeweixin/SKILL.md`：先识别主体、群类型和动作，再选能力；未知权限为 `NEEDS_VERIFICATION`。
- `playbooks/conversation-archive.md`：会话存档前置权限、游标拉取、解密、隔离和合规边界。
- 官方资料 `document-path-92951-92951.md`：会话存档内部群信息使用 `roomid` 和会话存档专用凭证。
- 官方资料 `document-path-95039-95039.md`：`msgaudit_notify` 是十五秒聚合提示，不携带具体消息。
- 官方资料 `document-path-98914-98914.md`：应用群聊详情只允许读取该自建应用创建的群。
- 官方资料 `document-path-100719-100719.md`：智能机器人群聊触发边界，以及文件/视频消息仅支持单聊。
