# 文件与图片大小统一约束

适用于全项目所有工作流和UI岗位，不按某个附件临时制定88K或89K的门槛。

1. 源文件身份按冻结字节、SHA、完整文件名绑定，不能因显示取整改变原字节或伪造读回值。
2. 客户端显示大小仅是辅助核验。共用校验按B/K/M/G及实际小数精度保留一个显示单位的换算余量，兼容向下取整、向上取整和四舍五入；双帧必须实际一致。90735字节显示88K或89K都合理，87K或90K不通过。
3. 上传硬上限与显示值分开。只有有明确配置的真实上限时，产物目标不高于上限的95%，提前留至少5%余量；不能把文件卡显示值误当上传上限。没有真实上限时不强行压缩到85K，以免损失可读性。
4. 接近真实上传上限的图片在生成环节优化，先保证文字可读；不能发送失败后临时随意缩图或改源SHA。需要新文件时重新冻结并沿原授权/防重合同处理。
5. 统一纯函数位于skills/wechat-messaging/scripts/file_size_policy.py，UI队列与旧文件卡只读核验共同调用。未来新任务必须复用，禁止另写floor或硬编码某个K值。测试覆盖单位、小数、边界、误差越界及真实上限留量。
