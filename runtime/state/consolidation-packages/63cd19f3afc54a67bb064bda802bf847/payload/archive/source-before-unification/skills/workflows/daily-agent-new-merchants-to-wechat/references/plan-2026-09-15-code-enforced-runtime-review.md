# 代码强制门禁与逐项复盘升级

## 产品目标与授权

用户要求“已写入执行器代码才算沉淀”，每轮成功、无新增、失败都展示每项耗时和踩坑点。模型仅阅读结果、进行维护诊断；是否允许继续、恢复和提交由固定代码决定。本次变更按用户的明确升级指示执行，维护期暂停原心跳、备份并进入有期限的解封验收；不得用空跑或历史验收为新代码封板。

生产群与生产游标保持原绑定。开发验收沿用本 Skill 已有测试群 FEIBING NEO AI数字员工及独立测试游标的站立授权，以真实尚未通知的测试增量进行非空验收；生产群仅执行正常增量或无新增重放，不重复发送已完成3条通知。

## 复盘格式与成功条件

每行包含序号、阶段、商家身份（如适用）、elapsedMs、状态和pitfalls数组。父阶段和子阶段明确标识，不把嵌套耗时重复相加；未进入阶段标记SKIPPED、elapsedMs=null，不能伪造0秒成功。已恢复问题也保留，不因最终成功删掉踩坑。复制复核和历史/游标提交单独计时。review.md仅由结构化review.json渲染，无模型补写事实。

无新增也必须有封板、策略、自测、预检、采集、审计、无新增发送节点、最终检查及总耗时。失败时保留原始收据、已提交游标、失败节点与未执行节点。报告生成异常必须使本轮返回失败，不因此补发。
