实机还确认“未申诉”计数先更新、候选卡片随后分批渲染。筛选后先连续两次读取同一组候选键才开始逐条处理；列表未稳定即不创建确认动作。这样不会把后续异步渲染的已申诉/已拦截卡片误作候选。

页面会保留隐藏渠道和旧筛选的 `.cryptonym` 节点。候选采集与点击定位都只接受 `offsetParent !== null` 的可见卡片；隐藏节点即使文字包含“自动申诉已关闭”或“立即申诉”也不能进入记录或点击范围。

候选资格不再以卡片继承文本推断，改为同一可见卡片内恰有一个可见 `.btn` 且文字为“立即申诉”。记录筛选与点击使用完全相同的条件，避免“已写 prepared、但没有实际按钮”的假候选。
