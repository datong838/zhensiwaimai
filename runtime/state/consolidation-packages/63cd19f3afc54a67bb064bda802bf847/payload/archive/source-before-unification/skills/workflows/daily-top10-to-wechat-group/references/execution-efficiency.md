# 执行效率与压力测试规程

## 1. 复盘结论

此前未在 3 分钟内完成，根因不是单个工具耗时，而是执行前准备不完整和主链路失控：执行中补读文档、浏览器控制通道切换、Chrome 未先全屏并锁定焦点、导航完成后继续操作菜单、重复读取巨型页面状态、手机准备被拆成多条零散命令。进入无关「顾客管理」是流程偏航的直接证据。

## 2. 禁止边学边做

开始任何业务动作前，必须一次性完成：

1. 完整阅读主 Skill 及本次会用到的全部引用规程；输出被截断时继续读到 EOF。
2. 完整阅读会调用的浏览器、计算机控制、微信和设备控制 Skill。
3. 确认唯一操作主链路、唯一控制通道、页面完成判据、失败处理和外部动作边界。
4. 只读预检浏览器登录态、设备连接、图片目录、微信实例和目标群配置。
5. 把可合并的设备探测、推图、媒体扫描和哈希核对准备成一个有界步骤。

开始执行前必须逐项具备：

- 唯一操作主链路；
- 所有必要工具已经连接并完成只读可用性检查；
- 页面和设备状态已经只读预检；
- 快速路径、完成判据与停止条件明确；
- 坐标、元素编号、窗口尺寸和焦点策略明确；
- 外部动作授权规则明确；
- 每阶段最多一次重试，禁止临场探索。

准备未完成时不得启动压力测试计时，不得点击业务页面、启动微信或执行外部动作。

## 3. 当前后台 Chrome 隔离规则

唯一主通道为后台专用浏览器：`taobao-brand`、`127.0.0.1:9230`、每轮唯一 task-id 标签。执行器不启动或重启 Chrome，不接触日常 Chrome，不激活窗口，不发送系统键鼠。
每次从固定品牌商首页开始，按唯一可见 DOM 链接进入门店分析；以父页面 URL、唯一内层 frame、昨日 checked class 和已选日期排除旧 iframe。截图按表格容器与分页器当次 DOM 几何裁剪，不读取登录凭据或中途切换控制通道。

## 4. 唯一桌面主链路

只允许：

`后台 Profile/CDP 门禁 → 唯一任务标签首页 → 门店分析 → 昨日 → 营业额降序 → 10 行/分页 → DOM 几何截图 → 自检`

当 URL 包含 `/store-analysis` 时停止侧栏导航；随后以门店数据、昨日 `Value=1`、表格和分页器完成业务内容复核。页面停在表格底部时「门店分析」标题可能不在当前无障碍树中，不得因此重新寻找侧栏入口。立即进入日期、排序和布局，不得处理菜单焦点、探索其他入口或点击任何无关模块。

每个阶段最多一次常规重试。第二次失败、进入无关页面、焦点不确定或状态无法证明时立即暂停复盘。

## 5. 最小检查点

只保留：

1. Profile、headless 进程、9230 和 task-id 唯一。
2. 门店分析 URL、门店数据、昨日三项一致。
3. 前 10 个营业额严格非增序，分页为 10 条第 1 页。
4. 表头和 10 行完整同屏。
5. 成品 1500 px 以上、无顾客信息、字段清晰、哈希已生成。
6. 主微信、完整群名、唯一图片、原图和发送结果。

禁止为同一状态重复读取完整无障碍树、重复截图或重复排序。

## 6. 主微信快速路径

荣耀双开环境不以图标位置推断实例。用户已指定主微信时：

1. 执行前完成一次物理设备和主微信配置预检。
2. 推图、媒体扫描和设备端哈希核对合并执行。
3. 启动 `com.tencent.mm/.ui.LauncherUI`。
4. 若出现华为双开选择器，依据当前页面文字/描述直接选择普通「微信」，禁止选择带分身角标的实例；不在此时补读文档或查询启动入口。
5. 立即核验前台包名和主用户进程，然后搜索完整群名「FEIBING NEO AI数字员工」。

正常路径只有“启动 → 选择主微信 → 核验”三个动作。

## 7. 当前压力测试站立授权

适用范围仅限：

- 主微信；
- 唯一目标群「FEIBING NEO AI数字员工」；
- 本 Skill 当次生成并通过自检的一张昨日 Top10 PNG；
- 勾选原图后单击一次发送；
- 发送后完成群内气泡和大图复验。

在此范围内不重复展示逐图授权单。群名不唯一、微信实例变化、文件未通过自检、内容类型变化、选择数量不为 1 或发送结果未知时立即停止，不自动重发。

## 8. 3 分钟预算

| 时间轴 | 阶段 |
|---|---|
| 0–10 秒 | 后台 Profile/CDP 与任务标签门禁 |
| 10–25 秒 | 数据中心 → 门店分析 → 昨日 |
| 25–45 秒 | 营业额降序与 10 行验证 |
| 45–75 秒 | 布局、关闭截图范围内遮挡、立即截图 |
| 75–90 秒 | 尺寸、隐私、行数、哈希自检 |
| 90–105 秒 | 推图手机并刷新相册 |
| 105–120 秒 | 打开主微信并定位测试群 |
| 120–145 秒 | 唯一图片、原图、发送一次 |
| 145–165 秒 | 群内气泡与大图复验 |
| 165–180 秒 | 最多一次受控恢复 |

目标总耗时 165 秒以内，180 秒为硬停止线。预计无法在 3 分钟内完成，或出现偏航、失焦、重复探索时，立即暂停并报告，不继续消耗时间。

## 9. 超时终止规则

超过时限后立即停止所有外部动作并转入复盘。禁止一边继续操作、一边解释效率问题；禁止以“继续准备”“再试一次”或追加命令掩盖已经发生的超时、偏航或状态不确定。

## 10. 执行器合同（旧 sky 细节为历史兼容说明）

### 10.1 旧 sky 桌面执行器（保留兼容，当前不调用）

实现 `scripts/desktop_executor.mjs`，由 `node_repl` 导入并传入当前 `sky` 实例；计时阶段只调用一次 `runDesktopExecutor()`。执行器内部完成：

1. 获取 Chrome 最新状态并确认目标标签；
2. 锁定前台与全屏，窗口变化后废弃旧元素；
3. 直接点击当前可见的门店分析/昨日控件，不运行导航分析脚本；
4. 有界轮询昨日数据，验证 10 行营业额非增序；必要时只排序一次；
5. 固定为第 1 页和 `10 条/页`，使用 67% 缩放并将页面底部对齐，使表头、10 行和完整分页器进入同一裁剪图；分页器是视觉完整性的确定性锚点，不再用逐行 OCR 或模型看图计数；禁止为了塞入十行降到文字不可直接阅读的 50%；
6. 在同一控制会话内截图、原像素裁剪、OCR 隐私扫描、尺寸和哈希自检；
7. 返回单个 JSON 收据：状态、阶段耗时、数据日期、文件路径、尺寸、哈希、营业额数列、失败阶段和原因。

状态轮询使用短间隔与明确截止时间，不使用固定长等待；同一阶段最多一次常规重试。执行器不得发送进度消息，也不得在中途返回模型请求判断。

布局滚动目标不得只依赖固定 iframe 名称。优先使用当前状态中的门店分析内层 `HTML 内容`，短时未出现时退到含 `/store-analysis` 的外层页面 `HTML 内容`；每次缩放后重新读取元素，禁止复用缩放前编号。两者均不存在才失败。滚动后必须重新验证 URL、昨日和 10 行营业额非增序，避免把“滚动动作成功”误当成布局成功。

若缩放后的无障碍状态临时缺失内外层 `HTML 内容`，不得因此失败：改用目标应用内 `End` 将当前门店分析页对齐到底部，再用一次 `Up` 给表头留出空间。最终截图必须直接包含「门店名称」和「10条/页」；这两个成品证据不成立时拒绝收据。

### 10.2 手机执行器

实现 `scripts/phone_executor.py`，使用固定 HarmonyOS 运行时；计时阶段只调用一次。执行器内部完成：

1. 显式绑定唯一物理设备，核验型号、图片哈希、主微信和目标群合同；
2. 推图、媒体扫描和设备端哈希核对；
3. 一次启动微信，选择普通微信并核验 user 0 主任务；
4. OCR 搜索完整群名并核对会话顶部标题；
5. 通过目标图片视觉指纹选择唯一图片，勾选原图并核对发送数量为 1；
6. 在站立授权范围内单击一次发送；
7. 核验新图片气泡，点开大图并比对 Top10 视觉内容；
8. 返回单个 JSON 收据：状态、阶段耗时、设备哈希、群名、文件哈希、发送尝试次数、复验结果、失败阶段和原因。

脚本默认 `--dry-run`，只做参数、依赖、设备和合同检查；只有同时提供 `--execute --standing-authorization zhensi-feibing-neo-ai-main-wechat-top10-v1`，且群名归一化后精确等于「FEIBING NEO AI数字员工」、图片自检收据有效时，才允许进入发送链路。发送结果未知时禁止自动补点。

微信 8.0.77 搜索框输入前再次核验前台包名为 `com.tencent.mm`。主通道使用当前焦点输入框 `set_text`；仅当其失败时允许一次剪贴板粘贴备用通道，不再依赖无响应的 ADB Keyboard 广播。新进入的空搜索页直接输入完整群名，输入结果必须经 OCR 完整匹配后才能打开群。开发真机测试使用 `--probe-locate-group`，只完成主微信、输入、搜索结果和群聊标题复核，不推图、不选图、不发送。

微信 8.0.77 真机 UI 树只暴露系统导航栏，不含微信页面节点，禁止声称能用 UI 树定位搜索按钮。微信首页不得硬编码搜索坐标或用固定间距推算；从当前截图顶部区域提取深色图标连通域，识别左侧放大镜和右侧加号后点击放大镜自身中心，并以搜索页文字做后置验证。若出现「发起群聊/添加朋友」菜单，说明误点 `+`，立即返回并停止当前尝试，禁止在菜单上继续输入。

发送后大图复验采用双证据合同，避免 Vision OCR 偶发漏掉单个表头造成假失败：先在大图查看器截图的中心区域按原图宽高比做有界纵向扫描，要求最佳裁剪与桌面原图的视觉指纹距离不大于 6；再要求「门店」「营业额」「有效订单」至少命中 2 项。视觉指纹保证没有打开错图，OCR 保证仍处于可读的榜单内容。发送前预览仍要求 3 项全部命中，不降低发送闸门。复验失败只报告，绝不补发。

### 10.3 当前总入口一次调用

准备阶段完成规则阅读、依赖、自测和参数装配。`workflow_executor.py` 内完成手机预检、后台专用浏览器桌面段、收据交接、手机执行与最终结果落盘；不在两段之间返回模型。180秒以任务标签打开首页开始，预检与总墙钟另外记录。发送一次后验证群内图及大图，未知不重发。
`--rehearse` 为互斥的无发送联跑模式，使用新鲜桌面收据与剩余整体期限；不能将预览通过冒充真实发送通过。单独手机训练允许同昨日旧收据，但保留图片哈希与业务检查，120秒止于预览。用户明确追加复跑才能提供固定重复授权ID，每个ID最多一次发送，原当天闸门保留。

桌面节点：focus_fullscreen、navigate_store_analysis、select_yesterday、verify_sort、layout、clear_obstruction、capture_self_check。手机节点：contract、push、open_main_wechat、locate_group、select_original、send_once、verify。每个已执行节点记录耗时；失败立即落盘，不隐式重跑。群名忽略人数与图标，不作图标种类判断。主路径以 `SKILL.md` 当前入口和稳定化方案为准。
