# 检测与恢复

## 桌面

只复用已登录WeChat。公共预检拥有AX当前标题快路径、唯一会话、精确搜索和标题复核。公共主窗抬升、窗口ID截图、AX输入框定位与跨进程互斥通过依赖摘要锁定。

仅发送前的明确瞬态（焦点未就绪、搜索区抢占、零标题/零结果）可在30秒及总截止时间内每2秒观察一次；多个候选、登录失效、草稿、未知错误立即停止。截图硬失败时不得切换发送方式或继续发送；按下文环境恢复流程处理。整个批次持有公共交互锁，不与外层重复加锁。

超时、进程退出或发送返回丢失，在有attempted后全部unknown。不能以底层未返回发送次数为0判定未发。reconcile只执行文本复制复核，没有发送函数。媒体证据不足仍unknown，不进行“证明没发过所以再发”的自动补偿。

## 手机

`scripts/mobile_readiness.py`提供显式serial/userId的只读probe：检查设备在线、非模拟器、指定微信进程及PNG可用；不输出原serial。userId=0/128分别表示本机主实例/分身候选，进程存在不等于登录/目标群已验证。

既有优势已整理：绑定每条ADB命令、双开选择器精确区分、空控件树使用截图/OCR、点击前两帧位置稳定、发送前后剪贴板随机标记与原文复制、发图原图勾选和大图内容复核、文件上传完成与全名大小核对。当前主微信三类发送已提取到独立mobile适配器并完成本机验收，详见mobile-acceptance.md；不转调原业务脚本，其他机型仍需独立校准。

## 重启策略

`evidence.recovery_decision`固定判定：必须发送前、显式允许、无他人草稿、持有交互锁、恢复次数为0，才可计划一次组件重启并重新预检；attempted后仅reconcile。当前未接入真实重启执行，capabilities明确unsupported。不能因策略判断允许就让模型自行执行系统命令。

### 固定投递的环境故障恢复

固定投递器在 `sendAttempts=0` 时若因微信窗口截图失败而阻断，先把它当作环境故障处理，不先判定业务代码有错。保留原事件、原载荷和账本，不改代码、不创建新事件、不换浏览器/通道、不使用文件选择器或手工发送分支。

按原链路报告具体应用和故障，或在确认没有他人草稿、未完成上传等未保存状态后，仅重启发生故障的应用。需要登录、验证码或账号恢复时停止在登录界面，由用户完成登录；不索取或代填凭据。恢复后只用原业务入口、原群、原文件和原事件重新执行，并重新核对目标群、空输入区、文件名/大小及发送后回读。

只有前一回执明确证明仍为发送前阻断且 `sendAttempts=0`，才允许对同一事件沿原固定链路恢复一次；若出现 `attempted`、`unknown`、发送次数缺失或无法确定结果，只做只读对账，绝不重发。环境恢复失败时继续报告阻断原因，不以更换工作方式绕过门禁。

电脑/手机操作系统重启属于独立维护，不是常规自动发送恢复；不得自行重启整台系统。接收方向只保留明确范围要求，不默认读取或监听历史。

## 桌面验收补充

当前原生输入/激活使用唯一系统PID和微信应用标识核对，跳过虚拟消息列表。媒体发送后最多15秒只读等待两帧完成状态；图片上传转圈未消失不通过。仅属于本任务且有原零发送收据、同群同哈希与完全一致附件区域的草稿可清理。用户明确授权测试群重复测试时，每轮记录独立测试事件并保留旧unknown，不应用于生产自动补发。
