# 金鲨昨日双平台日报生产工作流代码强制门禁方案（2026-09-11）

## 目标

把生产流程中所有决定“是否允许继续、是否允许重试、是否允许下载、是否允许发送、下一阶段是什么”的规则从 Markdown 提示迁入代码。Markdown 只说明代码合同和验收证据，不再作为运行时授权或分支判断来源。

## 当前缺口

1. `business_exam_pipeline.mjs` 暴露 `--download|--prepare|--send|--verify-only`，调用者可以手工挑选阶段。
2. 调用者可以提供任意 `python`、发送器路径、输出目录、原始文件路径和成品名称。
3. 成品名称当前只检查扩展名和禁词，没有强制等于业务日期对应的两份固定名称。
4. 发送通道仍可由配置选择 `auto|wecom|desktop|mobile`；当前生产合同应固定为普通桌面微信。
5. 隐藏封板核心的 SHA-256 只在人工复盘时核对，未成为任何外部动作之前的运行时门禁。
6. 页面暂时不可用、桌面微信短时被占用、发送 attempted/unknown 等情况的恢复动作仍可能由调用者临时决定。
7. 最终 `--verify-only` 依赖调用者记得执行，没有状态机强制要求。

## 代码架构

### 唯一生产入口

新增 `scripts/business_workflow_executor.mjs`，只支持：

- `--execute`：代码生成当日唯一配置和运行目录，依次执行下载、制表、桌面微信发送、最终只读复核。
- `--resume <run-dir>`：读取既有状态和收据，由代码计算下一动作；调用者不能指定阶段。
- `--self-test`：无副作用策略自检。

生产入口不接受群名、授权、通道、Profile、端口、业务日期、文件名、发送器或输出目录覆盖。

### 中央策略模块

新增 `scripts/business_workflow_policy.mjs`，代码固定：

- `jinshaChannel=browser`；Profile `jinsha-business`；端口 `9232`；强 URL 前缀。
- `wechatChannel=desktop`；唯一群 `FEIBING NEO AI数字员工`；固定持续授权。
- Asia/Shanghai 昨日业务日期。
- 两个平台、两份固定成品名称、固定原始文件和收据路径结构。
- 工作区内固定 Python、pipeline、浏览器执行器和桌面发送器路径。
- 禁止 `metrics`、自定义 sender、企业微信字段、手机字段、任意外部 run/output 路径。
- 隐藏封板核心18项 SHA-256；任一不匹配时在下载和发送前失败关闭。

### 状态机

运行状态只允许：

`created → downloaded → prepared → sent → verified → complete`

每次状态转换前重新读取实际收据、文件大小和 SHA-256，不仅信任状态文件。非法跳级、回退、缺收据、跨 `runId`、跨业务日期或跨通道均拒绝。

状态收据使用原子写入，至少记录：策略版本、运行ID、业务日、当前阶段、允许的下一动作、尝试次数、模型运行时决策数和证据路径。

执行器必须自动生成固定路径 `workflow-summary.json`，由代码根据状态事件计算下载、制表、发送、只读回验和收尾各节点耗时，并汇总重试、恢复、阻断、未知结果及180秒效率超时等踩坑点。复盘数据不得依赖大模型回忆或手工拼接；正常完成和最终失败关闭都要落盘。

### 恢复决策

恢复由代码分类，不由模型决定：

- 下载点击数均为0且无文件：允许同阶段最多2次有界重试。
- 美团已确认、淘宝点击0：只允许同 `runId` 设置 `resumeDownload=true` 继续淘宝。
- 任一平台点击后结果 unknown 且无可验证文件：禁止自动重新下载，状态转为 `blocked-unknown-download`。
- 桌面微信预检失败且本业务交付键没有 attempted：等待5秒后最多重试3次。
- attempted 已存在但未 verified：禁止再次发送，只允许 `verify-only`。
- confirmed/verified：只读回验；不得调用发送动作。
- 180秒只记录效率，不改变业务状态机或重试权限。

### 内部分阶段入口

`business_exam_pipeline.mjs` 保留实现复用，但改为仅接受生产执行器注入的内部调用标志，并在每个阶段再次调用中央策略校验。直接从命令行选择阶段必须返回 `direct-stage-invocation-forbidden`。

即使绕过唯一入口调用内部阶段，只要配置、状态、收据或固定路径不符合中央策略，也不得进入下载或发送动作。

浏览器下载包装器、桌面微信发送包装器、手机微信发送包装器、企业微信发送包装器及企业微信底层控制器同样校验内部调用标志。它们可被测试导入，但不能作为独立生产动作入口直接执行。

## 验收标准

1. 生产入口不接受任何业务参数覆盖，只能自动生成固定配置。
2. 直接调用分阶段入口被代码拒绝。
3. 状态机拒绝跳过下载、跳过制表、发送后不复核和阶段回退。
4. 固定群名、授权、通道、Profile、端口、昨日日期、两份文件名和所有路径都有正反测试。
5. 冻结核心18项哈希运行时校验通过；模拟一项漂移必须在外部动作前失败。
6. 自动恢复测试覆盖零点击下载、单平台已完成、桌面微信无 attempted、attempted unknown 和 confirmed 五类情况。
7. 现有浏览器、制表、桌面微信、企业微信和手机微信回归测试继续通过；生产入口仅选择桌面微信。
8. 无副作用 `--self-test` 输出策略版本、测试数和 `runtimeModelDecisions=0`。
9. 本轮仅进行无副作用代码验收，不再次发送已经 confirmed 的昨日文件。
10. 状态中始终包含代码计算的 `nextAction`；完成或阻断时为 `null`。执行器生成 `workflow-summary.json`，逐节点耗时和踩坑点有确定性测试。

## 实施验收结果

- 语法检查：策略、生产执行器、内部管线、浏览器下载器共4项通过，合计约0.09秒。
- 新增策略测试：32项通过，约0.05秒。
- 新增执行器测试：24项通过，约1.05秒；覆盖唯一入口、防直调、状态机、重试边界、`nextAction`、逐节点耗时、踩坑点和180秒效率标记。
- 金鲨动态定位及浏览器通道回归：通过，其中浏览器通道37项，合计约0.18秒。
- 旧通道策略回归：8项通过，约0.02秒；该模块仍可供历史代码测试，但生产配置会拒绝 `auto|wecom|mobile`。
- Python 发送与企业微信历史适配器回归：15项通过，约0.31秒。
- 无副作用生产自检：冻结核心18项哈希通过，`runtimeModelDecisions=0`，约0.03秒。
- 踩坑：当前终端没有系统 `node`，旧 Playwright Node 绝对路径也已失效；说明文档已改为当前工作区受管 Node 路径。一次测试使用了旧文件名、一次 Python 测试从错误目录启动，均修正为按真实文件清单并从脚本目录运行；产品代码测试无失败。
