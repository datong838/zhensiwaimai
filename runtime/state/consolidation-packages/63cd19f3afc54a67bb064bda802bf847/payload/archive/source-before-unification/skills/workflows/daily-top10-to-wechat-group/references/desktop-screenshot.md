# 桌面截图规程（淘宝闪购 Top10）

> 来源：`temp_skill`（taobao-shanguan-top10-to-wechat v0.2.0）步骤 1–3，业务层固化。
> 2026-09-01 真机验证后大修：吸收全程踩坑（见文末「真机验证踩坑实录」）。

## 0. 执行纪律（关键检查点，而非逐动作反复取证）

当前唯一桌面适配为 `desktop_background_executor.mjs` + `control-background-dedicated-chrome`。它只连接 `taobao-brand` 的 localhost CDP，在唯一 task-id 标签内从品牌商首页开始，以 DOM 后置条件完成导航、昨日、排序、十行和截图。固定无头 viewport 为 2200×1800、device scale 为 2；直接截设备像素，不做 resize。不激活窗口、不全屏、不用 AX、系统键鼠或系统截图。下方历史实录中的前台窗口、菜单和坐标只供故障复盘，不是当前自动执行分支。

0. **先准备、后执行**：进入本规程前必须已完整读完主 Skill、[执行效率与压力测试规程](execution-efficiency.md) 和后台浏览器控制 Skill。第一个页面动作必须在唯一 task-id 标签打开品牌商首页；整个截图段保持同一 CDP 与同一任务标签，禁止边操作边补读文档。
1. **检查点节拍**：只在以下状态变化后截图复核：到达门店数据页、切到昨日、确认排序、十行入屏、生成最终裁剪图。普通滚动或同一状态内的单次微调不需要反复截图；已有充分证据时禁止重复点击排序或重复核验。
   **自动执行检查**：使用本机 OCR、当前 AX 数据和视觉指纹完成确定性核验，正常执行中不请求模型识图。模型只在计时外审查成品与失败证据。
2. **流程节点不可自作主张增删**：流程只定义「昨日视图 → 营业额降序 → 一屏截图」。下载导出、多屏采集、切其他时间口径、点「更多经营数据」等都是**流程外动作**，一律禁止。发现自己在做流程没写的事 → 立即停。
3. **在任务标签内操作**：先打开固定品牌商首页，再用唯一可见「门店分析」站内链接到达目标视图。禁止直接打开分析页、读取 Chrome History 或借用日常 Chrome 标签。
4. **数据真实性**：只用当前实时截图判断页面状态。历史截图只能作参考，不能作为「当前长这样」的依据——看错图就是误导。

## 1. 定位到目标数据视图

1. `control-background-dedicated-chrome` 只读核验 `taobao-brand`、headless 模式、PID 和 9230 端口，再连接 CDP。
2. 创建唯一 task-id 标签并固定 2200×1800 viewport；打开品牌商首页，登录页标志为 0 且商家结构至少命中 3 项才继续。
3. 若唯一可见弹窗完整匹配“绑定手机号提醒”，单击一次“跳过”并验证消失；该提醒不是登录失效。其他弹窗停止。
4. 在所有 frame 中等待唯一可见「门店分析」站内链接。链接缺失最多只读等待 10 秒；不唯一或仍缺失直接结束。
5. 验证父页面 URL 已包含 `/store-analysis` 且唯一 `storeAnalysisDetail` frame 就绪；点击时间维度 **昨日**，同时看到 checked class 与 `已选时间：MM-DD` 才记录导航结束时间。
   **导航锁止**：URL、门店数据和「昨日」三项通过后立即停止导航，禁止再触碰左侧菜单、处理菜单焦点或探索其他入口；下一动作只能是营业额排序校验。
5. 再进入标签 **门店数据**，读取首屏营业额前 10 个数值。如果已经严格非增序（允许相等），记录数列后直接通过；**只有不满足降序时**才点击「营业额」列头，再验证一次。不得为了“保险”重复点击已经正确的排序。

验证点：
- 顶部指标概览有数字（预计收入/营业额/有效订单/曝光人数/进店转化率/下单转化率），且是「比上周一」口径（昨日=周一时）。
- 表格列序：门店名称 / 店铺分分值 / 商圈收入排名 / 营业额 / 支出 / 有效订单量 / 曝光人数 / 诊断 / 操作。
- 分页器「每页 10 条」第 1 页（共 175 页正常，不翻页）。
- **排序判读陷阱**：顶部指标卡的「营业额」是全连锁合计（如 754,521.80），与单店榜无关；单店 Top1 通常远小于它。判降序只看表格内营业额列自身递减。
- **登录态与结算态分开判断**：出现「登录已经超时」才按登录失效处理；凌晨等尚未形成昨日结算数据的时段，若「昨日」已选中但指标为 `--`、表格为「暂无数据」，记录为“导航通过、数据未就绪”，停止截图流程，不要求用户重登录，也不循环刷新等待。

## 2. 后台布局与截图区域

当前执行器固定 2200×1800 viewport，不执行全屏、缩放、滚动或系统分辨率修改。表格必须由 DOM 返回恰好 10 个非空业务行，分页器必须是第 1 页、`10 条/页`。

截图上边界取表格容器，下边界取分页器，左右边界限制在当前无头 viewport；宽度不足 1500 px 立即失败。截图范围来自当次 DOM 几何，不缓存历史坐标。

以下前台布局手段全部属于历史路径，当前执行器禁止调用：

| 顺序 | 手段 | 本次实测 |
|---|---|---|
| 1 | 浏览器全屏 macOS `Cmd+Ctrl+F` | 有效但收益小（本机菜单栏占位后仅 731pt 高）；**发键前必须确认 Chrome 是前台**，否则全屏的是抢焦点的 WorkBuddy |
| 2 | 页面缩放 `Cmd+-`（自适应） | 以“表头+10行完整且在成品 100% 显示时可读”为准；不追求把更多页面元素塞入一屏，更不能把 50% 当固定目标 |
| 3 | 微调滚动 | 缩放后轻滚 1-2 格让第 10 行完整入镜 |
| 4 | 折叠左侧导航栏 | 未用 |
| 5 | 调系统分辨率 | 破坏性，未用 |

**历史坐标换算（仅复盘，不用于当前执行器）**：
- 普通窗口态（含 112px 影边截图）：`屏幕x = (原图x - 112)/2 + 窗口X`，`屏幕y = (原图y - 112)/2 + 窗口Y`。
- 全屏态（bounds Y=117，截图无影边）：`屏幕x = 原图x/2`，`屏幕y = 原图y/2 + 29`（29=菜单栏偏移）。
- 每次窗口 bounds 变化（全屏进出）后必须重新枚举窗口再截图，公式随窗口态切换。

## 3. 清理界面干扰（直接决定会不会泄露顾客信息）

**清理对象只限「将落入截图范围」的遮挡**：裁剪区外的悬浮按钮/角标与本次截图无关，不花时间折腾。

必须处理（当且仅当落入截图范围）：
- 右侧客服消息弹窗（带头像/用户名/手机尾号/顾客留言）会动态轮换，元素 ID 可能在点击前失效。只允许基于最新画面尝试关闭一次；若仍轮换，直接把最终裁剪范围收缩到表格，不追逐弹窗。
- 顾客反馈浮窗、页面 toast、浏览器下载条与书签栏。

验证点：**裁剪后的成品图**内只剩表格与表头，不含任何顾客姓名、手机号片段、催单/投诉内容。整窗截图里右下角有无关悬浮物不算失败——裁剪会去掉。

## 4. 一屏容纳 10 条并截图

### 4.1 截图前先看页面

截图前必须基于最新画面做一次目视确认，不能只凭上一步命令成功或旧截图继续：

- 表头完整；前 10 行均已加载，第 10 行没有被截断。
- 营业额列当前确为降序；若已经降序，不再点击排序。
- 表格文字在当前画面上清晰，门店名、商圈排名、营业额、有效订单量可直接辨认。
- 将要裁剪的区域没有客服消息、toast、浮层或其他顾客信息。

### 4.2 成品内容边界

成品截图**只保留表格列头 + 前 10 行表格数据**。应排除：

- 页面标题、日期与筛选区、指标卡；
- 下载按钮、筛选控件和无关导航；
- 右侧悬浮按钮、客服消息；

底部分页器保留，作为第一页、每页十条与末行完整的证据。
- 浏览器地址栏、侧栏和桌面背景。

表格有横向宽度时，以保留业务列为先，不要为了纳入无关页面元素而缩小整张表。

### 4.3 原始像素与清晰度硬门

1. 先截取窗口或屏幕的**原始分辨率 PNG**，再按源图像素坐标裁剪表格区域。
2. 裁剪只改变边界，**不得对成品做 resize、thumbnail、JPEG 转码或二次压缩**；不得混用 Retina 逻辑点与图片像素造成二次缩小。
3. 成品宽度必须 **≥ 1500 px**。macOS 可用 `sips -g pixelWidth -g pixelHeight <图片>` 检查尺寸。
4. 用 100% 显示打开成品复核：门店名、商圈排名、营业额、有效订单量无需放大即可读；仅仅“能看出有 10 行”不算通过。
5. 若宽度不足或文字发虚，必须回到页面重新调整窗口/缩放并重截，禁止把低清图交给手机端“原图”发送——手机勾选原图无法恢复已丢失的像素。

参考基线：清晰样例为 **1560×1184**；此前 **600×500** 成品属于失败样例，即使行数正确也不得发送。

保存到临时目录，文件名 `<数据日期>_top10seller.png`（数据日期 = 执行日期 − 1 天，执行时用系统时间现算，不照抄示例）。**记录完整绝对路径**供手机发送段使用。

## 5. 失败处理

| 现象 | 处理 |
|---|---|
| 页面「发生了些错误」 | 点「点我刷新」重试一次；仍失败 → 登录态失效，停下报用户 |
| 跳登录页 | 连的是新窗口；停下让用户登录后重跑 |
| 营业额列点不动 | 改用表头下拉排序选项，或停下报用户 |
| 截图后发现含顾客信息 | **丢弃重截**，不允许发出去再补救 |
| 截图只有 600×500 或 100% 看不清字段 | 视为成品失败；回到原始窗口截图，仅按源像素裁剪，禁止 resize |
| 全屏快捷键无反应 | 先查前台是谁（八成被 WorkBuddy 抢走）；按 PID 强激活并轮询验证前台后再发键 |
| 缩放快捷键无效 | 检查键码：macOS 虚拟键码 **减号=`0x1B`**，数字 0=`0x1D`；发错等于一直重置缩放 |
| AppleScript 激活报 -10004 | TCC 责任进程是 sandbox-cli；改用 AppKit `NSRunningApplication.activateWithOptions_` + 前台轮询验证 |
| 动态菜单无障碍点击只获焦点 | 不追加 Return、不原地等待；重新展开一次，取最新截图后直接视觉点击「门店分析」文字。2026-09-02 实测到「昨日已选中」为 4.736 秒 |
| 展开「数据中心」后「门店分析」元素失效 | 只允许重新展开一次；立刻用最新子菜单状态点击。不得缓存元素编号、读取巨型整页状态或套用其他窗口尺寸的坐标 |
| 凌晨「昨日」指标为 `--`、表格「暂无数据」 | 若「昨日」选中且无超时提示，则导航通过、数据未结算；停止截图并如实报告，不刷新、不等待、不重登 |

## 6. 真机验证踩坑实录（2026-09-01，全部真实发生）

**流程纪律类**
1. 擅自切「今日实时」——口径是昨日，多管闲事。
2. 反复折腾「更多经营数据」入口——只是 dashboard 跳转链接，与链路无关。
3. 擅自点「下载导出」——流程只要截图；且此误点产生下载 toast 长期残留，成为后续自造干扰源（自己挖坑自己填）。
4. 自创多屏滚动采集合并方案（collect_stores.py）——完全偏离「一屏截图」定义。
5. 从 Chrome History 挖 URL 地址栏导航——应在已打开页面内站内导航（用户明确纠正）。
6. 点分页器当「坐标探针」——流程外自选动作。

**焦点管理类**
7. 发 Cmd+Ctrl+F 时前台是 WorkBuddy → 把 WorkBuddy 全屏了。教训：发任何键前按 PID 激活目标应用并轮询验证前台。
8. `osascript ... 2>/dev/null` 吞掉 TCC 报错 → 误以为激活成功。教训：激活失败必须显式暴露，不静默。
9. 滚动事件发到 WorkBuddy——同 7。

**坐标系与技术类**
10. 键码乌龙：减号写成 `0x1D`（实为数字 0），连发三次全是 Cmd+0 重置缩放，误判「67% 装不下」。教训：macOS 键码减号=0x1B，用前查表。
11. OCR 在缩放图上做、坐标按原图换算——尺度混用，点击全落空。教训：**OCR 永远直接跑窗口原图**，坐标即原图像素。
12. 影边 112px 有时重复扣减、窗口尺寸中途漂移未察觉。教训：每次动作后重新截图重算，不缓存旧坐标。
13. 客服弹窗 × 点击偏 42px 点到消息体 → 消息轮换冒出新顾客信息，越点越多。教训：关 × 用裁剪放大图精确定位，点完立即拍照验证。
14. 排序误判：把顶部指标卡的连锁总营业额（75 万）当单店榜第一，怀疑降序没生效。教训：先弄清数值归属再判断。

**验证方式类**
15. 用脚本返回值代替视觉确认——被用户两次纠正：每个动作后必须立即拍照过目。
16. 动作不连贯：点完不拍照，中间插入写脚本/算公式，基于过期 OCR 状态推进。
17. 把「清理」扩大化到裁剪区外的悬浮物，浪费多轮。

**2026-09-02 导航复测新增**
18. 子菜单展开后读取巨型整页状态，导致动态菜单重绘，旧元素编号失效；正确做法是只读一次最新子菜单并立即点击。
19. 套用用户截图或另一窗口尺寸的坐标，点击落到内容区；正确做法是先全屏固定布局，窗口变化后废弃全部旧坐标。
20. 把“到达昨日视图”和“昨日数据已结算”混为一谈，在凌晨空数据上长时间等待；两者必须分别计时、分别报告。
21. 菜单已经展开却继续准备脚本和反复取证，造成肉眼可见的空等；进入快路径后只允许“展开 → 最新状态 → 点击 → URL验证”四步，30 秒预算内未完成就直接截图诊断。
22. 对动态菜单调用无障碍 `click` 后继续按 Return，实际只改变焦点且延迟十余秒；正确做法是基于最新截图对可见菜单文字做一次视觉点击，再用 URL 与「昨日」选中态验收。

**工具链事实（复用价值）**
- 窗口级截图：`screencapture -x -l <CGWindowID>`，不受前台是谁影响（WorkBuddy 抢焦点时唯一可靠截图通道）。
- 窗口枚举：Quartz `CGWindowListCopyWindowInfo`（venv: `.venvs/harmonyos3-phone-control`，系统 Python 无 Quartz）。
- 合成输入：Quartz CGEvent + `CGEventSourceCreate(kCGEventSourceStateHIDSystemState)` 正式事件源；对 Chrome 原生 UI 和饿了么表格控件均有效（此前「isTrusted 挡网页点击」是误判，真因是坐标错）。
- **拍照识图（看图通道选择）**：模型能看图 → 直接视觉读图（最优）；模型不能看图 → 用技能包自带 `scripts/ocr_vision`（Swift Vision 框架，源码 `scripts/ocr_vision.swift`，可用 `swiftc -O -o ocr_vision ocr_vision.swift` 重新编译）。用法 `ocr_vision <图片路径> [zh-Hans|en-US]`，输出 `中心x,中心y,宽,高<TAB>置信度<TAB>文本`，**坐标=原图像素（左上原点）**。适用条件：当前模型不具备看图能力时的替代通道，模型能看图时优先用视觉。可裁剪放大后再 OCR 提高小元素识别率，但坐标须按裁剪原点反算。
- 强激活：AppKit `NSRunningApplication` 按 PID 激活 + `NSWorkspace.frontmostApplication` 轮询验证，双保险后再发键。
