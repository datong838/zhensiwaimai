# 企业微信共享群优先方案（2026-09-11）

## 目标与优先级

金鲨昨日双平台日报发送通道固定按 `wecom → desktop → mobile` 选择：

1. 企业微信已登录且企业身份、共享空间均唯一确认时，将两份日报上传到「上海臻肆文化传播有限公司」的微盘共享空间「金鲨昨日双平台日报业务群」。该目标是共享空间，不是企业微信聊天群。
2. 企业微信不可用时，保持现有普通桌面微信「FEIBING NEO AI数字员工」通道。
3. 只有配置显式要求手机微信时才使用原手机通道；企业微信或桌面微信出现 unknown 结果后禁止跨通道补发。

企业微信成为默认首选，但普通桌面微信和手机微信的代码、授权边界与恢复能力不删除。

## 执行器沉淀标准

以下规则必须进入执行器代码及自动化测试，只有文档描述不算完成：

- 绑定企业微信进程 `com.tencent.WeWorkMac`、唯一文档窗口、登录态和企业身份双门禁。
- 从“文档 → 微盘 → 共享空间”定位完整空间名，只接受唯一精确结果；打开后再次核验顶部完整空间名及面包屑。
- “消息 → 文档”切换不得使用固定 1 秒等待：点击唯一“文档”入口后，最多 5 秒、每 0.5 秒绑定同一窗口重新截图，直到顶部唯一合并标签同时包含“与我相关/智能文档/智能表格/全部”。未出现时才报告文档页未就绪；不得拿切换前的消息页 OCR 继续定位。
- 截图和动作坐标必须绑定同一个企业微信文档窗口，不读取 macOS 前台窗口，不依赖窗口列表顺序。
- 上传前必须验证两个文件绝对路径、完整名称、大小、SHA-256以及目标空间当前不存在同名文档。企业微信会将 `.xlsx` 转换为不带扩展名的智能表格，因此源文件名与目标文档名必须分开建模。
- attempted 必须在触发上传之前原子建立；上传动作最多一次；上传后连续两帧验证两个完整文件名和稳定列表状态。
- 企业微信、桌面微信、手机微信共用同一业务交付账本；业务键至少包含业务日、平台、完整文件名、目标业务目的。字节哈希仍用于本轮文件完整性，不能因重新生成 XLSX 导致重复发送。
- 已确认交付直接只读回验；无 attempted 的部分历史、同名冲突、目标歧义或发送结果 unknown 一律失败关闭。只有本业务键 attempted 已记录且导入次数为1时，才允许恢复移动未归档的剩余文档。
- 无 attempted 时若上轮安全失败遗留企业微信“打开文件”sheet或“前往文件夹”子弹层，执行器必须在目标空间定位前绑定唯一企业微信主窗口，逐层发送 Escape 并回读 sheet 数归零；已有 attempted 时禁止执行该清理，避免掩盖未知上传结果。
- 正常执行 `runtimeModelDecisions=0`，节点必须输出耗时、是否模型介入、发送尝试数和证据路径。

## 通道选择合同

- 配置未指定发送通道时使用 `auto`，先运行企业微信只读预检。
- `auto` 仅在企业微信明确为“未运行、未登录或企业身份不可用”，且没有 attempted/unknown 时，才允许落到桌面微信。
- 企业微信已经触发文件上传但结果 unknown 时，保持企业微信共享空间只读复核，禁止落到普通微信或手机。
- 显式 `wecom`、`desktop`、`mobile` 只运行指定通道，不自动切换。
- 最终收据记录 `requestedChannel`、`selectedChannel`、选择理由和预检证据。

## 企业微信共享空间定位合同

- 企业名：`上海臻肆文化传播有限公司`。
- 共享空间：`金鲨昨日双平台日报业务群`。
- 必须位于“文档/微盘/共享空间”，同时回读左侧选中空间名、右侧页面标题和面包屑。Vision 会把左侧选中圆点与空间合并为一个文本块，因此执行器要求两处独立精确文本 + 一处包含完整空间名的选中行；三处均必须保留完整空间名。
- 客户端身份弹层会把企业名截断为“上海臻肆文化传播有限…”，所以企业身份必须同时命中该固定可见前缀和当前业务窗口内的目标共享空间三处完整标题；不将截断 OCR 误报为完整企业名精确匹配。
- 共享空间名按去除空白后的完整文本精确匹配，不允许前缀、包含或 OCR 模糊匹配。
- macOS 辅助功能树缺少业务文字时，允许使用绑定窗口截图的 Vision OCR；OCR 坐标仅在同一截图和同一窗口几何未变化时使用。
- 企业微信冷启动或从消息页切换到文档页实测可能超过 1 秒；执行器必须等待结构就绪而不是依赖固定延时，结构一旦唯一命中立即继续。
- 窗口、多企业、共享空间、页面标题、上传入口或文件列表任一不唯一时不上传。

## 文件上传合同

- 上传前先读取目标空间当前文件列表；同一业务日的两个完整文件名都存在时上传0次并只读回验。
- 仅一个文档已存在属于部分历史：无本业务键 attempted 时失败关闭，不覆盖、不重新导入、不切换微信通道；已有且只有一次 attempted 时，只恢复移入缺失的那份已转换文档。
- 两个文档都不存在时，使用顶部唯一“导入”入口中的“导入本地文件”能力，一次选择两份已验证 XLSX；不得依赖“新建”、下载目录、剪贴板残留或最近文件。
- macOS“打开”文件面板可能因系统保护导致绑定窗口截图为纯黑；此处不得依赖 Vision OCR。执行器必须先确认本轮独立 `upload-staging` 目录恰好只有两份目标文件；打开“前往文件夹”后必须先全选覆盖历史路径、输入本轮绝对路径，并等待子 sheet 完全消失；随后通过企业微信主窗口唯一 sheet 的辅助功能结构回读位置为 `upload-staging`、唯一“打开”按钮存在。全选文件后还必须回读该按钮已启用，之后才允许写 attempted 并提交。
- 实测确认“导入本地文件”会先把 XLSX 转换到“与我相关/我的空间”，不会直接落入当前共享空间。执行器必须等待两份显示“导入完成”，再逐份打开转换文档，通过右上角菜单的“移动到...”选择唯一精确共享空间，并回读“已移动文档”。
- 触发导入前建立 attempted；导入动作只允许一次。如运行中断且 attempted 已存在，禁止再次导入，只允许从“与我相关”找回已转换文档、移入目标并进行只读确认。
- 最终必须回到目标共享空间，连续两帧同时回读两个不带 `.xlsx` 的完整文档名与稳定列表状态，再写 confirmed。
- 已有同名文件不得覆盖；若企业微信弹出替换、重名、权限或冲突对话框，结果记为 unknown/blocked 并停止。

## macOS 一次性门禁

- 首次读取“打开文件”面板可能出现“ChatGPT 想访问其他 App 的数据”系统隐私授权。该授权不是业务页面，不得被 OCR 坐标逻辑误点。
- 执行器在 attempted 之前先做系统面板可读性检查；未授权时明确返回 `wecom-macos-open-panel-privacy-gate`，不产生导入尝试。一次人工授权后不再介入正常运行。

## API 与桌面 UI 路由决策

- 当前实施路由是企业微信 macOS 客户端 UI，不是隐藏的本地接口，也不冒充企业微信微盘 API 已配置。
- 微盘 API 状态固定记为 `NEEDS_VERIFICATION`：只有管理员已配置可调用应用与微盘权限、可唯一获得目标 `spaceid/fatherid`，并由受管凭据注入提供访问令牌时，才可单独实现 API 适配器。
- API 凭据、令牌、Cookie 不得写入 Skill、命令行、日志或收据；API 配置未验证时不进行网络探测或降级猜测。

## 去重与授权

- 企业微信固定授权标识：`zhensi-business-wecom-jinsha-daily-v1`。
- 普通微信继续使用原授权 `zhensi-business-main-wechat-feibing-neo-ai-daily-v1`。
- 三个发送通道共享业务交付状态，但保留各自 attempted 证据目录。
- 只有两份成品名称严格为 `美团外卖日报_YYYY-MM-DD.xlsx`、`淘宝闪购日报_YYYY-MM-DD.xlsx`，日期为 Asia/Shanghai 昨日，且构建验证通过时允许发送。

## 实操验收

1. 企业微信已登录时，`auto` 必须选 `wecom`，并证明企业名和共享空间三处标题精确命中。
2. 两份文件只产生一次导入动作；导入完成后逐份移入目标，最终连续两帧回验通过并写 confirmed。
3. 再运行一次必须上传0次并完成只读回验。
4. 企业微信未登录的模拟测试中，`auto` 才允许选择桌面微信；unknown 模拟不得回退。
5. 普通桌面微信、手机微信原测试全部继续通过。
6. 按节点展示耗时、模型介入、通过状态和待优化项；运行时模型介入必须为0。
