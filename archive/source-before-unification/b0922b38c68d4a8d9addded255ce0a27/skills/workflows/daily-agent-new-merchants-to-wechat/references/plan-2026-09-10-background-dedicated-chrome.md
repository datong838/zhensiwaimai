# 服务商平台后台专用 Chrome 迁移方案（2026-09-10）

## 目标

把默认浏览器采集从 `control-existing-chrome` 迁移到 `control-background-dedicated-chrome`。首次登录使用独立可见 Chrome，登录阶段不启用 CDP、不连接 Playwright、不截图；用户关闭登录窗口并明确确认后，使用同一持久 Profile 无头启动，后续只经 localhost CDP 操作任务自有标签，不影响日常 Chrome、键鼠和焦点。

## 固定资源

- Profile：`taobao-agent-service`
- CDP：`127.0.0.1:9231`
- 首页：`https://open.shop.ele.me/manager/base/home`
- 强前缀：`https://open.shop.ele.me/`
- 浏览器控制器：`control-background-dedicated-chrome`
- 品牌商 `taobao-brand:9230` 与本流程完全隔离，禁止交叉连接或复制登录数据。

## 执行器设计

1. `structured_merchant_collector.py` 保留业务日期、游标、增量和收据接口；默认 `collect` 改为调用后台 CDP 执行器。
2. 后台执行器验证 Profile 状态、PID、端口和回环 CDP；创建带唯一 `aos-background-task:<task-id>` 标记的新标签并导航固定首页。
3. 页面恢复只使用 task 自有标签中的 DOM：按唯一完整文本依次识别 `appstore 控制台`、`代运营`、`客户管理`、`意向商户管理`；到达后必须同时满足正确源站、`商家意向列表` 和表格结构。
4. 日期使用 Ant Design 日历完整 `YYYY-MM-DD` 标识选择并回读两个输入框；起始日固定取当前有效游标的推荐日期，结束日取 Asia/Shanghai 今天。查询后要求每条推荐时间均落在闭区间内，列表签名连续两次一致后才允许读取。
5. 表格按表头映射，逐页读取到“下一页”禁用；商家 ID 跨页唯一、推荐时间稳定升序。详情只点击当前唯一行内的 `详情`，并交叉验证商家 ID 与名称。
6. 正常路径运行时模型决策为 0；登录页、CAPTCHA、风险校验、源站偏离、定位不唯一或任务标签丢失均失败关闭，不回退日常 Chrome。
7. 结束仅关闭本轮 task-id 标签，不停止专用后台 Chrome，不触碰其他标签。

## 登录交接

1. `init` 后执行 `login`，只打开独立可见窗口，收据必须为 `automationAttached=false`、`cdpEnabled=false`。
2. 用户人工处理账号、密码、验证码和风控；此时自动化保持零控制。
3. 用户关闭该专用窗口并明确说“登录好了”后，执行 `start` 切换为无头模式并首次 `probe`。
4. 登录失效时回到本交接流程，不自动填充凭据、不复制其他 Chrome 登录数据。

## 验收

- 离线：Profile/端口/URL/任务标记、日期、分页、详情和收据合同测试通过。
- 登录阶段：只有独立可见窗口，无 CDP、Playwright、截图和页面读取。
- 后台阶段：前台应用和日常 Chrome 窗口数不变；目标页结构和登录态通过；`runtimeModelDecisions=0`。
- 全流程：采集、桌面微信发送、历史与游标合同保持不变。

## 2026-09-10 补偿范围与页面结构整改

- 用户核对后确认增量任务必须覆盖“游标推荐日期至今天”的闭区间，而不是只筛今天；这保证跨日未运行时不会漏发。
- 先完整遍历区间内全部分页，再按推荐时间与稳定页面顺序排序，精确定位排他游标；仅发送游标之后且当前状态为“待处理”的记录。
- Ant Design 当前把表头和业务数据行放在两个相邻 table 中。解析器按唯一业务表头识别字段，再读取同一 frame 内带 `ant-table-row` 的业务行；若存在原始业务行而解析为零，立即失败。
- 查询后存在旧列表短暂残留，必须等待列表签名连续两次一致且全部推荐时间落入筛选闭区间。
- 详情弹窗先显示 `-` 占位值，必须等弹窗 ID/名称与目标行完全一致后才允许形成消息。
- 平台分页不保证全局推荐时间有序；必须读完所有页后在本地全局升序。翻回来源页读取详情时必须复核该页完整行签名。
- 同一商家 ID 可能在不同时间被重复推荐；跨页去重和发送身份使用 `(商家ID, 推荐时间)`，仅完全相同的复合身份才视为重复。

第 3 轮前台应用执行前后均为 `com.tencent.workbuddy.mac`；后台执行未创建可见 Chrome 窗口、未激活 Chrome、未发送系统键鼠事件。专用无头进程在任务标签关闭后继续存活。

第 5 轮 runId 为 `d052027b-b362-4688-9690-44cf0042a301`：桌面微信群预检 3.687 秒，后台采集 3.509 秒，审计、桌面 no-op 和最终游标复核均通过；`runtimeModelDecisions=0`、`sent=0`。

## 2026-09-11 日期控件连续运行稳定性补充

同版本整链完成后立即刷新复跑，Ant Design 日期范围控件在第二次运行的结束日期首次回读尚未稳定，旧执行器在 `date_filter` 0.404 秒直接报 `date-readback-mismatch:结束日期`。发送次数为0、游标未变。

日期设置改为每个端点“点击输入框 → 唯一完整日期单元格 → 点击 → 等待该输入框回读目标值”的独立事务，单端最多重设一次；两端完成后还必须连续两帧同时等于 `[游标日期, 今天]` 才能点击查询。查询后原有列表稳定、日期范围和分页校验保持不变。该恢复只在任务自有 CDP 标签内进行，不切换控制通道，不放宽日期合同。

## 2026-09-28 日期单元格短暂重复候选恢复

### 现场证据与判断

- 连续两次唯一生产入口都在 `date_filter` 的 0.367 秒和 0.691 秒失败，原因分别为 `calendar-day-count:2026-09-28:2`；两次均发生在任何采集行、审计或微信动作之前，`sendAttempts=0`、无 attempted/unknown，游标和历史仍指向上一条已验证商家。
- 代码在点击日期输入框后，立即跨所有 frame 统计页面内可见的同日单元格；任意两项便同步硬失败。现场回执不含候选 DOM 证据，故无法断言两个候选来自过渡动画、多个面板或页面重复节点。可安全处理的已知问题是对短暂重复候选没有有界稳定等待。

### 最小修复

1. 日期输入框点击后，仅对精确完整 `YYYY-MM-DD` 的可见、非禁用候选进行有界轮询；只有观察到恰好一个候选才允许点击。候选数量为 0 或大于 1 时不得选择、不按顺序取首项；达到固定预算仍不唯一就以原有 `calendar-day-count:<date>:<count>` 失败关闭。
2. 为轮询选择器提供离线可注入的候选读取与等待函数；回归覆盖 `2→1`、`0→1` 恢复、持续重复候选超时及持续缺失超时，证明只在唯一时点击/返回且不选择第一个歧义候选。
3. 维护入口不得把采集器加入长期通用漂移白名单。仅对本次两个受控文件，用固定的候选 SHA-256 精确允许这一份经测试的采集器及其自测变更；未来任何其他摘要都仍拒绝。随后只使用代码拥有的统一微信依赖维护入口及商户 `maintenance_executor.py` 原子更新摘要与验收态。
4. 完成方案与测试后，只在 `sendAttempts=0`、未创建 attempted/unknown、游标和历史未写入的机器证据仍成立时，之后仅经全新唯一输出目录调用生产 `workflow_executor.py` 一次。

### 边界与未证实项

有界等待只吸收短暂 UI 过渡，不会挑选歧义日期、不改变游标闭区间或日期验证合同。若重复候选持续存在，仍需机器失败并报告；本次现场不能证明 2 个节点的具体 DOM 来源，禁止据此放宽日期匹配或跨 frame 任意点选。

## 2026-09-28 日期候选限定到当前日历弹层

### 新增证据

恢复版总入口完整运行后，日期候选仍在整个有界观测窗口内保持 2 个。故障不是短暂过渡能安全解决的；原定位器还在所有 frame 页面范围内搜 `[title=<date>]`，没有证明命中的节点属于当前打开的日期控件。

### 最小实现

1. 点击日期输入框后，在所有 frame 中枚举可见 Ant Design `.ant-picker-dropdown`。必须有且仅有一个当前可见弹层；没有或多个弹层都继续有界等待，超时分别以机器错误拒绝。
2. 仅在该唯一弹层内查找精确 `YYYY-MM-DD`、非禁用的 `td.ant-picker-cell`。恰好一个才返回点击；同一弹层有多个同日单元格仍等待后失败，不按顺序或屏幕位置挑选。
3. 扩充纯离线回归：两个可见弹层即使其中只有一个候选也绝不返回；唯一弹层内日期单元格 `2→1` 才恢复；唯一弹层内持续重复/缺失继续失败。维护仍限于固定采集器与测试 SHA，不放宽其他运行文件或群/发送合同。

### 失败关闭

候选必须先被证明属于唯一当前日历弹层，再被证明是该弹层内唯一精确日期单元格。任何重复弹层或重复单元格都不得点选；日期双端回读、闭区间、分页、审计和发送合同原样保留。

## 2026-09-28 日期候选限定到当前月份单元格

### 诊断与判断

- 当前唯一弹层限定后，同一 `.ant-picker-dropdown` 内仍有两个精确日期候选；因此不能仅凭弹层唯一就区分相邻月份面板内的重复日期。
- Ant Design 日历会在相邻月份面板绘制前/后月溢出日期。不能用 `title` 单独选取，也不能按节点顺序或坐标猜选。失败回执需要输出每个可见节点的 class 与所属月份面板标签，便于解释持续歧义。

### 最小修复

1. 对精确日期节点要求其同时具有 `ant-picker-cell-in-view` 且不具有 `ant-picker-cell-disabled`。只有唯一当前月份日期才允许点击；0 或多项继续有界轮询，始终不唯一则失败关闭。
2. 失败诊断只记录日期候选的 class 和面板月份标签，不记录商家行或页面正文；诊断不得扩大选择权限。
3. 离线测试覆盖“两个同日节点但仅一个当前月份候选”的唯一资格、两项均为当前月份时持续失败，以及禁用项不具选择资格。生产入口仍须通过日期输入框回读、闭区间、全量分页、选择审计等门禁。
4. 维护摘要仅允许该采集器及其测试文件的固定 SHA 候选；回归通过后经维护入口更新验收态，再使用唯一生产总入口一次。

### 失败关闭

当前月份身份未证明、当前月份候选仍不唯一、或日期输入框回读失败时不查询、不审计、不触达微信、不写游标或历史。此修复不改变日期区间、游标、目标群与消息合同。
