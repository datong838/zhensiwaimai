# 确定性执行器合同

本文件只记录已经实操验证、会改变执行结果的定位与状态机规则。正常执行不得由大模型临场选择页面、坐标、重试方式或发送通道。

本文件没有运行时放行权。唯一入口先由 `runtime_guard.py` 校验 `runtime-policy.json`、固定参数、关键文件 SHA-256 和微信独占门禁；任一检查失败时，代码在业务动作前拒绝继续。实施方案见 [代码强制运行时约束方案](plan-2026-09-11-code-enforced-runtime-guardrails.md)。

## 固定状态机

| 节点 | 唯一定位/输入 | 通过条件 | 失败关闭 | 有限等待 |
|---|---|---|---|---:|
| 运行时策略 | `runtime-policy.json` | 策略字段与 3 个关键文件 SHA-256 全部一致 | `runtime-policy-*`，禁止触碰 Chrome/微信 | 立即 |
| 通道选择 | 代码常量 `desktop` | CLI 与策略均严格等于 desktop | `runtime-policy-wechat-channel-mismatch` | 立即 |
| 微信独占 | OS `flock` + 已知微信操作进程探测 | 取得固定锁且连续 2 次无竞争者 | 持续有界等待，不建 attempted | 每轮 ≤60 秒，无总放弃时限 |
| 桌面微信预检 | 完整群名搜索 | 已登录、精确结果唯一、顶部标题二次精确匹配 | `blocked-login` / 结果非唯一 | 30 秒 |
| 浏览器进程 | `taobao-brand` + `127.0.0.1:9230` | Profile、PID、端口、headless 一致 | 不启动/重启/换 Profile | 立即 |
| 首页 | 固定品牌商首页 | 商家结构标志满足，登录页标志为 0 | 登录/CAPTCHA/URL 偏离 | 10 秒 |
| 门店分析 | 唯一可见 DOM 链接“门店分析” | URL 进入 `store-analysis` | 0/多候选不点击 | 10 秒 |
| 昨日 | 唯一“昨日”控件 | checked class + `已选时间 MM-DD` | 空数据单列 `yesterday-data-not-ready` | 6 秒 |
| Top10 | 固定表格列与分页器 | 10 行、营业额非增序、第 1 页、10 条/页 | 不翻页、不重复排序 | 10 秒 |
| 截图 | 表格 box 到分页器 box | 原始 PNG、宽 ≥1500、OCR 字段与隐私门禁通过 | 不事后放大 | 5 秒 |
| 微信窗口 | 精确主窗名 + `NSScreen.visibleFrame` | 唯一精确名为 `微信` 的聊天主窗；允许已知 `微信 (窗口)` 网页窗和 `图片和视频` 媒体查看窗但绝不控制；取消最小化、AXRaise 后完整落在可用区域内 | 主窗缺失/非唯一/未知大副窗/仍不可见停止 | 2 秒 |
| 图片准备 | PNG 原生剪贴板 + CGEvent 粘贴 | 输入区相对空状态变化 ≥10000 像素 | 未出现预览不得建账本/回车 | 2 秒 |
| 唯一发送 | 业务日期+群哈希账本 | attempted 原子创建后只触发一次回车 | marker 已存在拒绝 | 立即 |
| 发送复验 | 同一群标题 + 连续两帧 | 聊天区变化 ≥10000，输入区预览消失 | unknown 后任何通道禁重发 | 3 秒 |

## 桌面微信群定位合同

1. 只选择唯一精确名为 `微信` 的聊天主 AX 窗口；`微信 (窗口)` 网页窗和 `图片和视频` 媒体查看窗是允许存在的已知伴随窗，但不得选择、截图或操作。其他未知副窗口只允许不超过 `500×400` 的小型临时弹层。只对聊天主窗取消最小化和 AXRaise，截图也必须按精确窗口名命中唯一主窗，并按当前主屏 `visibleFrame` 计算尺寸、四周保留 24 点。严格定位开始时只发送一次 Escape 清理被中断搜索留下的弹层，禁止操作其他未知窗口。
2. 当前顶部标题已经精确匹配完整群名（只允许尾部成员数）时直接复用。
3. 否则点击左上唯一搜索入口；控件 OCR 允许放大镜产生至多两个非中文短前缀（如 `Q 搜索`），但必须位于左上、短文本、以“搜索”结尾且全页唯一。进入搜索态后只截取主窗口屏幕区域，禁止重新激活/AXRaise 主窗导致搜索弹层消失。区域截图中重新定位唯一搜索框并点击聚焦，再全选清空并输入完整群名。
4. 桌面微信搜索结果只接受左侧结果面板内完整群名的唯一候选，与 `群聊`、`最常使用` 等可变分区文案解耦；搜索输入框回显和右侧聊天正文均排除。搜索下拉已展开时直接点击唯一候选，不得先关闭面板。`AI/Al` 只在群名识别环节归一化。手机微信继续执行其独立定位合同。
5. 点击后必须再次在顶部标题精确匹配；历史会话前缀、聊天正文、群内偶然文字均不能充当定位证据。

## 微信发送证据合同

- `before-send.png`：完整目标群标题、空输入区。
- `prepared.png`：同一群标题，输入区出现本轮图片预览；未通过不得创建 attempted。
- `after-send-1.png`、`after-send-2.png`：同一群标题、输入区清空、聊天区新增图片内容，两帧均通过。
- 整窗哈希、按钮消失、光标闪烁、滚动条变化都不是成功证据。
- 收据必须记录 `preparedInputChangedPixels`、`postSendEvidence`、`sendAttempts`、账本路径、各阶段耗时和 `runtimeModelDecisions=0`。
- 普通截图可以激活微信；搜索弹层截图必须使用无激活的主窗口区域截图，截图动作本身不得改变待验证状态。

## 重试与模型边界

- 每个纯前置节点只允许文件中规定的有限轮询；不返回模型选择备用定位。
- attempted 前失败且 `sendAttempts=0`：可在确定性问题修复后完整重跑。
- attempted 后失败或结果未知：停止，禁止自动重发、禁止换手机补发。
- 大模型只用于离线复盘、修改方案和测试，不参与正式执行器正常路径。
- 是否允许进入下一节点只由执行器返回值决定；Markdown、调度提示或模型判断都不能覆盖 `runtime-policy-*`、防重账本或发送后 unknown。
