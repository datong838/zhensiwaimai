## 1. 改动一：第三类出口（自动化 void）
**位置**：`workflow_bridge.py` `execute()` L487-500 四出口判定区。
**现状**：既有 marker 走 `check_old` ⇒ binding-mismatch 即 Rejected；只有 `bridgeVersion==1 ∧ blocked ∧ sendAttempts==0` 可安全 resume。死锁形态（attempted/blocked 绑旧 sha）无自动出口。

**设计**：在 `check_old` 抛 binding-mismatch 前（或 capture 后），新增自动 void 判定：
```
auto_void_candidate =
    prior.get('sendAttempts') == 0                    # 从未真正发出（零重复风险）
    and prior.get('state') in ('blocked','attempted')
    and 连续 FAIL 次数 >= 3（marker 或 run_history 侧计数）
    and evidenceNeverSent 实证三条件全真：
        ① current_chat 确认前台非目标群（或驱动返回会话列表不含目标群尾锚点）
        ② 回读窗口无本次载荷锚点（sha256 文本尾锚/文件名+大小）
        ③ 双群排除（目标群+测试群均无）
```
满足 ⇒ **自动执行双层 void**（层1 marker+.bridge.lock → `.voided-<ts>/`；层2 events 冻结 payload 目录）+ 写 `void-receipt-<ts>.json`（evidenceNeverSent 字段+三条件原始证据）+ 继续走正常发送 + 上报（monitoring 事件流）。

**判据红线**：void 判据必须机器采集，不接受人工口头断言；`sendAttempts>=1` 一律不自动 void（只能走 A2b `conclude_attempt_deadlock.py --apply` 受控通道）。

## 2. 改动二：legacy_text_reconcile 第四分支（口缸米线形态）
**位置**：`workflow_bridge.py` L419-443 `legacy_text_reconcile()`。
**现状**：三分支=① post_send_verify+unknown+attempts1 ② verified+attempts1 ③ wrapped_unknown（completed+commonReceipt.unknown）；第四形态（`stage=null` 中断态 + `state=unknown` + `sendAttempts=1`）落 `legacy-attempt-reconcile-only` 死锁（口缸米线实证）。

**设计**：`null_attempt_unknown` 判定旁新增 `interrupted_stage_null`：
```
interrupted_stage_null =
    prior.get('stage') is None
    and prior.get('state') == 'unknown'
    and prior.get('sendAttempts') == 1
    and common.get('status') == 'unknown' and common.get('channel') == 'desktop'
    and common_items[0].get('sha256') == requested_item.get('sha256')

```
满足 ⇒ 允许进入 reconcile 收口（复用现有 `_copy_exact_bubble` 证明路径：气泡在=verified 结论化；不在=保持 unknown 等下一轮）。
