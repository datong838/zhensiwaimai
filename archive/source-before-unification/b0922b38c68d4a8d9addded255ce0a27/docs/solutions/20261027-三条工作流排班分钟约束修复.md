# 三条工作流排班分钟约束修复

## 产品要求与范围

依据现行《工作流-落群对照表》及《看护职责交接手册-监理与车间主任》，基础诊断每日11:18、新店装修每日11:30、新店未养活每日11:40开始到点调度。未到该分钟不得自动触发；到点后由原车间主任串行执行，实际启动时间仍受前序工作影响，不承诺秒级启动。既有当天成功和消息防重保持原样，修复不授权重跑已执行事项。

本次只修改源码配置和离线测试，不部署、不运行业务、不改现役状态/账本/历史结果，不处理其它工作流或其它维护分支的文件。

## 只读证据与原因

2026-10-27核对源码与现役 `runtime/skills_manifest.json` SHA256均为 `9400faae4ffc214db330b5d31ccc33ebbee124d026069f2a6c15be811e1acecc`。装修与未养活只有earliest_hour=11，缺少earliest_minute，故11:00即符合门禁；基础诊断已设earliest_minute=18，但三项均无schedule_times。

`runtime/run_all.py::_cadence_gate` 按earliest_hour/minute约束最早时点；只有显式schedule_times才调用fixed_schedule.gate并参与daemon的next_boundary精确唤醒。只有班表中文文字不会参与计算，常规30分钟周期可能延后11:18/11:40任务。

## 最小技术方案

1. 三项分别补显式schedule_times=[11:18]/[11:30]/[11:40]；装修补earliest_minute=30，未养活补40，诊断保留18。
2. 保留order、cadence、latest_hour、重试、步骤、授权、发送路径全部原样。复用现有fixed_schedule，不改调度核心。
3. 新增 `runtime/test_midday_schedule_minutes.py`，隔离业务事实/状态读取，纯计算验证每个预定分钟之前不可触发、到点可触发、当天成功防重、到点前成功不能覆盖该档、昨日成功不覆盖今日、18点后不补跑、精确唤醒顺序。运行原fixed_schedule回归保护既有排班。

## 验收与风险

配置与门禁离线通过只证明调度条件正确，不等于生产已加载或业务交付。验收后由主监理按原安全重载流程加载；已有在途流程可能使实际开始晚于约定时点，不得为赶点并发抢占岗位。未改变原18点截止边界。不得通过本补丁重跑2026-10-26任何已交付任务。
