# 工作流与状态合同

## 产品方案

把“金鲨导出、客户字段补齐、模板化日报、微信交付”固化为三个低自由度执行器。模型只参与首次页面建模、模板结构理解和异常判断；稳定步骤由执行器内部轮询、验证并返回单一 JSON 收据。

## 下载合同

唯一控制通道为 CUA 的金鲨桌面 App 窗口。2026-09-03用户明确纠正：本业务使用桌面 App，不操作 Chrome 同域名网页。当前实测 App 为 `/Users/ddt/Downloads/金鲨数据 2/金鲨数据.app`，主进程 `jinsha`，窗口「臻肆外卖运营」；每次恢复先核对运行实例，不缓存 AppTranslocation 临时路径。内部 HTML 的 URL 只用于页面检查，不能作为切换宿主的依据。

下载主链路：`前台固定 → 美团/多店数据/按日/昨日 → 默认方案与指标复核 → 下载一次 → 原生存储面板按合同命名并存储 → 文件稳定与结构校验 → 淘宝/多店数据/按日/昨日 → 默认指标复核 → 单均到手与单均实付复核 → 下载一次 → 原生存储面板按合同命名并存储 → 文件稳定与结构校验 → 收据`。

每个平台下载前保存目录基线，只接受动作后唯一新增的 Excel。存储面板必须精确写入 `金鲨美团_<日期>至<日期>.xlsx` 或 `金鲨淘宝闪购_<日期>至<日期>.xlsx` 并单击一次「存储」。每次下载最多一次，等待采用短轮询；页面失焦时恢复同一宿主并使旧元素编号失效。

下载收据：`/tmp/zhensi_jinsha_reports/download_receipt.json`。

## 制表合同

制表前导入并审计客户表、两个模板、两个成品参考和实际下载文件。ID 列作为文本处理，仅纯数字 ID 参与映射；客户表 ID 列里的空值及「待合作」等状态文字忽略并计数。同一数字 ID 重复时遵循用户指定的 VLOOKUP 语义，采用客户表从上到下首条匹配；后续一致项、信息不完整项及冲突项分别计入审计，不能悄悄覆盖首条。下载行没有匹配客户时保留业务行，并把两列写为 `（未匹配）`，同时在收据列出店铺ID，不能静默丢行。

列序、列名、冻结、筛选、宽高、字体、填充、边框、数字格式与公式模式以模板和成品参考为准。模板首条正常业务行作为基础行格式，覆盖所有新业务行，禁止把模板旧数据对应的静态高亮带入新数据。两平台均按「营收」数值稳定降序，相同值保持原下载顺序；导出前验证全列单调不升。额外硬门：店铺评分 `<4.3` 红字；营收 `0–300` 黄底；客户等级 `A/S` 红字。美团的数据条列为 H/I/M/N/O/P/V（月售销量、营收、曝光人数、进店率、下单率、有效订单、30天复购率【老客】）；淘宝闪购的数据条列为有效订单、营收、曝光人数、进店率、下单率、近30天复购率。模板示例日期不得进入本次数据。所有工作表至少渲染一次；检查 `#REF!`、`#DIV/0!`、`#VALUE!`、`#NAME?`、`#N/A`。

制表收据：`/tmp/zhensi_jinsha_reports/build_receipt.json`，记录源文件与成品的路径、业务日期、行数、匹配/未匹配数、大小和 SHA-256。

## 已验证的快速路径与恢复边界

- 准备阶段完成三个执行器及引用规程阅读、运行时确认、参考图/模板字段校准；执行时不再查入口、不换控制方式。
- 原始下载、成品制作、手机传输三阶段分别持有收据；恢复时读取现有收据并核对实际文件 SHA-256，不因手机阶段失败重做下载/制表。
- 系统选文件使用完整文件名 UI 节点；侧栏快捷入口限定`roots_list`下的`android:id/title` + `下载内容`，等侧栏消失、`下载内容上的文件`出现，再进入唯一`zhensi_reports`目录。标题栏、搜索框或后台同名节点不可代替当前目录身份。
- 微信面板动画期间坐标全部无效；缺 UI 树时用两帧 OCR 验证「文件」位于「音乐」左边且位置稳定。
- 选中页校验 1 个文件、平台前缀、大小；已选文件来自精确 UI 树名称且推送哈希一致，不能仅凭截断文字建立身份。
- 发送后核对群标题、完整文件名（允许换行）和大小；OCR 的 `.xIsx` 只在扩展名处归一化为 `.xlsx`。任何其他日期、群名、平台差异仍拒绝。
- 本轮实测美团 118.3 KB、淘宝 117.9 KB；这些是历史证据，后续大小必须按当次成品实时计算，不能硬编码。
- 历史验证为两文件各一次点击、确认后落账，恢复可跳过已完成文件。当前用户授权本流程测试和有证据的未发送补点，不授权任意重复发送。
- 发送校验独立于制表视觉校验：手机预览不支持条件格式不等于原始文件没有格式。
- `test_wechat_file_sender.py` 覆盖 8 项发送安全/匹配测试；`test_saved_reports.mjs` 覆盖 6 项保存后验证。后者只读，不生成新 Excel。

运行时：Node 与依赖以 `load_workspace_dependencies` 返回值为准；在临时工作目录把 Node 执行器和测试复制到一起，并把 node_modules 连接到所给依赖目录，不修改依赖包。手机脚本用 `/Users/ddt/work/projects/ai_agent/.venvs/harmonyos3-phone-control/bin/python`。
