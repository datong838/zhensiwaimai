# 下载内容快捷入口修复与整轮验收方案

## 范围和顺序

按用户确认固定采用「手机文件 → 选取 → 下载内容 → zhensi_reports → 本轮完整文件名」。不再进入HLK-AL00根目录找Download，不把普通搜索框当路径框。维护后先完成第10轮原批次，再从头执行第11轮，分别记录，不拼接计时。

仅修改`../scripts/wechat_file_sender.py`的系统选择器目录导航与对应单测；同步`workflow-contract.md`和`../SKILL.md`。不修改制表、下载、业务数据、模板、微信群或设备权限。保留旧收据、发送账本和每文件哈希校验。

## 实现设计

1. 运行时先验证系统选择器包名。当前已是报告目录时直接定位精确文件；当前目录下有唯一zhensi_reports目录条目时直接进入，不回顶。
2. 否则打开系统选择器侧栏，在`roots_list`中按精确「下载内容」选择根入口；等待侧栏消失、下载内容页面可证实，再点唯一报告目录条目。入口缺失/重名/加载失败时停止该动作并留检查点，不回退根目录遍历。
3. 目录点击只等待目标目录证据，不执行滚回顶部。报告目录中的完整文件名仍使用已有精确名称选择和稳定列表校验；文件内容身份仍由推送哈希与待发送名称/大小校验保障。
4. 增加导航证据：起始目录识别、使用快捷入口与否。不得只凭文本出现在搜索框或后台树就认定目录。

## 测试与验收

维护实操补充（2026-09-05）：第10轮续跑已确认美团；淘宝精确文件条目bounds为top72/bottom89，处于顶部遮挡区域。进一步最小修复文件行点击门：完整文本匹配并不足够，必须在内容区完整可见且位置稳定；被顶栏遮挡时只调整当前报告目录列表位置，不回根目录。增加遮挡行拒点及恢复可见测试，未发出的淘宝仍消费原哈希。

- 单测：当前报告目录不导航；唯一可见报告文件夹直接进入且不滚动；其他目录从下载内容快捷入口进入；快捷入口缺失/重名拒绝；点击后未出现目标目录拒绝；旧发送安全测试全部保留。
- 真机先只读核对侧栏「下载内容」的控件与报告目录；随后第10轮按原始哈希断点续送，各文件只确认一次。
- 第11轮业务日期按开跑时Asia/Shanghai昨日重新计算，使用最新源数据和独立文件名。从已登录金鲨下载页与已核验手机状态开始，自动下载→制表→发送→群内双气泡复验。180秒为效率目标，超时同轮继续，不重做已完成环节。
- 输出首次失败、恢复、第11轮每节点耗时及模型是否介入；校验成品、格式、客户表关联、源文件/模板未被修改。不以单次通过宣称多日稳定。
