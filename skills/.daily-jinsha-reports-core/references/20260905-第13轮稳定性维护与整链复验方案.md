# 第13轮稳定性维护与整链复验方案

## 目标

针对第12轮实操暴露的四个真实故障做最小维护，然后使用新的 `runId`、独立收据目录和新的成品文件名，从金鲨美团下载开始完整执行一轮。不得复用第12轮下载、制表或发送完成状态。

## 保持不变

- 业务日期仍按 Asia/Shanghai 的昨日计算。
- 美团与淘宝下载方案、淘宝36项指标、客户表关联、模板、排序及条件格式合同不变。
- 手机仍为已绑定的荣耀 `HLK-AL00`，只使用普通微信，只发送到「臻肆测试群」。
- 每个平台最多下载一次；每个新文件最多发送一次。结果未知只读复验，不重发。
- 180秒只衡量效率，超过后继续完成业务并登记实际耗时。

## 最小修改范围

### P0：普通微信双开选择器自动恢复

- 修改 `scripts/wechat_file_sender.py`。
- 在启动或恢复微信时识别 Activity 名含 `HwChooserActivity` 的系统选择页。
- 只允许通过无障碍属性精确选择 `description=微信` 的普通微信；`微信分身`、条目不唯一、控件树不可见均拒绝。
- 点击后复核前台包为 `com.tencent.mm`，并通过主微信进程属主校验；不使用固定坐标。
- 节点记为固定执行器介入，`llmIntervention=false`。

### P0：金鲨协作租约

- 修改 `scripts/jinsha_cua_exam.js`，增加基于独占文件的本执行器跨进程租约。
- 租约绑定 `runId`、进程和签发时间；正常与异常出口都释放。
- 已存在且未过期的其他运行租约直接拒绝，不进入业务点击；过期租约可审计替换。
- 收据记录获取与释放时间。该租约只能约束遵守同一合同的执行器，不能阻止完全绕过合同的人工或旧脚本，因此仍保留窗口身份逐节点校验。

### P1：系统文件选择器只等待目标行稳定

- 修改 `scripts/wechat_file_sender.py`。
- 进入 `Download/zhensi_reports` 后，优先检查收据中的精确文件名是否唯一、可见且连续两帧位置稳定。
- 不再等待目录内所有历史 Excel 行同时稳定；目标被顶栏遮挡时只滚动当前列表并重新取证。

### P1：发送后上传态确定性轮询

- 修改 `scripts/wechat_file_sender.py`。
- 发送点击后，持续识别目标群、完整文件名、文件大小及上传中/发送中状态，最长50秒。
- 上传中只等待；完整气泡连续两帧后确认。超时保持 `in-flight`，进入只读复验，绝不重新打开文件选择器。

## 测试与实操顺序

1. 为上述四项增加离线测试，不执行外部动作。
2. 运行现有桌面、下载回执、手机、断点和报表回归测试。
3. 只读检查金鲨登录页面、唯一窗口、手机物理身份、连接状态、普通微信前台可恢复性。
4. 建立第13轮独立目录、配置、下载回执、构建回执、发送回执和发送账本绑定。
5. 从美团开始执行：美团下载一次 → 淘宝下载一次 → 明确释放金鲨 → 两份制表 → 保存后复核 → 两份发送 → 最终只读复核。
6. 输出每个节点耗时、重试、模型是否介入、下载/发送次数和总耗时。

## 合格判据

- 两个平台的新原始文件均绑定第13轮 `runId`、业务日期、时间、大小与哈希。
- 淘宝36项指标成立，两份报表通过保存值、结构、公式、条件格式和视觉检查。
- 金鲨租约获取及释放均有收据；释放后不再调用金鲨。
- 两个新文件在普通微信「臻肆测试群」各发送一次且状态为 `confirmed`，最终复核新增发送0。
- 四个已知故障均由固定执行器处理，整轮 `llmIntervention=false` 才能判为本轮稳定性合格。
- 超过180秒只标记效率不合格，不影响业务完成判定。

## 停止边界

- 登录失效、设备身份变化、目标群不唯一、普通微信身份无法证明、文件或业务合同不符时停止对应外部动作。
- 同一节点连续两次出现未建模错误时保留检查点，先维护再从当前节点续跑；已完成的下载和已确认发送不得重做。
