# 金鲨下载后释放与第12轮验证方案

## 目标

把金鲨桌面 App 限定为“原始文件下载资源”。两平台文件完成存储后，下载执行器立即停止访问金鲨，并在下载回执中写明释放时间；制表、保存校验、手机传输和微信群复验仅消费本地文件，不再持有或恢复金鲨窗口。

同时修复新一轮可能读取旧 `download-ui.json` 的问题，并让保存后数据不一致错误报告首个差异位置、预期值和实际值，避免只有 `saved-values-mismatch` 而无法定位。

## 修改范围

- `scripts/jinsha_cua_exam.js`
  - 下载结果绑定 `runId`。
  - 每个平台记录点击下载前的 `downloadStartedAt` 和存储完成后的 `savedAt`，允许从未完成平台续跑而不重下已完成文件，并避免把文件写盘与保存面板关闭的时间差误判为旧文件。
  - 完成时记录最终回执签发时间，旧轮回执不能冒充新恢复回执。
  - 两个平台存储完成后写入 `jinshaReleasedAt`、`jinshaResourceReleased: true`。
  - 标记释放后不得再调用任何金鲨 App API。
- `scripts/exam_pipeline.mjs`
  - `--wait` 仅接受与当前配置 `runId` 一致、时间不早于本轮启动门槛的下载回执；旧回执继续等待，不进入后续阶段。
  - 接受有效下载回执后记录金鲨已释放；后续不得依赖 App。
  - 每个原始文件按所属平台 `downloadStartedAt` 校验新鲜度，不用恢复动作的开始时间或较晚的保存面板关闭时间否定已完成平台。
- `scripts/build_reports.mjs`
  - 保存后比较保持严格全值比较。
  - 失败时增加工作表、单元格、值类型、预期值和实际值摘要；不降低门禁，不吞掉差异。
- `scripts/test_jinsha_cua_exam.mjs`、新增或扩展整链离线测试
  - 验证释放标记存在。
  - 验证释放后 App 调用次数不再增长。
  - 验证旧回执不能启动新一轮。
  - 验证保存差异能精确定位。
- `SKILL.md`、本文件和第12轮实操复盘
  - 同步当前真实验证状态、逐节点耗时和大模型介入情况。

不修改客户匹配规则、模板列序、排序、条件格式、发送目标群和防重发账本。

## 执行顺序

1. 记录修改前文件哈希和测试基线。
2. 完成上述最小修改并运行无副作用单元测试。
3. 对第11轮已经下载的本地文件执行一次诊断性制表，取得首个保存差异；如果属于数值表示等价问题，采用规范化比较并保留类型审计；如果属于真实业务值变化，保持拒绝并停止发送。
4. 建立独立第12轮目录和 `runId`，清除该新轮自己的临时回执，不删除历史收据。
5. 只读检查金鲨登录态和手机身份；本轮业务日期固定为 Asia/Shanghai 昨日。
6. 启动整链等待器，执行美团、淘宝各一次下载。确认文件存在、非空、结构有效后记录金鲨释放，不再操作该 App。
7. 本地制表、保存后全值检查、条件格式及视觉检查。
8. 只有全部门禁通过才把两个成品发送到普通微信「臻肆测试群」，每份一次，并以完整文件名气泡复验。
9. 输出每个节点耗时、执行器/大模型是否介入、业务完成与180秒效率结论。

## 失败与恢复

- 金鲨被其他进程操作：当前页面证据失效时暂停下载节点并重新读取状态；已经完成的平台不重复下载。
- 下载完成：立即释放金鲨，后续任何失败不得重新获取金鲨控制权。
- 旧回执：忽略并继续等待本轮绑定回执，不以旧文件进入制表。
- 保存值差异：输出首个差异和差异总数；真实值不一致时拒绝发送。
- 微信结果未知：先复验气泡和发送账本，不重发已确认哈希。

## 验收标准

- 两个原始文件均与第12轮 `runId`、业务日期、时间和哈希绑定。
- 下载回执明确 `jinshaResourceReleased: true`，且释放后 App API 调用数不增长。
- 本地报表保存后值、公式错误、条件格式、正文样式和视觉检查全部通过。
- 金鲨释放后制表和手机阶段能独立完成。
- 两个成品只发送到「臻肆测试群」且各一次；若数据或文件门禁失败则发送0。
- 收据包含逐节点耗时和 `llmIntervention`，180秒超时只判效率不达标，不伪造业务完成。
