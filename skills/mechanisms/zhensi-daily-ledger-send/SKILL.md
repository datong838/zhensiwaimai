# 当日工作台账核验

先读 `docs/operations/每日0800监理启动与持续值守.md` 和企业微信UI岗位执行约定。台账由原主任依据最新manifest生成到 `work/<YYYY-MM-DD>臻肆工作台账.xlsx`；不以旧日期/旧21流数量覆盖现行24行配置。

## 核验顺序

1. 只读运行 `runtime/ledger_gate.py <当天YYYY-MM-DD>`，核对其真实A/B清单、原收据和日终末档；当日成功或幂等复用须有当日真实证据。B清单逐条定性，不能把一次失败后的未知发送当作未发送。
2. 核对 `runtime/state/last_cycle.json`、原日志与末档事实。all_green不能代替真实交付，未全绿不得通过修改状态伪造收口；具体放行以原受控实现和用户最新口径为准。
3. 检查Excel每行完成列、实际执行时间及简洁客户备注与原证据一致；合并别名不能当作漏跑或重复执行。未确认就诚实记录未确认，不能为了“全部完成”删项或改成是。
4. 由原主任/原发送入口经原队列交付；监理不手动调用发送器、不停守护来跑manual任务、不复活Windows通道。
5. 检查原生企微回执：完整目标群、新文件卡完整文件名及显示大小、空输入框及两次独立观察。源文件SHA不是聊天附件字节回读。缺证据保持unknown，只读对账，不重发。

跨午夜记录先根据原载荷业务日期核对，不直接改sent_today键、游标或旧账本。仅在所有应执行末档及最终台账真实送达核验后完成当天目标。
