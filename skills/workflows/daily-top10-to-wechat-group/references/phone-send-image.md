# 手机微信发图规程（FEIBING NEO AI数字员工）

> 本规程叠加在 `wechat-mobile-control` 之上，只写业务侧编排；打开群、受控发送、图片核验纪律以其 [controlled-send.md](../../../../skills/skills/app-controler/wechat-mobile-control/references/controlled-send.md)（含视频/图片媒体核验节）与 [group-location.md](../../../../skills/skills/app-controler/wechat-mobile-control/references/group-location.md) 为准。底层细节不在此复述。

## 0. 前置检查

进入手机段前必须已完整读完本规程、`wechat-mobile-control` 必需引用和设备校准文件；不得启动微信后再补读。当前能力压力测试已由用户提供站立授权：主微信、唯一目标群「FEIBING NEO AI数字员工」、本 Skill 生成的一张昨日 Top10 原图。满足该范围时不重复申请逐图授权；任一范围变化立即恢复逐次确认。

| 项 | 检查方法 | 不满足时 |
|---|---|---|
| 设备与 ADB 就绪 | `harmonyos3-phone-control` 探测序列号/机型 | 停下报用户 |
| 微信已登录 | 打开微信后是否进入会话列表 | **停下等用户本人登录**，等用户说"好了"再继续；不代扫码 |
| 双开微信 | 任务栈/进程属主复核（u0=主，u128=分身） | 停下让用户指定实例 |
| 桌面截图就绪 | 图片文件存在且通过 4 项自检 | 回到桌面截图段 |

压力测试优先使用 `scripts/phone_executor.py`。默认运行是 dry-run，只检查合同、依赖与唯一物理设备，不启动微信；真实发送必须同时带 `--execute --standing-authorization zhensi-feibing-neo-ai-main-wechat-top10-v1`。脚本收到无效桌面收据、非主微信、非「FEIBING NEO AI数字员工」、图片哈希不一致、目标缩略图不唯一、原图未验证或发送结果未知时均 fail-closed，不自动补点。

## 1. 推图进手机相册

```bash
# 固定运行时（本工作区路径，其他机器须重新发现环境）
PY=/Users/ddt/work/projects/ai_agent/.venvs/harmonyos3-phone-control/bin/python
ADB_SERIAL=<实测序列号>   # 禁止用默认设备；双开机必须绑定物理序列号

adb -s $ADB_SERIAL shell mkdir -p /sdcard/Pictures/zhensi_reports/
adb -s $ADB_SERIAL push <截图绝对路径> /sdcard/Pictures/zhensi_reports/
# 推送后必须触发媒体扫描，否则相册里看不到新图
adb -s $ADB_SERIAL shell am broadcast -a android.intent.action.MEDIA_SCANNER_SCAN_FILE \
  -d file:///sdcard/Pictures/zhensi_reports/<文件名>
```

验证点：`adb shell ls /sdcard/Pictures/zhensi_reports/` 能看到文件；手机相册「最近」可见该图（文件名与桌面一致）。

## 2. 打开微信并定位群

按以下快速路径执行：

0. **主微信快路径**：设备与双开配置在执行前完成预检。一次启动 `com.tencent.mm/.ui.LauncherUI`；出现华为选择器时依据当前文字/描述直接选普通「微信」，随后核验前台包名和主用户进程。正常只允许“启动 → 选主微信 → 核验”三个动作，不在此阶段查询入口、补读文档或重复探测。
1. 微信若恢复到任意单人/其他群会话，立即使用**微信页面左上角返回箭头**回到会话列表；不得阅读、操作或把该会话误当目标。Android 系统 Back 可能直接退出到桌面，不作为首选。
2. 在会话列表使用搜索，输入完整群名「FEIBING NEO AI数字员工」→ 命中后打开 → **核对顶部群名归一化后一致**。
3. 同名/近似群超过一个 → 停下问用户，不逐个试探。

微信 8.0.77 控件树被屏蔽时走截图+OCR 视觉链路（其 SKILL.md 有实测坐标表，随版本漂移需重定位）。若目标群已清晰出现在近期会话列表，可直接打开，但仍必须复核标题。

当前实测 UI 树只含系统导航栏，不能用于微信页面精确定位。首页搜索图标通过当前截图顶部深色图标连通域定位，并以搜索页文字后置验证；禁止硬编码坐标或用加号固定间距推算。搜索结果只接受「群聊」或「最常使用」本地区域内的完整群名唯一候选，以下一个本地分区标题为边界，不强制要求出现「搜索网络结果」；群聊标题允许附带成员数。

## 3. 选择并发送图片

1. 手机端文件名必须带桌面截图哈希前缀，避免覆盖同名日期文件后被系统相册复用旧缩略图；媒体扫描完成后点输入区「+」→「相册」。
2. 相册中按当前四列网格对当前屏幕全部可见行做桌面原图视觉指纹比对，必须唯一领先；不是“最新一张”就一定是。选中后还必须打开「预览(1)」，在大图 OCR 中同时看到门店、营业额和有效订单字段，才允许进入发送。
3. 选中后必须勾选底部 **「原图」**，并视觉确认其显示绿色勾选状态；日报截图默认禁止压缩发送。
4. 最终页同时确认：唯一目标图的选择角标为 `1`、`原图`已勾选、按钮为`发送(1)`。三项缺一不可。
5. 授权应在进入手机相册前完成。最终状态与已批准的群名、文件名、哈希一致时，直接**单次点击**发送；不要停在相册页再次等待同一授权，以免页面超时、误触或用户误以为系统卡住。
6. 禁止用回车兜底；第一次点击未命中也视为一次外部动作，检查后需重新授权才能再点。

## 4. 发送后复验

- 群内出现**图片消息气泡且已加载完成**（非灰色占位）；用桌面原图视觉指纹定位最新匹配气泡。
- 点开大图后使用双证据复验：在大图查看器中心按原图宽高比做有界纵向扫描，最佳裁剪与桌面原图的视觉指纹距离必须 ≤ 6，同时 OCR 在「门店」「营业额」「有效订单」中至少命中 2 项。该规则处理 Vision 偶发漏识别单个表头的情况；不能用 OCR 单点漏字否定已经视觉一致的原图，也不能只凭 OCR 文字通过错图。
- 发送前「预览(1)」仍须同时命中上述 3 项；发送后规则不反向放宽发送前闸门。发送后结果未知或复验失败时只报告，不自动补发。
- 可选配文（默认不发）：`昨日门店营业额 Top10（数据日期 <数据日期>）`——配文属文本消息，须单独走受控发送的文本授权单，不得与图片授权合并。
- 恢复原输入法；按需删除手机相册临时副本：
  `adb -s $ADB_SERIAL shell rm /sdcard/Pictures/zhensi_reports/<文件名>`（删除前征求用户同意）。

## 5. 本规程特有失败处理

| 现象 | 处理 |
|---|---|
| push 后相册看不到图 | 重新广播媒体扫描；仍不行 → 改用文件管理器路径核对，或停下报用户 |
| 相册里同名/相似图多张 | 停下让用户指认，不凭缩略图猜测 |
| OCR 定位不到「+」/「相册」 | 坐标随微信版本漂移，按 wechat-mobile-control 的像素扫描法重定位；仍不行停下 |
| 微信中途被挤下线/安全验证 | 停下请求人工处理，不重试 |
| 微信恢复到上次单人聊天 | 不查看聊天内容；用微信左上返回箭头回会话列表，再搜索完整目标群名 |
| 「原图」未勾选 | 先勾选并截图确认绿色勾；不得直接发送压缩图 |
| 已获授权却停在相册等待 | 若群、文件、哈希未变化，完成三项最终复核后直接发送；授权变化才重新询问 |
