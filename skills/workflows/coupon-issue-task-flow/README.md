# 发优惠券任务流（coupon-issue-task-flow）

> 2026-10-22 01:13 大同拍板从 `daily-store-metrics-rotation-to-wechat`（每日店铺运营指标轮转发微信）拆出的**独立写操作任务流**。
> 动机（大同原话）：「R16 的耗时结构和其他指标完全不同……单独出一个工作流叫发优惠券任务流，不影响其他各项」。

## 是什么

对门店执行**品牌商后台「精准营销 → 人群营销 → 发优惠券」**：7 个人群逐个开发券 → 选有门槛/无门槛、其他默认 → 立即创建。

## 为什么单独拆出来

R16 是全部规则里**唯一带生产副作用**的一条，与 R01–R15（纯只读：截图 + 发文字）在五个维度上本质不同：

| 维度 | 只读指标流（R01–R15） | 本流（R16） |
|---|---|---|
| 副作用 | 无，重跑最多重复截图 | **真实创建营销活动、顾客可领券、直接花店铺资金**；重跑 = 重复花钱 |
| 放行方式 | 参数齐全即可轮转执行 | **人工放行闸**：参数（门槛/金额）未确认前禁止执行；首跑 dry-run 人工过目 |
| 耗时结构 | 单店单页截图，秒级–分钟级 | 7 次表单填写 + 7 次创建 + 创建后验证，分钟级且因人而异 |
| 频率模型 | 20 天轮换、每店每天 1 指标 | 写操作**不能轮换**，频率待 Q-R16b 拍板后单独建模 |
| 失败语义 | 重发即可 | **宁漏发不错发**；attempted 死锁要先取证（消息/活动在不在）再选出口 |

拆开后两条流各自排期、各自放行、各自台账，互不阻塞：只读指标流按 15 项继续推进采集器与灰度；本流等大同确认 Q-R16a–f 后单独启动。
