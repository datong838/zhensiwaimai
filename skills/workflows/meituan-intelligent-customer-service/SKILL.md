# 美团智能客服

用于从美团商家首页进入消费者消息工作台，逐条检查顾客诉求并处理：符合规则的会话真实回复并记录，随后整理当日 Excel 外发。

## 开始前

1. 仅使用隔离专用实例 `meituan-merchant:9233`：每次操作前通过 `127.0.0.1:9233` 复核目标工作台，禁止通过日常 Chrome、共享浏览器或其他端点读取、导航或发送。不得读取或复制 Cookie、存储、密码或日常 Chrome 数据。
2. 已授权回复执行器（2026-10-03）：真实回复只能经 `scripts/reply_unanswered_sessions.mjs` 完成——队列门禁通过后逐会话判定，符合政策才发送，发送后必须回显核验，未回显视为失败如实上报，不重试、不伪造记录。仍禁止点击退款、补偿、改餐、订单或客户地址控件。
3. 判定为确定性保守规则：顾客侧无关/引流/联系方式消息、订单咨询卡片与平台系统通知（含发票任务催促）一律不回；店家真人回复过的会话不回；`[AI客服]`、总部商家客服（小慧）、自动回复均不算店主人工接管；无法确认超 10 分钟不回。回复文案一律使用政策承接型兜底，不承诺退款、金额、时效或结果。
4. 对已验证且已有授权的定时执行链路，按既有步骤完成工作；不得在运行中自行增加分支、替代策略或扩展动作。只有确认的执行器缺陷可以进入维护，且维护不得扩大业务范围。

## 页面链路

按 [UI 树页面链路](references/ui-tree-discovery.md) 进入：

1. 美团商家首页右下角“消费者问题消息” iframe 入口；
2. 新开的 `imworkbench` 客服工作台（商家总客服小美）；
3. “全部顾客消息”→“未回复”；
4. 左侧会话列表的只读滚动与逐条核验；
5. 右侧“快捷回复”→“个人话术”。

不得把 `99+` 视觉徽标当成 DOM 文本定位，也不得按标签顺序猜选页面。

每轮开始时必须通过 `scripts/ensure_unanswered_queue.mjs` 的 `runWithUnansweredQueue(driver, scan)` 入口执行列表读取。该入口按固定顺序选择“全部顾客消息”和“未回复”，并确认两个控件的选中态；“未回复”必须通过筛选容器内唯一的精确文本项定位，已处于活动态时不重复点击。未成功返回 `{ok:true}` 前，扫描回调不会运行。它只验证队列位置，不改变客户筛选或发送规则。

## 分诊与建议

先读取 [诉求与回复政策](references/qualification-and-reply-policy.md)。只有同时满足“餐饮订单相关的明确诉求、超过 10 分钟、无店主人工回复”的会话，才能形成建议候选。

- 先检查店主人工回复；已人工回复的会话立即排除，不再干扰。
- 加微信/加下我/联系方式交换、纯数字、乱码、广告、引流及其他无关内容一律忽略；即使超时未回复，也不承接、不建议、不回复。
- 自动回复、机器人处理中、未读数字、平台任务或“未回复”筛选本身都不是店主未回复的证明。
- 优先以 [个人话术目录](references/personal-reply-catalog.md) 做语义参考；目录状态不构成发送授权。
- 无合适话术时使用政策中定义的承接型兜底，并避免作任何经营决定或结果承诺。

## 输出格式

每轮输出（reply_unanswered_sessions.mjs 回执 JSON）：扫描会话数、逐会话判定（脱敏会话标识、是否回复、判定理由、顾客原话摘要）、已发送（发送时间/文案/回显核验）、失败（原因）。不要输出完整客户历史、地址、订单号、支付信息或凭证。

## 当日回复记录与 Excel 外发

回复回显成功后由执行器当场写入同日临时 Markdown 台账（`records/待整理客户回复-<date>.md`）；每轮随后 `compile_daily_reply_xlsx.mjs` 整理当日 Excel，`send_daily_reply_xlsx_to_wechat.mjs` 经统一微信桥外发至群"上海臻肆外卖运营-盯个盯-饭敢当 💰发财精英荟💰"。**2026-10-03 大同新规：Excel 外发为当天当次数据、不限次数、没有重复门禁**（marker 按轮次唯一），当日无已核验回复时不发空表、如实记录跳过原因。只记录脱敏会话标识、问题摘要与实际发送文案；草稿、候选或回显未核验的内容不得记为已发送。

当天 Excel 附件外发或出现外发证据冲突时，先读[台账附件交付复盘](references/2026-09-21-台账附件交付复盘.md)。该流程要求区分业务判断与工具状态、两次同类非发送失败后停止，并将规则修复与当天生产交付隔离。
