## 作品描述

```
{校对后的封面文案}，{广告词}｜{店铺名}｜地址：{详细地址}
```

`prepare` 产出的封面段是 **OCR 草稿**，不是定稿。**填写作品描述、点发布之前**，必须由大模型对照封面图（或平台预览上的封面字）做循环自检：句子是否通顺、是否像人话、是否和封面一致。OCR 会读错（例：`独家秘制` → `独家秤郜`，`舌尖上的享受` → `舌类上的享觉`）。

闭环：

```
读一遍 → 不通过 → 回去再看封面 → 修改 caption → 再读
         → 通过   → 才能粘贴描述、点发布
```

自检不通过禁止发布。改完必须再读一次，不能改完就直接发。

## 抖音 Chrome 桥

- **发前硬门**：粘贴抖音作品描述之前，大模型必须对照封面读一遍描述；自检不通过就再看、再改、再读，直到通过。OCR 草稿不能直接发

## 阶段范围

### 下载阶段
- **时间线（用户指定）**：先拉到群**最新**，再**很小步**往上翻。
- **下载前硬门**：每一屏、每一条都要先看见聊天区里、**贴在这条视频上方**的历史时间（`12:11` / `昨天 18:46` / `星期六 21:21`）。**上方没有这个时间 → 不下**（下方那条时间属于后面的消息）。禁止用左侧会话列表钟点，禁止用上一屏残留时间猜。
- 聊天区时间一旦**早于**上次 checkpoint（当前 `2026-09-06T13:39`）立刻停。连续几屏都读不到时间也停，避免盲翻到上周。禁止翻到上周。
- **去重**：同一条视频永远同一个文件名 `YYYYMMDDTHHMM_时长_封面摘要.mp4`。`videos/`（含历史批次）里已有该文件名 → 跳过，不重复下。用**文件名**判重复，不靠「缓存里最新 mp4」。
- 只收下 `messageTime > checkpoint` 的片；恰好等于上次记录时间的那条已下过，不再下。
- **scan** 只负责找候选，**不写 checkpoint**。窗口顶栏不是指定群 → 直接失败
- 打开群后必须再核对顶栏群名。
- **落盘两步（用户指定，不要改）**：封面正中有下载箭头 = 还没下 → **先点一下视频**，等微信自己下完；然后再**右键**，菜单里出现「另存为...」（同时会有「在访达中显示」）→ 点「另存为」存到本波 `videos/` 固定文件名。没出现「另存为」说明还没下完，再点一次视频等，不要去翻微信缓存、不要猜最新 mp4。
- 文件落地后立刻做**主题门**：首帧/缩略图 OCR 必须命中群名/店名里的品类词（本店：`鱼杂` / `鱼杂王` / `鱼杂锅`）。本波人工验收前：主题门失败**不删文件**，标「待检查」；验收通过后再清错片。
- **人工验收前不写 checkpoint**。验收通过后再把游标推到本批已确认视频的最大 `messageTime`。
- **全部下完先暂停**，给人表：`时间 | 视频名称`。未检查前不 prepare、不发布。
- **宁可 0 条，禁止发错群、错主题的视频**

### 上传阶段
- **prepare** 为每条 `downloaded` 生成 caption（封面段=OCR 草稿）
- **发前自检（硬门，循环）**：大模型对照封面读句子；不通过就回去再看、再改、再读，直到通过才能填描述、点发布
- **publish** 对每条 `prepared` **逐条**上传。默认三平台：抖音、快手、视频号（见 [快手与视频号发布方案](20260907-快手与视频号发布方案.md)）。`--platform douyin|kuaishou|channels|all`
- 抖音点发布后如出现“接收短信验证码”，固定执行一次刷新，回读描述和位置未丢失后再点一次发布；最多恢复一次。
- 发布成功必须等平台自行离开编辑态，再进入内容管理页回读；禁止在编辑页用文案本身判定已发布。
- 抖音“发布”使用可访问性树 `AXPress`，不使用容易受窗口坐标影响的物理点击。
- 每平台写 `platforms.<name>.state`，并在内容管理页用描述前 8 字回读
