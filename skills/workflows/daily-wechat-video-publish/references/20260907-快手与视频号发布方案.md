### 多 Chrome 进程隔离

本机可能同时存在普通 Chrome 和后台无头 Chrome。发布器只认 macOS 辅助功能树中可见、带 `AXWindow` 的普通 Chrome 进程；不得用按应用名匹配的 AppleScript 选择浏览器，因为它可能命中后台无头进程。页面跳转、文件对话框键盘输入和 URL 回读都必须投递到该可见进程。

页面跳转期间辅助功能树可能短暂尚未挂出 `AXWebArea`。执行器在同一可见普通 Chrome 主窗口内轮询最多 10 秒；恢复后才继续，超时则以未上传失败并停止，不能改控其他 Chrome 进程或重发。

## 单条流程

```
预检标签 → 挪开淘宝闪购窗 → 打开上传页 → 系统对话框选 mp4
→ 等编辑页 → AX/OCR 填描述 → 搜并点选本店 POI
→ 未授权则停；授权则点 发布/发表
→ 打开内容管理页，用描述前 8 字回读
```

抖音、快手、视频号、小红书统一执行“上传完成门”：进入编辑页后至少留出 10 秒上传完成窗口，且不存在上传中/上传未完成提示，才允许发布。弹出可恢复提示时直接点“确定/确认”并继续等待。

### 2026-09-09 固定定位补充

- 上传入口只点主网页的 `AXButton`：快手精确命中“上传视频”；视频号命中“上传时长……”上传区。禁止 OCR 首个文本命中。
- 只有系统文件选择器出现后才输入绝对路径；路径禁止进入 Chrome 查找栏。
- 标题匹配到多个 Chrome 窗口时，只选择实际包含 `AXWebArea` 的主窗口。
- 文件选定后必须回读作品描述输入区才算编辑页就绪，不能只看 URL。
- 任一平台失败立即停止批次，禁止继续制造后续失败回执。
- 视频号短标题固定填“红太阳鱼杂王 蜀湘川菜”，避免自动标题中的特殊符号阻断发表。
- 视频号位置必须搜“辽阳路195号”并选“红太阳鱼杂王·蜀湘川菜”；只显示“上海市”不算完成。
- 发布后必须同时校验内容管理 URL 和描述前缀；仍在编辑页时禁止报已验证。
- 点“发布/发表”后先等平台自行跳转内容管理页，禁止执行器立即强制导航；否则可能中断尚未完成的发布请求。
- 快手如提示“请在视频上传完成后再点击发布”，该次不算发布尝试；关闭提示、等待 10 秒后再点发布，直到自动跳转内容管理页或 90 秒超时。

### 2026-09-10 上传前门与失败分级

- 快手、视频号主执行器对上传入口只执行 `AXPress`，不得再对说明文字或其中心坐标做物理点击。
- `AXPress` 后必须在同一个可见普通 Chrome 中确认原生系统文件框已出现，才允许输入绝对路径；未出现时以 `pre_upload_failed:file-dialog-missing` 停止。此状态没有选择文件、没有编辑或发布副作用。
- 文件框出现后，执行器才使用“前往文件夹 → 精确绝对路径 → 打开”的固定动作；随后仍须通过编辑页门和 10 秒上传完成门。
- `pre_upload_failed` 与 `publish_unknown` 必须分开：前者允许用户下一次重新发起同一平台上传；后者保留禁止自动重发的规则。批次内两者都会立即停止后续视频。
- 该门的测试必须覆盖：上传按钮走 `AXPress`、文件框缺失时绝不调用路径输入、主执行器把前置失败写入 `pre_upload_failed`。

## CLI

```bash
cd .../daily-wechat-video-publish/scripts

# 探测
python3 kuaishou_chrome_bridge.py --preflight
python3 channels_chrome_bridge.py --preflight

# 单条
python3 kuaishou_chrome_bridge.py --video V --caption C --location L [--confirm-publish]
python3 channels_chrome_bridge.py --video V --caption C --location L [--confirm-publish]

# 批次（默认三平台；可只发一个）
python3 workflow_executor.py --run-id <run_id> publish --platform all
python3 workflow_executor.py --run-id <run_id> publish --platform kuaishou --confirm-publish
python3 workflow_executor.py --run-id <run_id> publish --platform channels --confirm-publish
```

`candidates.jsonl` 增加 `platforms.<name>.state`（`publish_pending` / `submitted` / `verified` / `publish_unknown`）。总 `state` 仅当抖音、快手、视频号都 `verified` 才升 `verified`；只发其中一个平台最多升到 `submitted`。已 `submitted`/`verified` 的平台跳过，不重复填表。
