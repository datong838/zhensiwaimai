# 客户机器迁移前检查

当前生产机器可运行不等于新机器已验收。迁移不得复制登录凭据、用旧回执替代新机器验收或重置防重账本。

1. 按当前目录安装依赖，设置ZENSI_NODE、ZENSI_PYTHON等已有解释器覆盖；确认原manifest中的解释器与各流内部固定解释器都存在、可执行且具有所需模块。仅设置调度变量不能覆盖所有内部固定路径。
2. 检查四岗位connect模块、浏览器插件、profile目录与工位锁，安装客户机器自己的独立浏览器和登录态，禁跨岗位复制认证资料。原固定外部插件路径须逐流受控替换，不能全仓字符串替换。
3. UI能力提供者必须支持最新界面树、可见控件操作、图像与文件附件呈现、前置意图及两帧证据回传；不能把纯调度脚本视为具备此能力。岗位契约独立于模型。
4. install_daemon.sh按当前项目位置生成配置；Node配置路径失效时回退本机PATH/既有候选，有效配置优先。该修复不代表全部路径便携化完成。
5. 用合成载荷在客户指定测试群验收文字、inline图片、Excel、防重与中断；随后各业务流随新数据正常班次验收。未知结果不能重发。
6. 验收后启用08:00监理与22:00维护，确认原调度、实际心跳和原回执。不以文档、配置或测试通过代替当天真实交付。

2026-10-24本机只读核验：manifest三种解释器存在且可执行；未重装服务。差评明日业务日期和16项依赖/release通过。尚有内部固定解释器和外部插件耦合，迁移前按上述流程处理，禁止宣称已完成新机器验收。
