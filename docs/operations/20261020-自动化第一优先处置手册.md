# 自动化第一优先处置手册（2026-10-20 大同指令版）

> **总原则（2026-10-20 23:11 大同指令，永久生效）**：全部定时任务检测到问题后，
> **第一时间尽量自己解决，不允许等待、放任不管**。真解决不了的，直接输出
> **「⚠️需要人工介入」+ 具体原因 + 需要人做的那个动作**（一般是掉登录）。
> 禁止「只记录/只告警/等大同来问」。每轮报告必须含：发现什么 → 做了什么 →
> 结果如何（修好/仍需人工）。

## 1. 分层诊断顺序（铁律 #67：多层故障可并存，每轮重新定性，禁沿用上一轮原因）

按层排查，哪层坏修哪层，修完复验再进下一层：

| 层 | 探测命令 | 判据 |
|---|---|---|
| ①进程/端口层 | `curl -s --noproxy '*' -m 4 -H "Host: localhost" http://127.0.0.1:<端口>/json/version` + `lsof -t <锁文件/端口>` | 健康≠就绪（#40） |
| ②登录层 | `node runtime/auth_keepalive.mjs`（先 `--self-test` 须 X passed, 0 failed） | 退出码 0=活 / 3=掉登录 / 4=工位忙 |
| ③页面壳层 | `http://127.0.0.1:<端口>/json/list` 看 page URL | 停 `/login` 或 omnibox 残留 ⇒ 复位 |
| ④业务流层 | `python3 runtime/supervisor_drive.py --apply` | 读「当场自处置/待你拍板」输出 |

注意：`ps -eo` / `launchctl list` 在沙箱可能返回空，**绝不能据此判「进程不在」**（#65）；判活真判据=①`lsof` ②`launchctl print gui/501/<label>` 看 state=running ③产物 mtime 追加。`kickstart` 非必要不带 `-k`（会 SIGTERM 旧实例）。

## 3. 需要人工介入的判定（只有这些才输出「⚠️需要大同处理」）

判定为以下情形时：**修不了就是修不了，立即明确输出**「⚠️需要人工介入：<岗位/机器> <原因>，需要做的动作=<具体动作>」，并把请求写入 `runtime/state/war_room.json`（status=awaiting_you + SLA）：

1. **掉登录类**（最常见）：
   - 岗位 Chrome：`*-login-expired` / `NEEDS_LOGIN` / `state=out` / `UNAUTHORIZED`——先跑 `auth_keepalive.mjs --notify --open-login` 拉起 headful 登录窗（2h 冷却内不重复拉），然后输出「Mac 屏幕已弹登录窗，请扫码/账密登录，登录后系统自动切回无头+自动补跑」。
   - Windows 微信：网关 `/health` 回 `agent up` 但 `logged_in=false` 或 `list_sessions`（结构=`data.sessions`）无目标群——输出「需在 Windows 机上重新登录微信」。此时**不要尝试发微信告警**（发不出去），只在回复里置顶。
2. **Windows 主机物理开机**：WoL 魔术包唤不醒（BIOS 未启用）——输出「需人工按电源键开机，开机后网关服务自启，按完我来验收」。
3. **需要大同给资料/拍板**：建店需求（需新资料）、越红线授权（重发生产流等）。
4. **自修两轮仍失败**：同一问题按 §2 修复后复验仍失败 ⇒ 不再盲目重试，输出具体失败码+已做动作+需要人做什么。

**夜间 20:00–次日 08:00 Windows 主机休眠、双侧网关不可达 = 预期状态**，不告警、不重试、不算故障（除非当夜有收口任务依赖发送）。

## 4. 红线（任何自修不得越过）

- 绝不重跑/重发带对外发送的生产流（重跑=一次对外副作用，#26）；补跑只经 `control.json force_run` 由 daemon 采纳。
- 绝不碰 Mac 桌面微信；内部通道名 desktop/windows-driver-unreachable 指的是 Windows 服务网关（8731）。
- 绝不新开浏览器标签页做业务导航（#68）；页面复用 + 站点左侧菜单 SPA 导航。
- 判定只依页面状态/现场工件，不依 toast/印象。
- 发送证据只认 `transport.data.sent=true`（#30）。
- 本机 curl 网关必须 `--noproxy '*'`。

## 5. 明早卡点前瞻排查（2026-10-22 大同指令·21:00 监理督查档固定动作）

每晚 21:00 监理督查（automation 3f070f45）在当晚巡检之外，必须做一轮「明早卡点前瞻」，保障次日最早档（通常 8:00 top10）前外发面/环境面就绪。顺序与判据：

0. **读明日排班**：`runtime/skills_manifest.json` 的 `skills[].earliest_hour/earliest_minute/latest_hour/cadence_hours` 排序输出，明确各档时间。
1. **relay(8732)**：`lsof -nP -iTCP:8732 -sTCP:LISTEN` + `curl --noproxy '*' -m 8 http://127.0.0.1:8732/health`。已知事实（10-22 实战）：
   - relay **会随启动会话结束自然死亡**（run_in_background 起的进程活不过会话）；
   - launchd 注册 `com.zhensi.windows-relay.plist` 持续 `Bootstrap failed: 5`（I/O error，沙箱内外、重试均失败，疑系统级；`launchctl print` 对未成功注册的服务回 Bad request，careloop 例外可 print）；
   - 修复=§2①重启 + `POST 8732 {"action":"list_sessions"}` 回真实臻肆会话复验（token 用 `CHANGE_ME_STRONG_TOKEN`，#96 漂移态；relay 内部走 token_fallbacks 双 token 重试）；
   - Windows 网关直连 `http://192.168.110.184:8731/health` 判 `logged_in&&ready`（IP 以大同告知+ping 实证为准，候选式处理勿钉死）。
2. **四岗位 CDP 快检**：`curl -s http://127.0.0.1:923{0,1,2,3}/json/list`。判活：CDP `/json/version` 活着=Chrome 活着（**各岗位 `/health` 无响应不是卡点**，该服务本就不常驻）；9232 金鲨必须 headful；9231 判活=POST `UtilService.isMasterAccount` 回 200。无 page ⇒ `curl -X PUT "http://127.0.0.1:<port>/json/new?<目标URL>"` 补建业务页，跑 `auth_keepalive.mjs --notify` 复验，关重复页保留 1 个。落登录特征 ⇒ 按 §3.1 掉登录流程。
3. **WOL**：`wol_windows.py --fire`（发 192.168.110.255 广播，实测 2/2）+ 直连 8731 复验。已知事实：`com.zhensi.wol-morning.plist` launchd 注册失败已改名 `.unused`，**WOL 由 21:00 档每夜直接执行承担**；另建次日 07:45 一次性保险 automation（首建 id=ada94a7e）做早晨兜底。
4. **封印全量体检**：`seal_drift_repair.py --flow <每个 enabled 流>`。判据：`"state": "healthy"` 与 `"reason": "无受管流"` **都算健康**（无受管流=该流无封印管理，10-22 曾误报 18 个流）；只有「白名单外文件/代码文件失配」才是真问题。真失配修复路径见 §2 与 10-22 实战（negative-reviews 走 `maintenance_executor.mjs prepare-unsealed-acceptance`；merchants 同步 `executor-lock.json` 的 `messaging_bridge`/`messaging_dependencies` 钉死值 + `executor_integrity.verify_for_run`），修完 dry-run 复验 + war_room 真实结案（防谎报 resolved）。**修完绝不因「今天没跑」force_run**——当日已 SUCCESS+已外发证据的不重跑（#26）。
5. **daemon 活性**：`launchctl print gui/$(id -u)/com.zhensi.waimai.careloop` 应 `state=running`；`daemon.out.log` mtime 35 分钟内有更新（cycle 30 分钟）；死/落后 ⇒ `launchctl kickstart`。
6. **台账与补发 automation 对账**：`sent_today.json` 有当日记录=已发；一次性补发 automation（如 fee2fd6c 有 validUntil）确认到期不再造成重复外发。
7. **保险兜底**：确认次日 07:45 有一次性保险 automation（WOL+relay+四岗位快检）；一次性会过期，21:00 档负责每晚检查，缺则重建。
8. **输出**：巡检报告后追加「明早卡点前瞻」小节；自修两轮仍失败或需人工（掉登录扫码/launchd 系统级故障需大同真实终端 bootstrap）⇒ 置顶「⚠️需要大同处理」+ war_room 挂 SLA。
