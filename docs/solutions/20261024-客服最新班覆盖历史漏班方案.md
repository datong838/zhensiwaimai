# 客服最新班覆盖历史漏班方案

依据用户2026-10-24最新指令：每次客服执行全量实时数据，历史12/15点漏班不逐档追补；到当前最新班只执行一次，最终17点班正常完成即可认定当天值班完成。历史失败、未知和已发记录保留，不改写为成功，不重发旧附件。此规则仅客服三档，其他任务流不变。

最小实现：在runtime/fixed_schedule.py统一定义客服三档及历史档判据；run_all.py的周期门禁、强制补跑和单跑入口均拒绝已过时客服档，以实际执行时钟判断，防周期跨档。daily_progress.py将历史档标为不补跑，排除积压分母，不标成功。台账统计同样排除历史档，最后17档必须有当天17点后真实成功；ledger_gate.py使用相同判据，不拿凌晨或中午成功顶最终档。既有授权、防重、发送合同及其他排班不改。

自测覆盖12/15/17边界、跨档恢复、强制单跑不执行旧档、凌晨成功不覆盖末班、历史记录保留、非客服不受影响。先离线验证，原daemon无live_steps后安全重载；不为重载中断当前任务。文档和SKILL同步，源码推送GitHub。实际最终档必须核对原run和UI回执后才认定完成。

## 用户当天确认完成例外
用户明确手工关闭17点档附件窗口，本次未发送，并确认今天客服就当成功、不再重复。新增独立当天用户验收记录（非发送成功收据），限定当前业务日与客服最终档、明确本次未发送。调度、单跑、进度表与台账门均识别它，终止当日客服重试；不改原unknown为verified、不制造SUCCESS运行记录。翌日自然失效。进度显示“用户确认完成·本次未发送”，不能声称最终档附件送达。
