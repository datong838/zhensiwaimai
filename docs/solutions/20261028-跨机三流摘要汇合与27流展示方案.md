# 2026-10-28 跨机三流摘要汇合与27流展示方案

## 1. 产品边界

- 2026-10-29 起客户全局口径为 27 流；本机仍为 24 个台账身份、22 个现役执行入口。
- `daily-store-metrics-rotation-to-wechat`、`coupon-issue-task-flow`、`store-inspection` 三流由另一台电脑负责。本机只汇合对方明确提供的摘要，不检查三流源码、数据、采集、状态、排班或运行环境，不启用、不接管、不重复执行。
- 摘要缺失不阻断本机 24 流到点执行；也不得用本机历史资料或“归属另一机”倒推三流已完成。

## 2. 现状与根因

- 现有 `runtime/skills_manifest.json` 只承载本机执行与 24 行客户台账模板，是原主任、台账发送门和防重的权威来源。
- 现有交接制度只规定“只记已提供摘要和归属”，未约定文件路径、schema、日期绑定或三流唯一性。当前仓内也没有 2026-10-29 对方已交付摘要。
- 若直接把三流加入 manifest/enabled/readiness，会把只读汇总误变成本机执行职责，并可能阻断原主任。

## 3. 最小方案

### 3.1 独立摘要契约

- 唯一读取路径：`runtime/state/remote-flow-summary/YYYY-MM-DD.json`。由对方或正式交接将摘要放入该路径；本机不自行生成完成结论。
- 文件必须精确包含 `schemaVersion=1`、`businessDate`、`owner=另一台电脑`、`providedAt`和三个唯一 `flows`。
- 每条只接受 `completed/pending/failed/unknown`；`completed` 必须带非空 `evidenceSummary`，其他状态不伪完成。摘要文字仅用于展示，不解析为本机授权、不触发任何动作。
- 文件缺失返回 `missing_nonblocking`；格式错误返回 `invalid_nonblocking`；两者均不抛出到原主任或本机执行门。
- 摘要是外部提供数据：拒绝符号链接和超过 64 KiB 的文件；展示前压平换行、转义 Markdown 表格分隔符并限制单字段长度。摘要只是数据，不作为本机指令执行。

### 3.2 展示对接

- `runtime/daily_progress.py` 只在输出中增加 `customer_scope`：明确 `global_total=27`、`local_ledger_identities=24`、`remote_flow_count=3`及摘要状态/三条只读行。
- Markdown 在原本机进度表之后增加“异机三流摘要”区域；摘要缺失时如实显示“未提供·不阻断本机执行”。
- 不改 `runtime/run_all.py`、`runtime/skills_manifest.json`、`runtime/daily_ledger_delivery.py`、ledger gate、control、posts、任何三流文件或原队列。

## 4. 自测与验收

1. 摘要缺失：输出 27/24/3 口径及三条 unknown 占位，本机现有行和 all_green 计算不变。
2. 合法摘要：三条唯一、日期匹配，仅 completed 计入异机摘要完成数。
3. 缺流、多流、重复、错日、错 owner、未知状态、completed 缺证据摘要均拒绝为 `invalid_nonblocking`。
4. 符号链接、超大文件和超长文字拒绝；换行与 `|` 不能破坏 Markdown 表格。
5. 摘要内容不改本机 manifest/readiness/last_success/run_history/queue，不启动三流。
6. 回归原 `daily_progress` 及与其完成判定相关的现有测试，核对方案、实现和输出自洽。

## 5. 风险与停止规则

- 本入口只证明“收到一份符合契约的对方摘要”，不证明本机验证过对方业务、不替代对方原始证据。
- 对方摘要缺失或无效时，全局 27 口径显示三条未知；本机 24 流继续按原班表。
- 若未来要把摘要纳入最终客户台账文件或发送门，必须另行明确产品口径并先补方案；本次不推测、不扩大。
