## 二、补建设计（四段闭环）

### 段1｜分诊采集执行器 `scan_queue_triage.mjs`（新增，只读零发送）
- 挂在 12:00 / 15:00 / 17:00 三条 entry 的 ensure 门禁之后（manifest `steps` 追加）。
- 流程：经 `runWithUnansweredQueue(driver, scan)` 进入 → 左侧会话列表逐条点开核验（滚动到底部结束标志）→ 按 `references/qualification-and-reply-policy.md` 过滤（餐饮订单明确诉求 + 超10分钟 + 无店主人工回复；加微信/乱码/广告一律忽略）→ 从 `personal-reply-catalog.md` 语义匹配建议文案。
- 产出：`records/分诊候选-YYYY-MM-DD-HHmm.json`（脱敏：会话标识最小化、无地址/订单号/支付信息），并同步输出 `candidateCount` 到 stdout 供 daemon 记录。
- 门禁继承：所有页面操作沿用 ensure 的 driver 合同与唯一性断言；`99+` 徽标不作为定位；不碰输入框/发送/退款控件。
- 预算：会话数上限（如 40）+ 单轮超时继承 entry `timeout_seconds: 1800`；超限如实报告覆盖数，不静默截断。

### 段2｜记账执行器 `append_daily_reply_md.mjs`（新增，唯一写 md 入口）
- 职责：把一条已回显确认的回复按 `daily-reply-log.md` 八列格式**原子追加**到 `records/待整理客户回复-YYYY-MM-DD.md`（当日文件不存在则建，含表头）。
- 防重：按 `发送时间+会话标识+实际回复` 三元组当日去重（与 xlsx 去重规则一致）；重复输入输出 `{appended:false,reason:"duplicate"}`。
- 输入合同：单条 JSON（date/sentAt/session/store/question/reply/status），字段校验 fail-closed；`status` 只允许「已核验/待核验」——回显未确认的候选**禁止**写「已核验」。
- 回显核验（段1/段3 共用小工具 `verify_echo.mjs`）：发送后在会话中 CDP 只读读取最新一条己方消息与预期文案精确比对；比对不过 → 只能记「待核验」。
- 人工补录 CLI：`--record '<json>'`（监理/车间主任补账用，同样走去重与校验）。

### 段3｜回复段（业务决策点，两案供大同拍板）
- **A 案（保守，默认推荐）**：只读分诊 + 建议候选落盘，**回复由人工在工作台完成**；人工回复后由 15:00/17:00 轮的分诊器回读「已回复」会话 + `verify_echo` 核验，自动补记临时 md。技能边界与 SKILL.md「默认只读建议」一致，零发送授权问题。
- **B 案（自动化发送，另行立项）**：新建发送执行器 + 授权话术 + 发送防重账本 + 回显核验，需大同明确授权（参照旧 18 的授权边界：不承诺退款/补偿/改餐/库存）。**本次不实施**，仅预留接口位（候选 JSON 中带 `suggestedReply`，可直接升级）。

### 段4｜17:00 交付段（挂上 manifest 预留位）
- 17:00 entry steps：`ensure_unanswered_queue` → `scan_queue_triage` → `compile_daily_reply_xlsx` → `send_daily_reply_xlsx_to_wechat`。
- 「0 条」语义修正：当日 0 条已核验回复时，**仍产出带「0 条已核验回复」标注的合法终态表**（按 `daily-reply-log.md` 规范），但必须满足：① 分诊候选计数=0 才算真 0 条；② 若候选>0 而 md/xlsx=0 → 矛盾 → 当轮 FAIL + CRITICAL 告警，**禁止静默发送空表**（今日事故红灯规则）。
- 告警接线：daemon 告警分类新增 `meituan-ledger-gap`（候选>0 但记账/汇总缺失）；`missing-report`/`no-temp-ledger` 不再以 skipped 语义吞掉，按 FAIL 处理。

## 三、新机制合同（全部代码强制，prompt/MD 无放行权）

1. **排班**：全部经 manifest 三条 entry 承载，零改 daemon；`cadence_hours:24 + earliest_hour` 保持。
2. **封印**：新脚本引用共享发送器/依赖的，经 `dependency_maintenance.py` 受控登记（新文件 `setdefault` 显式纳入）；`ensure_unanswered_queue` 等既有门禁文件不动。
3. **防重与账本**：md 记账三元组去重；xlsx 已有去重沿用；发送段（B 案落地时）账本记 `sendAttempts`，attempted/unknown 一律禁止重发。
4. **fail-closed**：任何群定位/核验/回显状态不明 → 停止并告警；正常路径 `runtimeModelDecisions=0`。
5. **监理边界**：监理只看告警与台账，不代跑任何业务步骤（10-02 事故铁律）。
