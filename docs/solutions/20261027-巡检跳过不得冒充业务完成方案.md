# 巡检跳过不得冒充业务完成

## 问题与依据

当前新店活动和装修原执行器将shop-not-found等skipped算作顶层complete、主任SUCCESS。当前原始两份日志显示唯一新店均未检查；新鲜名称/ID搜索亦为空。用户要求不得擅自排除客户，完成列与简洁备注必须真实，不能靠技术SUCCESS写“已完成”。不修改历史SUCCESS、last_success、发送标记或游标，不自动重试外部不可见门店。

## 最小修改目录

新增`runtime/business_coverage.py`、`runtime/test_business_coverage.py`；接入`runtime/ledger_gate.py`、`runtime/daily_progress.py`、`runtime/run_all.py`的build_ledger_rows。仅对活动/装修两流从当日原run_history记录及其原step日志读取顶层回执，校验同日/flow/log目录绑定、targetCount与shops完整性。无候选且原完整0目标允许完成；verified/already_verified/no-missing或明确shop-not-operating按原产品口径处理；not-found/timeout/busy/unknown不得计完成。未找到当日业务回执不得替原SUCCESS背书。其他20现役及两合并别名不改变。

## 生效与验证

隔离测试覆盖完整检查、0目标、目录不可见、超时/忙、非营业例外、漏店、旧日/越界日志拒绝；集成证明原SUCCESS记录不改而台账为否、最终gate进入A清单。原ledger/progress相关测试回归。当前真实两流读回应显示1家未检查。需要刷新主任缓存时，只在确认launchctl正常、live_steps为空、真实后代无业务、物理租约和组锁无活跃者、UI队列无在途任务后，通过原launchctl单次安全重载，不并发新主任、不重启Chrome；若临近13点或忙则不重载，优先保持业务，先让独立只读gate/progress生效并明确草稿缓存限制。

原用户事实、授权、防重与终态收据不重写。重载后回读原服务新PID/心跳及无旧业务进程，确认无重发。失败只恢复本次代码，不回滚业务数据。外部目录同步/授权由账号管理员核对，独立正常流继续。

## 实施结果

42项相关测试通过，真实两流各1家未检查，台账门A清单与进度/台账完成列一致为未完成；另保留technical_success=1说明技术记录未改。原SUCCESS及last_success SHA不变。新口径仅2026-10-27起，不回改旧日查询解释。原主任在确认无业务子进程/活锁、6条旧UI任务均过期或owner不存在且未改历史后，经原launchctl单次安全重载，PID28308→57981；新周期生成台账active8/22，未发送台账，Chrome未重启。
