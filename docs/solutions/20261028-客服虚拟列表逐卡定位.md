# 客服虚拟列表逐卡定位

原collectAllCards全量滚动后恢复视点；processCards用精确ID定位返回0时却记“可能已读/已回”并增加checked、done。虚拟列表中的屏幕外卡片也可能不在DOM，因此这不能证明已实际检查，且可能阻止另一视图接续。

修改 `skills/workflows/meituan-intelligent-customer-service/scripts/reply_unanswered_sessions.mjs`，新增同目录 `session_card_locator.mjs` 与 `test_session_card_locator.mjs`。精确19位ID当前唯一可见时沿原路径；未找到时只在原会话列表有界滚动重新定位，不按预览/索引猜身份，不点击其他会话，不输入/提交。使用原80%视口步长、300轮预算，先从当前视点向后，再最多从顶部包回一次；到底须高度/可见ID序列稳定，滚动无进展/预算耗尽明确失败。找到后仍重新核对精确ID唯一，原卡片点击及judge不变；检查结束或失败恢复本次原列表视点。

无法定位仅记脱敏locatePending，不增加checked/done、不推断已回或消失成功。独立卡片继续；另一原视图确实成功读取同ID时才清除此项pending。主回执及last-scan显式记录pending，非空则executionComplete=false、CLI原不完整退出1。旧attempted/unknown、回复账本/意图、防重、附件及排班不改。

先假虚拟DOM验证屏幕外定位、当前视点向后/包回、精确重复ID拒绝、未找到恢复、滚动卡住/预算失败恢复；原processCards集成测试验证未找到0输入/意图/发送且不伪checked，之后第二视图读取才清pending。原全部客服回归及岗位/共享门复核，15点原主任自然运行验收，不在维护中回复客户。
