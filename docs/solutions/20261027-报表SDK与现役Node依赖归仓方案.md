# 报表SDK与现役Node依赖归仓方案

## 范围依据

用户要求无积压时尽快收口，本系统机制不可留工具内，外部大系统不搬。现存SDK是独立库`@oai/artifact-tool`2.8.99，自带node_modules（skia-canvas3.0.8、walnut0.1.262等），全包无软链接。只接管这个库和playwright1.62.1包，不复制Node二进制、Codex/WorkBuddy/ChatGPT引擎或365MiB整套全局node_modules。playwright-core依旧使用用户独立browser共用组件1.62.1。

## 目录与最小更改

将SDK完整包（含自身依赖与文档/元数据）及playwright包复制到`vendor/node_modules/`，保留原文件，不改变宿主安装。仓内`vendor/node_modules/playwright-core`指向已授权独立browser组件。逐文件SHA核验、包版本及真实既有XLSX读写/渲染零发送验证后，10个现役node_modules目录链接改指仓内vendor/node_modules，2个非现役store-inspection链接保留并登记，不改旧非现役能力。

客服4脚本的SDK绝对导入改为`@oai/artifact-tool`，在该客服包增加指向仓内vendor/node_modules的解析链接。具体文件：`compile_daily_reply_xlsx.mjs`、`send_daily_reply_xlsx_to_wechat.mjs`、`build_empty_daily_reply_log.mjs`、`append_daily_reply_log.mjs`。不改函数、账本、发送、业务日期或原文件校验。金鲨冻结核和差评报表裸包导入通过目录链接归仓，不改冻结核字节或其封印。

## 验证与切换

先复制、文件SHA及版本；隔离临时输出对既有真实日报进行import/export及区域render验证（不修改原Excel、不发群）。确认无live_steps且未到原档时，备份原链接及4文件，再逐个原子替换链接并修改4导入。所有消费者模块加载、原冻结核/五门、客服零行逻辑、现役依赖基线检查通过后验收；不手动执行生产任务。若原任务已开始先等原任务结束，不抢岗位。

回滚恢复原目录链接及4源码，不改业务状态、不删除源依赖。更新dependency-contract主库根、部署说明及安装镜像对照；宿主Node/Python/应用仍为明确外部运行环境，不迁入大系统。库包位于被gitignore排除的node_modules，本地已归仓不等于Git包含依赖二进制，需另留精确文件清单供部署备份。
