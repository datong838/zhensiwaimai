# 测试隔离契约（2026-09-30）

> 适用范围：**所有任务流的测试脚本，要求完全一致** ——
> **测试脚本不得操控线上数据逻辑，也不得操控线上群。**

---

## 0. 为什么要有这份契约

2026-09-30 发生过一次事故：一个测试脚本打着"离线回归"的旗号，却经由已废弃的接缝、用真实品牌名当目标，**真把垃圾图发到了线上业务大群**（详见 `docs/operations/开发清单-长程路线图.md` §D19）。

事故根因有三：① 夹具用了真实品牌名；② 桩打在已废弃的函数上；③ 出站无统一守卫。
事后我们用"出站载荷闸门 + 进程级守卫"把当晚那一条链路堵死了，但那只是**单点**。

本契约把铁律从"一处堵漏"升级为"**全任务流统一、可自动检查、可 CI 拦住**"的三层防线，
让任何新来的测试脚本，无论作者记不记得，都不可能再把数据发到线上群。

---

## 1. 三层防线（互相独立、任一生效都能兜底）

### ① 运行时硬闸门（能力隔离，最主要的一道）`tests/isolation_guard.py`
- **不可绕过**：用 `sys.addaudithook` 注册，Python 进程内**无法被测试代码移除**。
- 测试进程内**禁止任何非回环网络出站**（`socket.connect` / `getaddrinfo` 指向外部地址一律抛错）。
- 测试进程内**禁止写生产状态目录**（`records/` `state/` `runs/` `artifacts/` `.runtime/`）。
- 强制 `ZHS_TEST_MODE=1`，使生产传输层（如 `windows_adapter`）在测试进程内**连构造都不允许**。
- 接入：每个测试目录的 `conftest.py` 三行即可全量生效（根目录 + 所有 `skills/*/tests` + 所有 `skills/*/scripts` 已接好）。
  > 即便某处测试忘了打桩、或桩又打在了废弃接缝上，**也不可能**驱动真实出站。

### ② 静态审计（字符串契约，可 CI）`maintenance/audit_test_isolation.py`
- 扫描仓库内**全部**测试工件（代码 + 夹具 + 数据，不只某一个技能），逐条核对 T1–T6。
- 单一数据源：`maintenance/test-isolation-policy.json`。
- `python3 maintenance/audit_test_isolation.py` —— 有 BLOCK 则退出码 1，可直接挂 CI / pre-commit。
- 负向断言（如 `assertNotIn('--execute', …)`、`assertRaises(WindowsAdapter)`）**不算违规**，那是契约的盟友。

### ③ 出站载荷闸门（已有）`skills/wechat-messaging/scripts/egress_policy.py`
- 任何出站载荷若命中"退化标识符"（如 64 个 a 连排）、哨兵词（正文甲/正文乙/`__TEST__`）、或非授权群，**一律拒**。
- 这是"即便绕过①②，也发不出去"的最后一道。

## 2. 统一要求清单（T1–T6）

| 规则 | 严重度 | 要求 | 违背判据 |
|---|---|---|---|
| **T1 不连真机** | BLOCK | 测试不得出现真机地址/端口/驱动令牌 | 命中 `192.168.110.*`、`:8731`、驱动 token 字面量 |
| **T2 不新增线上群名** | BLOCK（新增） | 线上群名/搜索键不得**新增**（存量冻结，只减不增） | 存量基线外的线上群名出现 |
| **T2b 业务数据脱敏** | WARN | 真实门店/品牌名建议改合成数据 | 命中 `businessDataTokens` |
| **T3 不驱动线上逻辑** | BLOCK | 不得连 CDP / launch 浏览器 / import 真实驱动客户端 | `connectOverCDP(`、`wxsend`、`client.WeChat(` 等 |
| **T3b 不构造真适配器** | WARN | 构造真实出站适配器仅作清偿清单（运行时已被①硬拦） | `WindowsAdapter(` / `MobileAdapter(` / `DesktopAdapter(` |
| **T4 不写生产状态** | BLOCK | 测试账本/收据/缓存必须落临时目录 | 指向 `records/state/runs/artifacts/.runtime` 的绝对路径 |
| **T5 不直调生产入口** | BLOCK | 不得真跑 `--execute` / `auto_send` / 真发文件 | 字面量命中 |
| **T6 不关隔离开关** | BLOCK | 不得把 `ZHS_TEST_MODE` 置 0 | 字面量命中 |

豁免（仅限"证明危险动作被拒绝"的负向用例）必须**双向登记**：
在测试文件内写 `# ISOLATION-WAIVER: T3 — 理由`，并同步登记到 `policy.waivers`，否则审计判 BLOCK。

## 3. 存量清偿清单（已冻结，只减不增）

首次审计扫出 **115 处线上群名**（T2）、**5 处真实门店名**（T2b）、**2 处真实适配器构造**（T3b），
已冻结为基线。它们大多是**纯函数/纯逻辑测试**（标题匹配、OCR 解析、字符串处理），名字换成什么都不影响有效性；
也有少数"断言生产常量等于字面量"的 pin —— 这类应改为从生产模块 `import` 而非复抄字面量。

**新写的测试脚本不得再新增这些字面量**；存量按 `maintenance/audit_test_isolation.py --update-baseline` 单调收紧。
要立刻把某文件清零：把线上群名改为测试群（`臻肆测试群`）、合成群名（`__TEST__群`），或**从生产配置只读引用**（如 `runtime-policy.json` 的 `groupName`）。

## 4. 怎么用

```bash
# 跑审计（人类可读；有 BLOCK 退出码 1）
python3 maintenance/audit_test_isolation.py
python3 maintenance/audit_test_isolation.py --json report.json

# 收紧/刷新 T2 存量基线（改动后须人工复核再提交）
python3 maintenance/audit_test_isolation.py --update-baseline

# CI 门回归：审计 PASS + 守卫真能拦 + 规则非空转
pytest tests/unit/test_test_isolation_contract.py
```

## 5. 残余风险与下一步（待大同拍板）
- **Node 侧测试**（`.mjs`）当前靠静态审计兜住，未装 Node 运行时硬闸门；若这些 `.mjs` 测试有一天长出真实浏览器/CDP 调用，静态审计会比运行时更早报。需要可在 Node 侧加等价的 `audit` 钩子，或把纯函数测试迁到离线 `node --test`。
- `test_reconcile.py` 在 `/usr/bin/python3` 下因缺 `openpyxl` 无法收集——属环境缺口，与契约无关。
- 存量 122 处 WARN 是清偿 backlog，不阻塞 CI；建议下个迭代分批消除。
