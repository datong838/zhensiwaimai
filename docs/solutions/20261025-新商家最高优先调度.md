# 新商家最高优先调度

用户最新明确每30分钟新增意向商家最高优先，其次当日积压。原daemon按manifest.order升序，但商家order=0，低于客服/巡店等负序号，违背最新要求。最小修改仅将商家order设为-1000，使其先于所有现有任务；其他任务相对顺序、班次、防重、群、载荷均不变。不抢断在途任务。离线验证恰好一个字段变更且商家排首。原daemon加载配置后常驻，需在无live_steps、无活跃未完成UI任务的空闲窗口安全重载，按原启动流程运行，不清锁账本，不改旧回执。后续真实到点商家优先执行才算运行验证。

## 周期中途优先检查

仅改order不覆盖中途跨班。runtime/run_all.py在每个其他任务之前以及周期结束前，再走原_cadence_gate检查商家最新有效班次；到点则调用同一run_one先执行，复用原收据/游标/防重。记录本周期已尝试的班次，避免同一失败档在每个任务前反复重试；跨下一档可再次执行，未到点/已完成/19:00后不运行。不抢断在途发送或任务，单个长任务内的安全让出仍需后续评估，不能声称实现了并行抢占。新增runtime/test_merchant_priority.py覆盖时段、去重、下一档及调用顺序。
