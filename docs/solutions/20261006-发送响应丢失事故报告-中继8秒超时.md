## 二、根因

### 2.1 定性：通道**没有走错**

两条流都走 `skills/wechat-messaging/scripts/workflow_bridge_windows.py`（**Windows 网关**）。
`daily-agent-new-merchants-to-wechat/scripts/desktop_wechat_sender.py:20`
`DESKTOP_SENDER = <…>/workflow_bridge_windows.py` 为硬编码；文件头写明
「大同 2026-09-30 授权：Mac 桌面微信停用（"桌面微信不让用了"），通知改走 Windows 10 驱动服务」。

### 2.2 真因：launchd daemon 被迫走中继，而中继静默丢弃 >8s 的响应

现场工件 `…/send-attempts/.wechat-messaging/events/<event>/preflight/preflight.json`：

```json
{"health": {"ok": true, "...": "...", "route": "relay",
            "direct_error": "[Errno 65] No route to host",
            "direct_local_network_blocked": true}}
```

⇒ **launchd daemon 无 macOS「本地网络」TCC 授权**，直连 `192.168.0.2:8731` 被拦（Errno 65），
按方案 A 回落本机中继 `127.0.0.1:8732`（`wechat-windows-driver/localhost_relay.py`）。

同 event 的 `delivery.json` 停在 `status:"attempted"`，且 **`transport/` 目录完全未生成**
⇒ 进程卡死在 `adapter.send_one` 的 `self.client.send()`（经中继的 HTTP 调用），
被 sender 的 `subprocess.run(timeout=180)` 杀掉。

**缺陷代码**（`localhost_relay.py`，修复前）：

```python
dst = socket.create_connection((target, TARGET_PORT), timeout=8)   # ← 8s 超时残留
...
def pump(a, b):
    while True:
        data = a.recv(BUFFER)        # dst.recv() 静默 8s 后抛 socket.timeout
        if not data: break
        b.sendall(data)
...
t = threading.Thread(target=pump, args=(dst, src), daemon=True)   # dst→src 方向
t.start()
pump(src, dst)
```

`socket.create_connection(timeout=8)` 的 8 秒超时**留在 socket 上并作用于其后所有阻塞 IO**。
`pump(dst, src)` 的 `dst.recv()` 在上游静默 8 秒后抛 `socket.timeout`（`OSError` 子类）——
被 `except OSError: pass` **静默吞掉，响应泵线程直接死**。

⇒ **任何耗时 >8 秒的上游响应永远回不到调用方。**
真实发送是 UI 自动化（打开会话 → 逐字输入 → 提交），必然 >8s。
