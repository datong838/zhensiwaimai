# 图片提交后同消息只读等待

## 产品目标与现状

用户要求稳定后不必每天人工看群确认图片。当前System Events原通道在唯一一次提交后直接调用media_observation两次，第一观察未暴露AXImage即抛错，没有异步渲染观察窗口。已核对本方原任务的单次提交/精确群/空框/inline-image-not-exposed收据；这证明缺少等待，不证明等待一定能让本机暴露图片。完整自动验收仍须真实业务证据，不能以等待或空白cell代替。

## 最小方案

仅图片提交后的原读取分支增加最多15秒只读轮询，两次连续独立观察仍须实际inline结构、完整群及空框。第一新消息候选即绑定原行path；候选行变化、群/草稿漂移或owner失效立即停止。只对无新行/同候选图片尚未暴露等待，不对其他异常兜底。已有unknown不重新进入发送，不增加任何点击/按键/意图，也不放宽现有内容标准。文字与文件观察保持。

源码仅skills/wechat-messaging/scripts/native_ui_post.py及受控维护授权登记dependency_maintenance.py、相应测试。共享源修改需经原共享维护器新窄授权，限定这两文件并钉住native_ui_post新SHA；不能沿用旧授权扩大路径。维护后商家原refresh-unsealed-acceptance同步，差评原维护器同步依赖且保持真实业务日验收门，Top10仅按备份旧SHA同步唯一共享依赖钉值并复验原runtime_guard。其余原policy逐项复验。无夜间生产/测试发送，不伪封板。

## 自测、安装和回滚

先测试延迟暴露后成功、持续不暴露有界停止、同候选变化/群草稿漂移/owner消失立即停止、需两次连续观察、旧intent不发送。完整共享、商家、差评及Top10相关回归、原门禁全部通过后才安装完成。保留共享源/依赖及三个消费者原件，若任何安装环节失败恢复本轮匹配原字节，不改任何发送账本、游标、原业务回执。06点前不能安全收口则完整回滚未安装候选。下一真实图片原主任一次提交后验收；观察仍无证据时保持unknown，不称自动图片回读已彻底解决。
