# 接班资料Git忽略规则调整

用户明确其他机器接班需要数据，不得遗漏资料，并要求查看.gitignore、尽量全放开。本轮仅调整忽略策略，不执行大规模资料提交或推送，不改业务文件、历史回执、防重账本和运行锁。

修改.gitignore：取消state、runtime/state、各流.runtime、.local、run_history、data、archive、outputs、work、records、runs等目录级忽略；取消xlsx/csv/图片/数据库/log/备份文件的通配忽略，保留全部业务资料、历史数据和证据。仅保留实际凭据文件模式、node_modules安装目录（vendor现有归仓库例外保持）、Python与测试缓存、系统杂项。业务数据库与锁文件可以记录，但在另一机器恢复时不得把旧PID/活锁当作新机执行许可，不得双主任并行生产。

验证：git check-ignore原state/runtime/state及代表性名单/回执/报表不再命中；git ls-files --others --exclude-standard可发现其文件。只核对文件名与忽略规则，不改业务内容。此前只代码归仓的范围不再代表用户当前要求；后续提交必须包括本轮放开的资料。

已清点此前忽略文件约5.8GB，未发现单个超过45MiB的文件；git-lfs可用。整体提交/推送和接班恢复完整性须另行实际执行验证，不能把本轮改规则说成已上传或已可接班。

## 忽略规则复核补充

真实清点新可见44405个文件、约5.86GB，发现12个名为node_modules的符号链接指向本机智能体运行时。原`**/node_modules/`只忽略目录，不匹配符号链接本身；将其改为`**/node_modules`，只排除依赖安装入口本身（含符号链接），vendor已归仓依赖例外不变。业务文件不受影响，原链接不删除、不改目标；接班不能把外部运行时绝对路径链接当依赖已归仓。
