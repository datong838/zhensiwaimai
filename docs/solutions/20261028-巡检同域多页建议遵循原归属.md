# 巡检同域多页建议遵循原归属

## 问题及证据

原supervisor_patrol.py的check_chrome将同URL前缀多页列为YELLOW，并建议“清window.name并关掉多余页”。当日9232实际存在两个相同路由业务页，而原existing_owned_target.mjs需要已完成回执、当前监听PID/启动时刻和window.name精确绑定工作页。盲清标记可能破坏正常复用；同域或同路由多页本身不证明有可删除页面。

已读现行监理Skill、0800SOP、企业微信岗位约定、CDP Bridge、原巡检check_chrome与金鲨原归属选择器。原生产及用户页面保持；没有获得仅凭该告警关页的授权。

## 最小更改

只修改runtime/supervisor_patrol.py中duplicate-page finding的detail和suggest字符串。继续保留原YELLOW/代码/分组/数量/全部枚举与登录检查；改为说明尚未判定归属，要求原回执、监听PID/启动时刻及精确页面标记核验。明确同域多页不构成清理许可，不清window.name，不批量关页，岗位忙跳过。

不新增自动修复、浏览器写操作、调度行为或静默抑制告警，不改实际页面、租约、业务数据和旧unknown。仅提示文字，无新增运行逻辑；不新增镜像文字的单元测试。用现有资料检查回归和原只读巡检真实输出核验告警仍存在且不再建议破坏归属；不通过真实关页验证。变更与证据一并推送。
