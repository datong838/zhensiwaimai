# 客服Excel原节点接通UI岗位

问题：12/15点客服采集与整理后，原附件节点被UI-only阻断，未形成完整闭环。遵循用户原授权：原流程提交任务、UI岗位按原账本执行、原流程核验；不新增独立发送入口。

最小范围：wecom_ui_queue.py仅新增meituan-customer-reply-daily单文件白名单，群固定运营群，文件名固定美团客户回复记录-YYYY-MM-DD.xlsx，仍由原桥校验路径、授权、载荷SHA和原事件；不开放任意文件或其他路由。UI岗位经真实附件按钮/系统文件选择框选取原文件，核对新文件卡片名及显示大小，两次独立观察新卡和空输入框；证据等级明确为文件名/显示大小UI核验，不声称已对聊天附件字节做SHA。

原调用方deadline180秒、外部子进程240秒与人工式UI岗位所需时间不一致：调整为deadline840秒、父进程900秒；三档调度entry的per-step看门狗改为1000秒。无新动作、无新重试、原轮次事件与未知不重发规则保留。改变manifest后只在live_steps空且无任务持锁时安全重载原daemon。

文件：skills/wechat-messaging/scripts/wecom_ui_queue.py；skills/wechat-messaging/tests/test_wecom_ui_queue.py；skills/workflows/meituan-intelligent-customer-service/scripts/send_daily_reply_xlsx_to_wechat.mjs；runtime/skills_manifest.json；相应SKILL及岗位协议。先纯函数反例测试及原发送器无调用测试，后原control补跑单档，实际非空文件送达才验收，不以单测宣称完成。

离线验证：UI队列10组，共享全量310项通过；发送脚本Node语法检查与deadline840 < 外层900 < 调度1000一致性通过。原daemon当前尚未安全重载，真实非空验收未完成。

迁移缺口修复：现有UI-only制动仅存在运行目录，源码导出会过滤该目录，客户机器可能意外回退旧发送器。新增受版本管理的config/ui-execution-policy.json；适配器和旧CLI发送入口同时识别静态策略或原运行制动，任一存在即必须UI岗位。保留原运行标记，不新增关闭开关；离线测试验证无运行标记时静态策略仍阻断。只改wecom_adapter.py、wecom_desktop_sender.py及策略测试，不改底层输入实现。生产发送行为保持现有纯UI。

为使静态UI策略在客户目录实际生效，适配器ROOT和队列路径改为按本文件推导，旧子进程解释器用当前sys.executable，HOME默认取当前用户目录；否则复制到其他机器仍会查找旧机器路径，静态策略无法生效。只消除本次UI交接模块硬编码，既有其他工作流外部库路径仍列为迁移待办，不能宣称全项目已可移植。
