# 2026-10-28 主任业务事实读取模块安全生效方案

## 1. 背景与实据

- 当前原主任由 `gui/501/com.zhensi.waimai.careloop` 托管，进程启动时间早于 `runtime/business_delivery_facts.py` 当日补丁生效时间。Python 已导入模块不会自动重载，因此盘上新逻辑不等于常驻主任已加载。
- 2026-10-28 21:20 隔离新进程只读检查显示，九条已有一次实际图片提交的任务流均返回 `businessDelivered=true`、`basis=bound-single-submission-standing-user-policy`、`technicalStatusPreserved=unknown`、`newSendAttempts=0`。
- 同时刻常驻主任的周期输出未显示新的业务事实路由，符合旧模块缓存未加载的现象。
- `runtime/run_all.py` 的反虚高设计明确：`business_delivery_observed` 仍保留 `PENDING` 分类，不伪造 `SUCCESS`。因此本次不以状态变成 `SUCCESS` 为验收条件。

## 2. 复习的产品与技术军规

- 持续监理仍使用原 `run_all.py`、原 director、原 adapter、原 UI 队列和原 ledger；不新建并行调度器。
- 企业微信仅允许 System Events 原生 UI 通道；本次不进入企微、不发送、不读取聊天历史。
- `attempted/unknown` 只读对账，不允许重发、补写 verified、改写原 response/intent/marker/run/last_success。
- 业务完成事实与技术回读状态并存：可承认已提交的业务完成，但技术 `unknown` 必须保留。
- 任何在途 `live_steps`、群租约、物理锁、非 `caffeinate` 子进程、control 强制请求或可执行的生产门禁，均立即中止激活。

## 3. 方案

### 3.1 唯一主路径与控制通道

- 唯一主路径：在原主任完全空闲且全部当日生产门禁均为跳过时，对原 launchd service 做一次受控 `kickstart -k`，使原进程重新导入盘上已测试的模块。
- 唯一控制通道：`gui/501/com.zhensi.waimai.careloop`。不写 `control.json`，不使用 force run，不直接调用任何 workflow executor。
- 重试上限：一次。新心跳 25 秒内未出现则停止，不连续 kickstart。

### 3.2 激活前门禁

1. 当前 PID 必须同时与 `daemon.json`、launchctl 一致且存活。
2. `live_steps` 为空，`runtime/state/locks/*.lock` 为空，四个已知物理锁均不存在。
3. 主任子进程只允许 `caffeinate`；`control.json` 无 force/reset 请求。
4. 使用当前盘上模块对 manifest 全部 enabled 流做隔离只读 gate 评估，必须全部 `skip=True`，不存在可启动业务的流。
5. 九条图片流必须均只读得到同日业务事实，且 `technicalStatusPreserved=unknown`、`newSendAttempts=0`。
6. 冻结浏览器 9230–9233 PID、队列 task 集合、技术源文件、manifest/control/posts/dependencies 哈希。

### 3.3 激活后验收

1. launchctl 只记录一次重载，新 PID 与新心跳稳定且原 service 仍为 running。
2. 四个 Chrome PID、受保护文件哈希、队列 task 集合全部不变；新队列任务数为 0。
3. 无 `live_steps`、无锁、无新业务子进程、无任何生产请求。
4. 新主任周期日志对九条流均记录 `business_delivery_observed`；`last_cycle.json` 仍保留 `PENDING`，这是反虚高正确结果。
5. 九条原技术 `unknown`、原 task/response/intent 哈希与发送次数不变，新发送为 0。

## 4. 停止规则与风险

- 任一激活前门禁不成立：不重载，只留证据并停止。
- 原 service 重载失败或 25 秒内无新心跳：不二次重试，不启动新服务。
- 浏览器 PID 漂移、队列新增、锁出现或任一受保护文件改变：立即中止后续动作，不修改原事实补绿。
- 重载会产生一个新主任 PID，但在全 gate 为 skip 时不会产生业务外部效果。新周期仍可能更新自然运行状态文件，但不允许改动业务原回执。
