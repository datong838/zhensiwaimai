# 微信收发统一技能方案（发送优先）

日期：2026-09-16。状态：独立技能首期候选代码已实现，离线自测与测试群历史文件核验通过；真实新发送和生产迁移尚未完成。后续用户指示与实施差异见第12、13节。

## 1. 产品目标

新增独立能力 `wechat-messaging`。业务流准备好内容后，只需指定完整群名和发送对象，即可完成普通微信群的文字、图片、文件或原生视频发送。桌面/手机检查、实例绑定、启动与有界恢复、精确搜索、发送、防重、结果复核和阶段收据全部由该能力负责。

对用户的输入保持简单；对执行器的合同保持完整。业务执行器自动携带已有授权、业务事件标识和产物收据，不把内部参数转嫁给用户，也不能因接口通用化取消原有固定群、生产/测试隔离和内容限制。

这是一项发送能力抽取，不改变报表生成、商家筛选、截图口径、业务日期或业务游标语义。不将企业微信、视频号发布或微信群素材下载纳入发送范围。

## 4. 需要解决的实际缺口

1. 已经有共用方法，但没有跨通道的统一发送合同；调用方仍决定等待、复核、账本和成功含义。
2. 公共发送器只接受 `text/image/file`，没有独立 `video` 分支。把 MP4 当文件发送不等于原生视频消息能力。
3. 公共文字核验使用 OCR 行命中，允许少一行；商家适配器另加原生复制全文复核。抽取时必须保留后者强度，不能退回较弱公共成功标志。
4. 公共图片成功条件主要是聊天区像素变化与输入清空；文件使用文件名前缀证据。都不足以直接承诺任意内容逐项匹配，需要分类型增强。
5. 公共授权只检查字符串非空，真正的授权范围依赖业务外层。新技能不能开放一个“任意授权字符串即可发任意群”的入口。
6. 手机定位跨业务互相引用，并包含特定群 OCR 修正规则。抽取不能把 `Al → AI` 等特例无条件施加到所有群名。
7. 多条业务对公共文件做 SHA-256 校验；修改一个共享文件可能让多个入口拒绝运行。需要固定版本依赖和逐条迁移。
8. 现有一般发送幂等身份包含路径等信息，业务又自定义 marker。新合同必须独立定义业务事件、防重与载荷身份，避免换目录、换通道或换运行编号变成重复发送机会。

## 5. 目标分层与调用合同

```text
业务技能：选择数据、生成内容、校验业务完成条件、携带既有授权
    ↓ 群名 + 有序对象列表 + 执行上下文
wechat-messaging：合同/授权 → 防重 → 环境/群定位 → 发送 → 复核 → 收据
    ├─ desktop 适配器 → 现有桌面原子控制
    └─ mobile 适配器  → 手机设备控制 + 微信页面语义
    ↓ 逐项收据
业务技能：仅对 verified 项幂等提交业务历史/游标
```

用户可说：“把这份日报和这张图片发到某群。”业务内部建议合同如下，字段是设计而非已可调用 API：

```json
{
  "schemaVersion": 1,
  "groupName": "完整群名",
  "items": [
    {"itemId": "summary", "type": "text", "text": "完整正文"},
    {"itemId": "report", "type": "file", "path": "/absolute/report.xlsx"},
    {"itemId": "chart", "type": "image", "path": "/absolute/chart.png", "quality": "original"},
    {"itemId": "clip", "type": "video", "path": "/absolute/clip.mp4", "presentation": "native"}
  ],
  "context": {
    "workflowId": "业务流程标识",
    "eventId": "稳定业务事件标识",
    "authorizationRef": "已核对范围的授权引用",
    "profileRef": "已配置账号与执行通道",
    "deadlineAt": "本轮绝对截止时间"
  }
}
```

- 业务只构造内容与上下文，不指定点击坐标、OCR 条件、设备重启命令或任意发送器路径。
- `profileRef` 固定账号别名、desktop/mobile、手机设备和主微信/分身。四条当前生产调用保持 desktop；不得依据某一端可用性自动换端。
- 群名可参数化，但必须落在本次授权允许范围；群名相同且候选不唯一时停止，不能凭头像、最近聊天或猜测选择。
- 全批次先校验对象存在性、类型、数量、顺序、大小、内容哈希与通道支持度。不支持的视频必须在第一项发送前返回 `unsupported`。
- 源文件先冻结为私有、不可变的本轮载荷，计算 SHA-256；后续只发送该快照，防止检查后被覆盖。图片可转换格式但必须声明转换，不能默默压缩；视频不能静默变成附件。
- 既有长期授权由业务策略核对来源、业务日、群、通道和内容范围后交接。临时请求根据用户已明确的目标和对象绑定授权；只有真正缺失目标/内容或超出范围时再询问，避免重复确认。
- 通用运行时不导入商家/金鲨业务模块；授权桥接和业务收据转换由轻量业务适配器完成。

## 6. 状态、防重与并发

固定阶段：`validate → claim_request → preflight → locate → prepare → attempted → verify → receipt`。每个对象有独立状态和证据；一次请求只面向一个群。

- 幂等主键建议为 `accountAlias + groupBinding + workflowId + eventId + itemId`。通道、文件目录和临时 runId 不参与主键；完整群名、类型、内容哈希、展示方式和顺序另绑定为不可变载荷合同。
- 同一主键同载荷：verified 返回既有收据；attempted/unknown 只读对账；同一主键载荷不同直接冲突。另一真实业务事件允许发送相同文字/文件，不能仅以内容哈希永久去重。
- `claim_request` 为跨进程原子占用，发送前持久写入 attempted 并落盘。已有 attempted 即使进程崩溃也保守视为未知，禁止推测零发送。阶段锁释放不删除发送事实。
- 桌面与手机共享逻辑账本。设备交互锁按实际资源隔离，发送逻辑锁按账号/目标/事件隔离。预检、准备、发送、复核保持同一个交互所有权；避免外层与子进程重复获取同一个不可重入锁造成死锁。
- `unknown` 没有自动回到发送阶段的路径。只读对账失败仍 unknown；没有看到气泡不能证明没有发出。
- 多对象按序提交；前两项 verified、第三项 unknown 时停止，收据返回部分完成。已发内容无法事务回滚，不承诺全批次原子发送。
- 通用账本 verified 后、业务游标提交前发生崩溃：重跑返回既有成功收据，由业务幂等补提交，不再次发消息。
- 历史多文件合并尝试必须按原组合保守对账，不能拆分生成新 itemId 来绕过旧 marker。导入历史只生成别名/映射，不删除原文件。

## 7. 环境检测、定位与重启

| 情况 | 新技能内的确定性处理 |
|---|---|
| 桌面微信未运行 | 若预先配置允许启动则启动一次；随后验证唯一主窗和登录状态；否则返回明确就绪失败 |
| 桌面已运行但主窗未抬升 | 当前目标已命中时尽量仅 AX 读取；确需交互时抬升唯一主窗，再重新读取实时元素与坐标 |
| 登录失效、锁屏、权限或风控提示 | 返回具体阻塞原因；不接管登录、凭据或系统安全确认 |
| 手机离线或实例歧义 | 绑定明确物理设备与 userId；禁止默认设备或双开猜测；先恢复可观测性再进入微信 |
| 微信控件树为空但截图正常 | 使用已校准视觉链路；不把微信屏蔽树误判成 u2 故障反复重启 |
| 发送前短时抢占 | 固定白名单、统一截止时间下有界等待；未知错误或多候选立即停止 |
| 微信进程/自动化服务确认卡死 | 只有尚无 attempted、无他人草稿、持有交互锁且配置明确允许时执行至多一次指定组件恢复；随后重新核验账号、群、载荷和授权 |
| 重启电脑或手机操作系统 | 不作为普通发送的自动恢复动作；需要独立明确的维护授权 |
| attempted 后崩溃、超时或失焦 | 保留账本，返回 unknown；恢复环境后只读核验，绝不通过重启进入补发路径 |

精确定位在技能内统一为：当前群标题 → 可见完整群名唯一行 → 精确搜索 → 群类型与标题复核。普通联系人与群同名时必须识别群会话属性；不能只因名字相同就发送。无法从当前 UI 唯一确认群类型时停止。

标题仅允许已验证的人数/装饰归一化；正文不进行汉字、数字和业务标点模糊替换。切换窗口、重启或抬窗后不能复用旧坐标。各业务等待预算可由策略配置，但不得超过总截止时间。

## 8. 分类型完成合同

| 类型 | 发送前 | 发送后 |
|---|---|---|
| 文字 | 唯一输入区原文逐字回读、群复核、清理本次剪贴板残留 | 定位本次新出站气泡、两帧稳定、原生复制全文哈希一致、输入清空；不能只做 OCR 摘要命中 |
| 图片 | 核对冻结原图、数量/顺序、图片预览及原图选项 | 本次新气泡完成加载、逐项媒体预览与源图内容匹配；记录媒体复核证据，聊天区像素变化只作辅助 |
| 文件 | 完整文件名、大小、源文件哈希、附件数量与顺序 | 新文件消息完整名称/大小、传输完成、无失败标志；允许时对发送消息保存副本并比较哈希。未做字节回读不得宣称字节一致 |
| 原生视频 | 容器/时长/尺寸、唯一媒体、原生视频预览 | 新视频消息传输完成、时长与关键帧匹配、可打开播放；不得将文件气泡认作视频气泡 |

通用收据字段：`status`、`groupName`、`accountAlias`、`channel`、`requestId`、逐项 `itemId/type/sha256/status/sendAttempts/evidence`、`verificationLevel`、`stageMs`、`pitfalls`、`recoveryCount`、`runtimeModelDecisions`。

返回状态至少包括 verified、already_verified、partial、blocked、unknown、unsupported。`verificationLevel` 区分界面对象匹配、媒体内容匹配和字节一致；业务可要求最低等级，不满足即不推进。微信本地发送核验不能表述为每位群成员已收取或阅读。
